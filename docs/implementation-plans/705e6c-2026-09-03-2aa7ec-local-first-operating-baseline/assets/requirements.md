| ID | Requirement | Acceptance Criteria | Phases/Steps |

| REQ-1 | Simplicity and local-only operation are the first repository rules. | Active guidance requires deletion/reuse/local fixes before new infrastructure and records deliberate simple-over-safe tradeoffs. `test:LocalFirst.BaselineContract` | 1.3, 2.3, 3.3 |
| REQ-2 | GitHub-hosted workflows and workflow-only support are removed and prohibited. | No workflow remains or is referenced as a required gate. `test:LocalFirst.BaselineContract` `review:cr` | 1.1, 1.3, 2.1 |

| REQ-4 | Broad and premium execution remain explicit operator-only paths. | `-FullRepository` is the sole broad local selector; Waza remains plugin-filtered premium opt-in; both are reachable only through direct explicit CLI invocation, with no package alias or skill caller and no identity/authentication subsystem. `test:LocalFirst.BaselineContract` `review:cr` | 1.3, 2.1 |
| REQ-5 | Every active gate, JSON path, test, design note, and architecture contract receives exactly one owner and disposition. | `assets/ownership.md` records source category counts and one `keep`, `transfer`, `delete`, or operator-resolved disposition per row; every delete has a reason, every transfer names a canonical child ID, and no `uncertain` row remains after step 1.2. `file:docs/implementation-plans/705e6c-2026-09-03-2aa7ec-local-first-operating-baseline/assets/ownership.md#exists` `test:LocalFirst.BaselineContract` | 1.1, 1.2, 2.1, 2.2, 3.3 |
| REQ-6 | Baseline-owned tests survive only when they protect current user behavior, an external format, or a high-impact regression. | The ownership audit states the value for every retained test; uncertain rows are decided by the operator; deleted tests leave no stale tier/coverage requirement. `file:docs/implementation-plans/705e6c-2026-09-03-2aa7ec-local-first-operating-baseline/assets/ownership.md#contains:Value category.*Reason` `review:cr` | 1.1, 1.2, 2.1 |
| REQ-7 | Baseline-owned internal operational JSON is converted to strict Markdown or deleted; external-required JSON remains. | Every retained JSON row names its external consumer; each deletion or conversion updates its producer and consumers in the same step; each transfer names one child and updates that child's references; no baseline-owned internal JSON or schema remains. `file:docs/implementation-plans/705e6c-2026-09-03-2aa7ec-local-first-operating-baseline/assets/ownership.md#contains:external consumer` `review:cr` | 1.1, 2.2, 2.3 |
| REQ-8 | VS Code and Copilot CLI expose equivalent informed choices and stable direct-script behavior. | Both hosts provide the same decision context with `effort: 1-10` and `complexity: 1-10`; read-only/focused scripts use stable paths and mutating scripts remain explicit. `test:LocalFirst.HostErgonomics` | 3.1 |
| REQ-9 | Planning and review reuse the existing bounded historical artifact adapter. | Explicit concepts/plan IDs remain bounded, fenced, secret-screened, and conflict-reporting; no second history reader or durable context service is added. `test:PlanArtifactContext.BoundedConsumer` | 3.2 |
| REQ-10 | Agent/model/context cost guidance is concise, advisory, and operator-approved. | The RFC records 2 default/5 maximum calls, primary plus availability fallback, at most 5 supporting artifacts, and 600/1,200-word instruction bounds without adding a runtime policy service. `test:LocalFirst.AgentCostBudgets` | 3.3 |
| REQ-11 | Active notes, provisional contracts, and indexes describe the final local-first repository without a cleanup sweep. | Workflow-authoritative notes/contracts change in the same MVP step as workflow deletion; later owner-local documentation changes with its corresponding deletion; superseded workflow/tier/schema authority and baseline residue are absent. `test:LocalFirst.BaselineContract` `review:cr` | 1.3, 2.3, 3.3 |
