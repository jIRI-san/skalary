# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | A broad, stale-approved, caller-authored, or wrong-platform waiver turns absent proof into a false pass. | Medium | High | Bind exact plan/REQ/marker/OS/status/ID, prohibit wildcards/caller disposition, record one reviewed waiver-set digest, invalidate it on policy/inventory change, and mutation-test every mismatch. | 1.2, 3.1, 3.2, 5.1 |
| RISK-2 | Duplicate or ambiguous test IDs run an unintended subset, or zero matches are mistaken for success. | Medium | High | Search the committed scope, run all exact matches, report counts/files, classify zero as missing, and test duplicates/exclusions/source mutation. | 1.3, 2.1, 2.2, 5.1 |
| RISK-3 | Pester skip, NotRun/Inconclusive, discovery, framework, timeout, or container failures collapse into passed/failed booleans. | High | High | Batch in one killable child, require selected/executed count equality, map every result, discard partial timeout output, and preserve typed findings through outer exits. | 1.1, 2.1, 2.2, 3.3, 5.1 |
| RISK-4 | The legacy `Success` adapter or mixed old/new callers create a false-green migration window. | Medium | High | Adapt only when Status is absent, reject contradictions, migrate canonical/plugin/dogfood callers atomically, and keep negative parity fixtures. | 1.1, 3.1, 3.3, 5.1 |
| RISK-5 | Formatter and completion gate interpret inventory, freshness, or disposition differently, or lifecycle commits self-invalidate valid evidence. | Medium | High | Pass one shared inventory to both, use a v2 evidence-input digest excluding receipt/finalization outputs, host the verdict in PlanCrosscheck, and mutation-test publication plus later lifecycle commits. | 3.1, 3.2, 3.3, 4.1, 5.1 |
| RISK-6 | Hostile IDs, paths, reasons, or diagnostics escape confinement, forge lines, or create unbounded output. | Medium | High | Bound arguments, canonicalize then confine, reject reparses/extra fields, single-line sanitize, byte-cap output, and cover hostile/oversized fixtures. | 1.1, 1.2, 2.1, 2.2, 3.1, 3.2, 5.1 |
| RISK-7 | Root, bundled CI, dogfood, manifest, marketplace, or registry copies drift. | High | High | Use the existing sync pipeline, per-step patch bumps, installed-consumer tests, structural evals, and final drift/mutation gates. | 2.3, 3.3, 4.1, 4.2, 5.1 |
| RISK-8 | Focused discovery duplicates suite ownership or pushes the ordinary gate over its platform budget. | Medium | Medium | Introduce one committed scope owner consumed or parity-checked by both paths, run only exact matches at crosschecks, and enforce existing Linux/Windows ceilings. | 1.3, 2.1, 4.2, 5.1 |
| RISK-9 | A visible waiver still normalizes away platform-only security coverage. | Medium | High | Permit only skipped or pass/skip degraded states, keep status unchanged, bind OS exactly, require final human review, and reject waivers for failed/unrun/missing/stale/malformed/error. | 1.2, 2.2, 3.2, 5.1 |
| RISK-10 | A crash after run start leaves an older green receipt authoritative, or the machinery proves itself with its own parser/runner. | Medium | High | Atomically publish blocked running state first; publish terminal state only from a complete set; test every interruption boundary, fresh-clone recovery, hand-authored parser goldens, and ordinary/focused cross-checks. | 3.1, 3.2, 4.2, 5.1 |
| RISK-11 | A red inner gate is swallowed by container/host/sandbox orchestration or authoritative platform proof is replaced by local evidence. | Medium | High | Assert outer exit propagation for blocked/framework/timeout/partial states and require current-tree Linux and Windows CI receipts before final approval; local container results stay supplemental. | 3.3, 4.2, 5.1 |
| RISK-12 | Shared digest, cardinality, architecture mapping, or parser copies omit an input or drift together and self-prove. | Medium | High | One canonical module owns hashing/limits/mapping; hash all tracked files except a closed exclusion list; synchronize every consumer; use hand-authored membership/parser goldens and seeded omission mutations. | 1.1, 3.1, 3.2, 4.2, 5.1 |
