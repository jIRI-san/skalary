| REQ-1 | Before any implementation mutation, resolve every declared `depends-on` plan and require lifecycle `done`, approved final review disposition, complete typed evidence, and exact consumed ABI/schema/contract digests. | REQ-2 | Implement a dormant one-child GitHub slice. The child receives Copilot authentication but no repository-write credential. It exports a deterministic Git bundle plus metadata into host-retained authority; the host verifies/imports commits, audits plan/evidence/path scope, performs expected-old-OID push, and creates the explicit-base PR. Bundle admission is 256 MiB, 100,000 objects, 256 commits, and 32 MiB per blob, with digest/object/ref closure, crash retention, and cleanup acknowledgement. The reconcile core snapshots one target OID, pins graph/tool authority, and selects one topologically ready child. | Fault scenarios prove separate auth, deterministic bundle export/import, exact limits and one-over refusal, missing/thin/foreign bundle rejection, crash retention, host push/PR, target pinning, and one eligible child handoff: `test:EpicAutopilot.OneChildBundleVertical` · `test:EpicAutopilot.BundleAdmissionAndAuthSeparation` | 1.2 |
| REQ-3 | Keep `/ci` menu and direct `Run` disabled while proving the Phase-1 slice from an isolated installed copy. PowerShell below 7.6, nested container invocation, and every dependency/security/capability failure return a bounded pre-mutation refusal. | Completed-result scenarios prove one-child happy path, read-only rich Status, no activation, exact dependency/security/capability reasons, source poisoning, duplicate/skip/mis-tier detection, and unchanged plan/single-plan flows: `test:EpicAutopilot.PhaseOneInstalledClosure` | 1.3 |
| REQ-4 | Extend the existing child launcher with optional nonce-bound run identity, exact target fork/base, idempotent launch, managed reattach, remaining timeout, and bounded bundle/transcript extraction while preserving single-plan defaults. | REQ-5 | Implement a domain-owned epic state machine using only shared stateless canonical-JSON, digest, confinement, and atomic-replace helpers. Reuse `669ad3`'s external authority root and namespace protocol; lock order is namespace -> epic -> fleet -> coherency/review-run -> ledger, with no lock held across external calls. Model orthogonal run, child, wait, merge, coherency, reason, and exit fields plus append-only transition/attempt/audit indexes. Run performs deterministic recovery; Reset starts a new epoch while preserving merges, audits, history, and cumulative budgets; Status never mutates. Map process exits `0`, `2`, `3`, `4`, degraded `5`, and child/runtime `42`-`45`, `124`, `143`, and unknown nonzero results. | Crash-replay scenarios prove legal transitions, lock order, leaf-swap refusal, partial publication, Run recovery, Reset matrix, stale authorization, exact exit/reason producers, no budget laundering, and atomic state/receipt agreement: `test:EpicAutopilot.StateMachinePublicationAndRecovery` | 2.2 |
| REQ-6 | Prove Phase-2 runtime closure on live Windows and Linux host paths using installed assets. Windows uses Credential Manager; Linux uses authenticated `gh`/environment token sources for Copilot only. Cap each child at eight operator attempts and the epic at 128 launches, seven cumulative runtime days, 64 rebundles, and eight delivery-audit generations. Supplemental real-Docker smoke is not required evidence. | Platform result gates prove unique non-skipped Windows/Linux scenarios for restart, duplicate suppression, bundle preservation on exits 43/124/143, exits 44/45/5/unknown, transcript/cache/publication faults, cumulative exhaustion, and source-path poisoning: `test:EpicAutopilot.RuntimePlatformClosure` | 2.3 |
| REQ-7 | Harden GitHub host authority. Use trusted absolute executables, fixed arguments, curated environment, fully qualified refs, pinned repository/remote identity, exact target fork point, explicit PR base, bounded structured output, and expected-old-OID push. Import pre-existing completion only when bundle/target ancestry and required receipt reconstruct one verified merge record. Persist initial membership/edge and privileged host/reviewer digests; graph or authority changes require digest-bound operator re-pin. | GitHub scenarios cover open/merged/missing/retargeted/force-moved/squash/baseline import, stale expected OID, fake executable, malformed/oversized output, exact ancestry, graph growth, authority re-pin, and rollup disagreement: `test:EpicAutopilot.GitHubMergeAndAuthorityPin` | 3.1 |
| REQ-8 | Enforce child path/ref capabilities by auditing imported bundle refs and the complete target-base-to-child-head object/commit/path/diff set before any host push. Reject sibling plan/epic, host/config/privileged paths, tags, deletions, force moves, or unauthorized refs. Bound one child to 256 commits, 100,000 objects, 4,096 changed paths, 256-MiB bundle bytes, 32-MiB blob/diff metadata, 16-MiB provider output, 60-second provider calls, and a five-minute reconcile deadline. Select one topologically ready child; distinguish in-epic, external, terminal, cyclic, ambiguous, and unreadable dependencies. | Exact-limit/one-over and two-child installed scenarios prove bounded bundle/diff/ref audit, later-sibling dependency scheduling, external/unresolvable dependency handling, merge-before-next, stale target, sibling mutation, process-tree termination, projection refusal, $O(P+E)$ counters after snapshot, and zero automatic retries: `test:EpicAutopilot.MultiChildCapabilityAndBounds` · `test:EpicAutopilot.TopologicalSelectorCounters` | 3.2 |
| REQ-9 | Define owner-state review family `epic-delivery@1` while keeping review-run v1 unchanged: dispatch as `purpose=design` and `designSource.kind=rfc`, with exact adapter mapping, registry-generated concern variants, eight frozen concern/model slots, and epic-associated storage. Build the canonical source from reviewed target OID, intent digest, ordered merge records, and verified receipts; admit before first run and project before every merge at 64 children, 8 KiB per receipt, and 768 KiB total. Confine, normalize, secret-scan, and fence bytes as untrusted. | Contract scenarios prove v1 schema compatibility, owner-state family/version, adapter/registry parity, exact slots, source ordering/digests, 64/65 and byte one-over refusal, pre-run/pre-merge projection, directive/secret rejection, and source-change invalidation: `test:EpicAutopilot.DeliverySourceAndReviewV1Mapping` | 4.1 |
| REQ-10 | The fleet owner descriptor authorizes eight logical and 16 attempted delivery-review calls. Dispatch one frozen audit through review-run v1, require complete attendance and finding disposition, and map verified degradation to process exit 5. | REQ-11 | Findings or degraded delivery review never self-remediate already-merged code. They pause for a corrective child/plan and a completely fresh source/audit generation; cumulative audit credits and append-only audit/transition history survive restart and Reset. | Correction-loop scenarios prove no self-edit, no stale-verdict reuse, fresh source after corrective merge, audit-credit exhaustion, compact history retention, and no terminal completion from findings or degradation: `test:EpicAutopilot.DeliveryCorrectionLoop` | 4.3 |
