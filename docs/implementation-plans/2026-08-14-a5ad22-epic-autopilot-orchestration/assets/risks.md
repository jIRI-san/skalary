# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | Corrupt, forward-version, partial, or cross-worktree state causes a duplicate launch or false terminal result. | Medium | High | Reuse the external host authority and shared publication primitive, a stable lock/order, strict schema/capability admission, append-only indexes, and fault recovery. | 1.1, 1.2, 2.2 |
| RISK-2 | Host paths escape through traversal/reparse behavior or reset destroys the only audit/recovery authority. | Low | High | Canonicalize and confine every component, reject reparse ancestors, cap archives, refuse overflow, and never delete branches/PRs. | 1.1, 1.3 |
| RISK-3 | Existing `NextChild` cannot represent all topologically ready work, or graph/host authority changes silently expand privileged execution. | Medium | High | Add an explicit selector mode over one clean target snapshot; classify dependency states; pin graph/tool digests and require stale-safe operator re-pin. | 1.1, 1.2, 3.1, 3.2 |
| RISK-4 | Crash or restart around bundle export/import or launch/reattach loses commits, timeout, transcript, cleanup, rebundle, or attempt ownership. | Medium | High | Reserve before effects, retain bounded bundles in host authority, bind runtime identity, persist counters/deadline, and make reattach own the full remaining lifecycle. | 1.2, 2.1, 2.2, 2.3 |
| RISK-5 | Run-identity and image-reuse changes regress existing single-plan launcher/auth behavior. | Low | High | Keep parameters optional, key cache from exact inputs, run existing suites, and delay `/ci` activation until compatibility and duplicate gates pass. | 2.1, 2.3 |
| RISK-6 | New runtime assets exist only in the source repo or one installed copy. | Medium | High | Declare scaffold/schema/agent/script closure, generated bundles, dogfood, registry, marketplace, and installed-consumer parity. | 2.3, 6.1 |
| RISK-7 | Child code mutates sibling plans, host config, or unauthorized remote refs while still producing a green child receipt. | Medium | High | Withhold remote credentials and host state; host mediates expected-OID push/PR effects; audit complete commits and remote-ref deltas. | 1.2, 3.1, 3.2 |
| RISK-8 | Rollup or provider status claims completion while target ancestry or persisted merge proof disagrees; squash merge remains blocked. | Medium | High | Make verified merge records authoritative, refresh target refs, require exact ancestry, and emit a specific squash/remediation reason. | 3.1, 3.2 |
| RISK-9 | Final review consumes hostile/unbounded bytes, drifts from review-run v1, or cannot remediate already-merged findings. | Medium | High | Map owner-state `epic-delivery@1` to v1 design/RFC fields, use owner-authorized fleet limits, 64-child/768-KiB admission, sealed finalization, and corrective work plus a fresh audit. | 4.1, 4.2, 4.3 |
| RISK-10 | Test IDs exist only in prose or generated payload/docs/architecture drift. | Medium | High | Commit a scenario/tier inventory, mutation-test discovery and non-skip behavior, sync every payload/catalog, regenerate the epic/architecture mirrors, and remeasure runtime. | 5.1 |
