# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | One `PlanState.psm1` parser/formatter owns legacy numbered, unprefixed hash, epic-prefixed hash, and `standalone`-prefixed hash folders. Compatible `Scheme` remains `legacy` or `new`; closed `FolderForm` is `legacy`, `unprefixed-hash`, `epic-prefixed`, or `standalone-prefixed`; nullable canonical `EpicId` reuses membership vocabulary. Prefix/marker mismatch and duplicate IDs are errors. Read-only consumers return typed unmatched-directory diagnostics; mutators fail closed. Unprefixed hash remains permanent read-only compatibility, but creation never emits it. | Table-driven fixtures cover every grammar and mismatch, body-only epic markers, fuzzy-match isolation, duplicate IDs, typed diagnostics, one-snapshot ordinal ID maps, and pre/post inventory parity. A structural guard rejects parser duplicates except the fully anchored terminal-approval mirror. `test:PlanFolders.ParserFormatterAndResolution` · `test:PlanFolders.NoDuplicateGrammar` · `test:PlanFolders.TerminalApprovalGrammar` | 1.1, 1.2 |
| REQ-2 | Under the namespace lock, `New-Plan.ps1` creates the final target folder immediately: direct `/cip` defaults to `standalone-<date>-<plan-id>-<slug>`, while `/cep` supplies a resolved epic ID for `<epic-id>-<date>-<plan-id>-<slug>` without touching an intermediate path. | Sentinel-path, pending-journal, standalone, epic, invalid-ID, collision, confinement, and stage-stamp scenarios pass. `test:PlanFolders.LockedFinalNameAtCreation` | 2.2 |
| REQ-3 | Every plan-namespace writer uses protocol `plan-folder-mutation/v1` and one stable host namespace lock acquired before authoritative discovery. Complete order is namespace lock, review-run lock, then ledger/store lock; reverse acquisition is forbidden. The namespace critical section has a 30-second acquisition timeout and 120-second hold ceiling. The existing provisional `ARCH-Review-Run-V1` contract records this outer boundary. Installed payload generation/hash readiness and stale-process quiescence block mixed-version writers. | Interleaving tests cover every writer, lock order/timeouts, protocol skew, stale processes, review-lock contention, and exact amendment/freshness of `ARCH-Review-Run-V1`. `test:PlanFolders.NamespaceProtocolAndLockOrder` · `file:docs/architecture-notes/arch-review-run-v1.md#contains:plan-folder-mutation/v1` · `review:cr` | 2.1, 4.1 |
| REQ-4 | `New-Epic.ps1` transacts all new epic artifacts, children, membership/dependency markers, folder renames, and mirrors through the shared mutation protocol. Real collisions refuse with zero mutation; repeat, partial, and mismatch states follow a closed classification; legacy numbered folders keep their names. | Multi-child create, repeat, re-parent, collision, mismatch, body-marker, mirror, writer-allowlist, and fault-boundary scenarios pass. `test:PlanFolders.AtomicEpicMembershipRename` · `review:cr` | 3.1 |
| REQ-5 | Cip owns `Migrate-PlanFolderPrefixes.ps1`; `Repair-Plans.ps1` remains legacy loose-layout repair. Both share parser, stable JSON, fingerprint, schema-validation, and receipt-verification helpers with the installer transaction where confinement permits, but keep separate commands and locks. Prefix migration uses one snapshot, fails whole preflight, supports `-WhatIf`, converges idempotently, and never repairs loose layouts; repair never renames folders. | Mixed fixtures independently run dry-run, apply, and replay for both commands plus malformed residue, live state, collision, Windows nested-CWD/open-handle probe rename, reparse, kill, and recovery cases. `test:PlanFolders.DisjointMigrationCommands` · `test:PlanFolders.MigrationPreflightAndRecovery` · `file:scripts/skalary/Migrate-PlanFolderPrefixes.ps1#exists` · `review:cr` | 3.2, 5.1 |
| REQ-6 | One physical host authority root contains isolated lock and per-session recovery leaves; runtimes mount only those leaves, with no repository, Git metadata, home, or local fallback exposure. Operation IDs are lowercase UUIDs. A single-use host-generated nonce capability is read-only mounted and binds repository, session, operation, branch, base/progress commit, approved dry-run UUID, candidate digest, and expiry. Journal recovery validates Git state as discarded, exact pushed apply commit, or conflicting/divergent before mutation; conflicts return `RecoveryRequired`. Limits are 512 candidates, 1 MiB journal, 2 MiB receipt, 20 retained terminal receipts, 64 KiB diagnostics, and one active journal. | Host/runtime contention, mount-attestation, capability positive/refusal/replay, UUID traversal, cap/+1, journal tamper, killed-runtime teardown, and fresh-clone Git-state scenarios pass. `test:PlanFolders.HostAuthorityCapabilityAndRecovery` | 2.1, 3.2, 5.1 |
| REQ-7 | Canonical plan ID plus independent branch/worktree/run handles replace mutable basename authority. Exit `44` halts without retry. Exit `45` requires a new pushed progress commit and next-step transition, preserves the cumulative plan deadline, and permits one relaunch per operation; no progress, second `45`, cap, or host-update failure stops. Before the bootstrap handoff, recovery-required conditions use exit `42` plus a blocking marker and no real corpus mutation occurs. | End-to-end fixtures prove exits 42/43/44/45 through all runtimes, one-relaunch bounds, cumulative deadline, update failure, canonical relaunch, and no stale-folder recreation. `test:PlanFolders.LifecycleHandlesAndBoundedRelaunch` | 4.1, 4.3, 5.1 |
| REQ-8 | Active templates, headers, links, `file:` evidence, and current-tree historical checks resolve canonical IDs or are rewritten; pinned-commit paths and archived/finalized prose remain non-authoritative provenance. File-wide `plan-id` parsing remains unchanged while `epic` membership stays header-scoped. Operations preserve stable identity, tracked/ignored bytes, ledger keys, and finalized review authority. | A path-authority inventory and scenario tests cover current versus pinned lookup, decoy markers, evidence rewrites, stable bytes, live-review refusal/finalization, and zero new index errors. `test:PlanFolders.PathAuthorityAndStableIdentity` · `review:dr` | 1.2, 4.1, 5.1 |
| REQ-9 | Every source-changing step synchronizes affected bundles, versions, dogfood, manifests, registry, marketplace, settings, templates, README, direct consumers, and named notes before commit. Named docs are `plan-workflow.design.md`, `copilot-customizations.design.md`, `autopilot-execution.design.md`, `autopilot-skill.design.md`, `plugin-manager.design.md`, `ci-gates.design.md`, both root indexes, `ARCH-Review-Run-V1.json`, `arch-review-run-v1.md`, and regenerated `architecture.human.md`. | Per-step drift and seeded-drift tests prove same-commit synchronization, protocol generation, hostile terminal-approval rejection, architecture-doc freshness, and exact doc/index coverage. `test:PlanFolders.StepDistributionAndDocs` · `test:PlanFolders.DistributionSyncDetectsDrift` | 1.1, 1.2, 2.1, 2.2, 3.1, 3.2, 4.1, 4.2 |
| REQ-10 | A committed marker/scenario/file/tier map assigns every `test:PlanFolders.*` marker and required scenario to exactly one active, non-skipped Pester case. Parser tests are Fast; process, lock, kill, Windows-handle, migration, and fresh-clone tests are Slow. Discovery has seeded absent, skipped, undeclared, duplicate, and unloaded failures. Fast keeps existing per-platform budgets; exact before/after Slow runtime is recorded on Windows/Linux without a new ceiling. Fixtures use minimal clones, at most eight child processes, 30-second fault-case timeouts, and a ten-minute file cap. | Discovery compares the map and executed NUnit cases; seeded failures return typed nonzero outcomes; suite profile and exact-commit platform receipts prove tier execution and runtime recording. `test:PlanFolders.TestDiscoveryAndScenarios` · `test:PlanFolders.SuiteTierAndRuntime` | 4.2, 5.2 |
| REQ-11 | Terminal apply is host-authorized: after the bootstrap handoff, the updated host produces readiness and capability artifacts, finalizes review authority, remediates or reports initiating-workspace residue, validates the approved dry-run UUID, and invokes the bundled cip command. Only operation-owned `669ad3` state is exempt under the namespace lock. Apply writes and pushes a durable in-repo `assets/plan-folder-migration.json` mapping before bounded exit-45 relaunch. | Capability/version/mount readiness, residue, foreign-state, stale-digest, writer-kind, mapping, commit-progress, and host-caller scenarios pass. `test:PlanFolders.HostAuthorizedTerminalApply` · `file:docs/implementation-plans/2026-08-14-669ad3-epic-prefixed-plan-folder-naming/assets/plan-folder-migration.json#exists` · `review:cr` | 4.3, 5.1 |
| REQ-12 | Post-apply verification resumes from the exact apply receipt/commit and runs the full distribution, analyzer, dependency, plan-validation, and project gates on the migrated tree.
