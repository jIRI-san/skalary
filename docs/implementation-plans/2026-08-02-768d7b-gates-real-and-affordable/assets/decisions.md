# Decisions

Resolved in the `/cip` interview on 2026-08-02, then revised after DR rounds 1 and 2. No TBDs.

- **The ceiling is bound now at 600s, matching the intent's stated outer bound, with one policed escape hatch (D1, revised three times).** Round 1 demanded `< 300s`, unreachable because the residue outside `Skalary.Tests.ps1` is 322s. Round 2 replaced it with "measure then decide", which bound nothing — every REQ marker passed with `1800` in the file. Round 2 also established the floor: on this plan's own bracket (fixture construction 65–85% of 1419.6s), driving fixture cost to **zero** leaves `npm test` at **535–819s**. A draft then set 900s, which the `/ci` intent re-read caught as **50% above the 10-minute outer bound `intent.md` declares** — the plan could have gone green while breaching the operator's own limit. The ceiling is therefore 600s with a 480s target. Because 600s sits above only the lower part of the floor bracket, step 4.2 may raise it **once**, to at most 900s, and only with a written justification recorded here; the test asserts both the absolute 900s cap and the presence of that justification, so the hatch cannot be used silently.

- **The budget is measured against `npm test`, not the `test:unit` leg (D2, new).** Round 2: the ceiling lived in `Run-UnitTests.ps1`, which covers only the Pester leg, while both the 1741.8s baseline and the operator's stated bar are for `npm test`. The gate would have measured a different quantity than the goal. CI therefore invokes `Run-UnitTests.ps1` — the only place the check lives — rather than calling `Invoke-Pester` directly.

- **The fixture is made small before it is copied (D3, revised).** Round 1 chose a shared read-only fixture; round 2 showed it fits 1–2 of ~20 executions. The template-copy replacement carried its own trap: `git clone <localpath>` **hardlinks** the object store, so copying a full clone 25 times replaces a cheap operation with 25 full byte copies. The synthetic minimal fixture therefore lands **first**, and only then is it copied per case. The synthetic repo must carry `git tag` data, because `Build-Registry.ps1` resolves versions from tags and a test-name inventory structurally cannot detect that loss.

- **Each reduction phase declares a required saving and a stop condition (D4, new).** Round 2: Phase 3 named work items but no target, so it could not fail. Phases 2 and 3 now each state the saving required to stay on track for the ceiling, record the achieved figure, and escalate rather than continue silently when missed.

- **Phase 2's target is half of the measured fixture-construction cost, scored on `New-RepoClone` rather than wall clock (D4a, new at step 2.3).** The phase-1 baseline measured `New-RepoClone` at **8.775s across 29 calls** (mean 0.303s). Phase 2 therefore declares a required saving of **4.4s** — half the measured cost, set from the baseline alone so the target does not follow the result. It is scored on the operation's aggregate seconds, not on the run's wall clock, because a ~7s move inside a ~100s run is close enough to run-to-run noise that a wall-clock gate would be decided by scheduling rather than by the change. The stop condition is executable in two places: `Measure-SuiteProfile.ps1` exits non-zero on a miss while still recording the row, and `test:SuiteProfile.PhaseTargetsMet` fails on any recorded phase whose achieved saving is under its declared target. Achieved: **6.715s** (8.775s → 2.060s, mean 0.303s → 0.070s), template construction included in the figure.

- **Coverage is defended by a test-name inventory, not an assertion count (D5).** Pester exposes test counts, not assertions, and `-TestCases` expands one `It` into N — so a count is false-red when cases consolidate and false-green when a `Should` is deleted inside a surviving `It`. The inventory is a subset assertion with an enumerated removal list. Install-confinement rejection cases are named must-keep: a fixture-based rewrite cannot exercise write-path rejection, so trimming pressure falls hardest on the executable evidence for `ARCH-Install-Confinement`.

- **`Run-UnitTests.ps1` fails loudly when it cannot test (D6, corrected).** Silent exit 0 with zero assertions forges evidence, since it is the `test:unit` evidence executor. It must also fail when Pester is present but zero tests are discovered. **Correction from round 2:** earlier drafts called this "a synced plugin script" requiring consumer migration — it is bundled in no plugin, so no consumer migration exists and RISK-3 is narrower than stated.

- **Plan stages are an ordered, closed set (D7).** `Set-PlanStage.ps1` accepts any non-empty string today, so a typo such as `draftd` would fall into the not-drafted branch and silently disable every evidence check while exiting 0. The order is defined once; an unrecognised value fails loudly; the skip emits a distinguishable signal.

- **Catalog ordering uses an ordinal comparer, proven against a divergent fixture (D8).** `cs-CZ` and `en-US` order lowercase-ASCII ids identically, so a naive locale test passes with zero fixes applied. The fixture must genuinely diverge and be demonstrated red before the fix lands.

- **CI wiring is gated by an executable precondition, not an `[after:]` edge (D9, revised).** Round 2 confirmed `Test-Plan.ps1` validates only that an `[after:]` target parses and the graph is acyclic — it never checks a predecessor succeeded. Phase 8 therefore opens with a step that runs the budget check and blocks on a non-zero result. `timeout-minutes` is set **above** the hard ceiling, so the job cannot be killed before the gate speaks.

- **The workflow is hardened as part of wiring it (D10, revised).** Trigger stays `pull_request`, never `pull_request_target`; `permissions: contents: read`; `persist-credentials: false`; actions SHA-pinned and modules version-pinned. **Round 2 correction:** a version pin alone is insufficient while `-SkipPublisherCheck` and a globally trusted PSGallery remain — both are removed, not merely supplemented. NUnit output uses a deterministic per-OS path and a per-OS artifact name, since two matrix legs uploading one name is a hard failure.

- **The `arch:` marker is dropped (D11, new).** REQ-8 carried `arch:ARCH-Eval-Gate-Separation`. Round 2 verified it is unsatisfiable: `docs/architecture-notes/receipts/` and `arch-test-config.json` do not exist and no step creates them, so the requirement would hard-block at the final crosscheck; and once minted, `provisional` maturity is warn-only and scoped to the eval scripts, blind to `.github/workflows/`. The contract's intent is preserved as an explicit REQ-9 criterion instead of an unenforceable marker.

- **Repo-wide constants consolidation is deferred, not silently moved (D12, revised).** Round 1 finding 42 moved it to sibling `34088e`. Round 2 noted the hand-off had no `depends-on`, no risk row and no requirement on the receiving side — so it was dropped rather than moved. It is recorded here as an explicit deferral with the receiving child named; `34088e` must pick it up in its own `/cip`, and this plan asserts nothing about it.

- **The ceiling is enforced per platform, and a platform that cannot meet it splits its tiers rather than raising it (D13, new).** Measured after Phase 7 landed: the same suite runs **108s** in the Linux container and **1157s** on a Windows host — roughly 10×, against RISK-4's assumed 2×. A single 600s ceiling would therefore be either unreachable on Windows or vacuous on Linux, and Phase 8 wires both into CI, so the Windows leg would have failed on the budget rather than on a defect. `tools/suite-budget.psd1` now carries an entry per platform and the runner enforces the one it is running on. Both start at the same 600s/480s the intent states — the ceiling is not slackened to fit the slower host. Operator direction: get Windows as close as possible; if Phase 3 cannot bring it under, **split the suite into fast and slow tiers** rather than raise the ceiling. The escape hatch in D1 remains a single 900s raise with a recorded justification and is not a substitute for that split.
