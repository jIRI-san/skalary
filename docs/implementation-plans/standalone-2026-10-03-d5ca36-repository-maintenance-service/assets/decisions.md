# Decisions

- **Quality and drift, not merely cleanup.** Operator-defined goal covers intent, architecture, design,
  coding standards, dead code, and overall codebase improvement actions. Plan housekeeping supports it.
- **Repository maintenance names.** Operator selected plugin `repository-maintenance`, central record
  `docs/repository-maintenance.md`, and retained `/rcs` with its original repository-cleanup-service expansion.
- **Default depth.** Operator selected repository-wide survey plus risk-selected deep traces over
  systematic every-requirement tracing. Unread/incomplete areas are visible, not certified clean.
- **Central readable record.** Operator chose one record over distributed owning-asset dispositions.
  Keep source links and original meaning; the record does not supersede source authority.
- **Operator control.** Confirmed baseline permits fixed-record findings publication but requires
  explicit choices for dispositions, corrective plans and archive. No direct code fixes/deletion or
  automatic commits, broad/premium runs, criteria changes or network crawl.
- **Same action model.** Drift may be intentionally accepted or corrected; design/dead-code/standards
  candidates may be won't-fix or corrective-plan actions. Silence remains pending.
- **Core repeat-run checks.** Operator selected active corrective-plan overlap discovery and changed-
  basis revisits. Unchanged decisions suppress repeat questions; changed evidence does not erase history.
- **Separate documentation sweep.** Full local documentation/reference crawling stays outside v1.
  Encountered contradictions/stale guidance remain normal findings; a standalone sweep can feed the
  record and planning flows when explicitly requested.
- **Reuse available review improvements without blocking v1.** Coordinate with plan `9abf21`
  implementation through `91310c78` and inspect current integrated helpers. Operator selected current
  inventory/bounded intent intake when enhanced snippets are absent, with disclosed search/epic-context
  gaps; no integration prerequisite, automatic branch merge or duplicate index. Incompatible current
  APIs or unresolved needed context still stop. History is advisory; current contracts prevail.
- **Small local implementation.** Thin skill plus on-demand guidance and one small plugin-owned
  Markdown helper; existing inventory/intake/review/approval/distribution paths do the rest.
  No independent registry, ticket lifecycle, database, model panel or new authority.
- **Bounded report.** Operator-confirmed detailed v1 criterion: 128-KiB UTF-8 input/output cap,
  explicit stop on overflow, no automatic pruning/rollover.
- **No invented reachability.** Zero references alone does not justify deletion. Manual/public/dynamic/
  generated/test/external entry points remain relevant; unknown usage is reported as unknown.
- **Concrete local contracts.** Operator selected all seven pre-confirmation recommendations: current-
  helper fallback, no-plan probe before index, explicit fixed-record guards, existing optional-input
  allowlist extension, deterministic stable-ID matching with operator ambiguity choice, existing-
  evidence subsystem discovery, and one existing untrusted framer without nested history framing.
- **Focused evidence.** Helper tests and structural evals prove deterministic contracts; disposable
  scenario traces demonstrate outputs. Paid/broad trials are separate and no semantic quality-gain
  claim is inferred from the review-improvements session's limited trials.
