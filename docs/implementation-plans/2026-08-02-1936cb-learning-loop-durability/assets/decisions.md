# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- **Scope is Cluster F plus G1–G3.** This plan fixes both missing durable `/si` state and the capture/resolution defects that bias or erase the evidence `/si` consumes. Splitting either half would leave a durable record over incomplete data, or better data with no durable handoff.
- **Reuse plan `b0c0d3`'s safety boundary.** `UNTRUSTED_INPUT`, explicit operator selection, worktree isolation, `Test-SiWriteScope`, draft PR only, and never-auto-merge remain unchanged. This plan extends persistence around that workflow; it does not weaken or redesign it.
- **Reuse plan `007`'s ledger writer and idempotence.** Per-phase promotion calls `Add-LedgerEntry` through the existing concern map. Finalization remains an idempotent retry sweep so interrupted phase promotion is recoverable without creating a second ledger grammar.
- **A separate structured SI state artifact, not the `/pfb` queue.** `/pfb` feedback and `/si` decisions have opposite failure semantics and different records. `docs/self-improvement/state.json` is versioned, schema-validated, and written only by `Update-SiState.ps1`; the plugin declares its first-use scaffold because installation is confined to `.github/`.
- **Plugin-owned lifecycle, shared phase-harvest engine.** Self-improvement is the sole owner of SI state/lifecycle scripts and schemas; autopilot depends on it and CI receives it through that dependency. Phase-harvest and ledger scripts remain root-canonical shared sources distributed by the existing `Sync-PluginScripts` gate.
- **Bound the hot manifest and segment history.** `state.json` holds pending/in-flight state and recent run references; complete history is sharded per run. Status is metadata-only and harvest pages free text through one snapshot-bound resolver under [operational limits](decisions/operational-limits.md).
- **Headless runs queue but never propose.** Autopilot writes a deduplicated due record and reports persistence failure as degraded, but it still never runs `/si` or opens a proposal. The next interactive completion surfaces pending work; explicit `/si` can do the same.
- **A script-owned remote state machine governs authority.** Every interactive action fetches and pins `origin/main`; correlation and one fixed branch derive from the due; that branch exists before mutation; trusted synchronization re-derives concurrent manifest deltas and owns pushes. Merge consumes. See [si-lifecycle-state-machine.md](decisions/si-lifecycle-state-machine.md) and [si-state-topology.md](decisions/si-state-topology.md).
- **Record every ranked candidate and the set itself.** Accepted, declined, and deferred candidates all remain durable with rationale, targets, cited sources, and a ranked-set count/digest; otherwise omissions and declined ideas are indistinguishable from never-ranked ideas. A proposal PR remains optional per candidate, while an all-declined outcome travels through a state-only record PR.
- **Promote at phase crosscheck; sweep at finalization.** The phase boundary is where review/evidence context is complete and provenance is known. Step-time ledger writes remain prohibited; finalization retries all phases idempotently rather than being the first write.
- **Receipts replace final redistillation.** `Invoke-PhaseHarvest.ps1` validates content-addressed phase source records, batch-writes the ledger, and emits a phase receipt. Finalization replays receipts; it never asks another context window to reinterpret the phase.
- **Preserve before summarizing.** Feedback has an exact 16 KiB post-sanitization UTF-8 bound and rejects larger input before mutation. Learning overflow is written as append-only content-addressed batches before the compact digest-bound summary changes; duplicate recovery is safer than missing data.
- **One executable, bounded, fenced free-text resolver.** `Get-SiHarvest.ps1` owns plan resolution, immutable snapshot cursors, source status, and wrappers for every source. `Get-SiState` returns metadata only; `/si` never reads raw state/overflow files or ranks incomplete input.
- **Run all enforcement from trusted base.** The proposal may edit its guard, state writers, resolver, or state files. Trusted synchronization pins the base/head OIDs, re-renders state, verifies hashes, runs enforcement against the exact pushed commit, and confirms remote-head equality. Operator completion repeats enforcement against the live PR OID and merges only that expected SHA.
- **One shared ledger engine.** Scalar and batch entry points both use `LedgerStore.psm1`, preserving one sanitizer, parser, dedup/recurrence key, scaffold, lock, and atomic-write implementation.
- **The concern map moved behind the installed harvester.** Plan `b0c0d3` proved both workflow guides named the installed map. This plan supersedes that guide-text evidence: CI and autopilot invoke `Invoke-PhaseHarvest.ps1`, whose closed map and source-record validation now own deterministic routing.
- **Cross-repo transport stays deferred to `2366ad`.** This plan may prove installed payload behavior in a consumer fixture, but it does not automate forks, upstream proposals, or foreign-repo standards.
