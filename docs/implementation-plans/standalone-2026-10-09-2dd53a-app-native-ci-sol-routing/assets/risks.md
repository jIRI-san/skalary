# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | Remapping secondary aliases silently preserves false cross-model/fallback promises or leaves generated consumers on old models. | High | Medium | Change policy and active claims together; test all six bindings, current efforts, generated eval consumers and unavailable-model refusal. Stop if exact host identifier is unsupported. | 1.1, 1.2 |
| RISK-2 | A new child starts from the project default or shares an unsafe checkout; workers recurse into coordination. | Medium | High | Explicit source branch/full HEAD and isolated worktree verification; coordinator/worker role boundary; missing native capability refuses visibly. | 2.1, 2.2 |
| RISK-3 | Idle or a stale message is accepted as completion; interrupted integration creates duplicate work or unexpected branch movement. | Medium | High | Verify native activity and committed scoped progress; serial source-bound intervals; fast-forward only; reconcile Git and known child identity on resume. Ambiguous ownership/divergence stops. | 2.2, 4.1 |
| RISK-4 | Skipping a human blocker weakens phase prerequisites or decision logs become unauthorized criteria changes. | Medium | High | Permit ready AI siblings only within the first unfinished phase and independently admitted epic siblings; test later-phase refusal until earlier closure, independent versus dependent work and partial phase state. Material ambiguity stops affected work and returns through CIP; log remains mutable history. | 3.1 |
| RISK-5 | Old per-child PR close proof blocks the one-PR epic path, child finalization is omitted, or archive/finalization repeats on resume. | High | High | Distinguish one finalization target per child plan from the coordinator's distinct epic completion/index archive and one final delivery PR; retain archive checks and historical reads; test all-closed unarchived children, archived children, and pending/completed epic boundaries. | 3.2, 4.1 |
| RISK-6 | Replacing local orchestration accidentally retires working isolated runtime assets, breaks config/factory callers or deletes user state. | High | High | Keep autopilot plugin/dependency and isolated launch/auth/toolchain/feed/config/usage assets. Migrate only competing local loops after all live callers; test fresh/update installs, isolated runtime regressions, factory bounds and preserved history. | 4.2, 5.1 |
| RISK-7 | Static tests or shared harness claims are presented as live native/runtime capability proof. | Medium | High | Explicit human smokes cover local app and both isolated environments; verify actual worker settings/isolation and integration. Do not equate app local sandboxing with Docker/Windows Sandbox or promise native attachment. | 6.1, 6.2, 6.3 |
| RISK-8 | Isolated worker output/commits do not return safely, or old autonomous loops/PR publication compete with the app coordinator. | Medium | High | Bind exact start and bounded target, keep one coordinator, retain controlled transport/permissions and locally verify commits before fast-forward. Distinguish 42/43/failure from success, disable worker phase/child PRs in coordinator mode and preserve failed outputs/usage for recovery. | 2.2, 4.2, 6.2, 6.3 |
| RISK-9 | Shared Copilot harness is mistaken for shared lifecycle tools, silently breaking VS Code when local routes are removed. | High | High | Discover actual modern VS Code full-session creation/settings/observation/handoff; document target/version and small client-specific route. No app-only authority, same-context substitute or legacy Local guarantee. Capability gap stops before removal; explicit VS Code live gate covers local and isolated dispatch. | 2.1, 4.2, 7.1 |
