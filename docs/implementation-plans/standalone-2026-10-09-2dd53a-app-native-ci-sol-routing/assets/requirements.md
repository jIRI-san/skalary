# Requirements

Test IDs below are proposed focused regression names to implement in the repository's existing fixtures/runners. Live native-tool behavior additionally requires step 6.1; static tests do not substitute for it.

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | All six existing public aliases resolve to GPT-6.1 Sol, with policy-owned generated bindings. | CLI/app identifiers are `gpt-6.1-sol`; VS Code identifiers are `GPT-6.1 Sol (copilot)`. Generated skill assets and Waza executor/judge bindings agree. `test:ModelAllowlist.Sol61Bindings`; `test:ModelAllowlist.GeneratedConsumers`. | 1.1, 1.2, 5.1 |
| REQ-2 | Retain initial role effort and honest same-model review/replacement semantics. | Routine remains medium; Standard/Deep/Independent remain high. Secondary review uses separate context, not model diversity. An unavailable Sol cannot be retried as another model by switching aliases. `test:ModelAllowlist.RoleEffort`; `test:ModelAllowlist.SameModelUnavailable`. | 1.1, 1.2 |
| REQ-3 | CI is one app-native coordinator for interactive and unattended runs. | No CLI runtime menu/launch or silent direct-execution fallback. Missing native tools produces an explicit unsupported-host outcome. Both modes share admission/integration/finalization behavior. `test:AppCi.SingleExecutionPath`; `test:AppCi.UnsupportedHost`. | 2.1 |
| REQ-4 | Each admitted phase visit runs in a fresh isolated native child with exact settings. | Kickoff explicitly binds `gpt-6.1-sol`, high effort, default context, source branch, full expected HEAD, canonical plan/phase and non-planning execution. Workers cannot recursively coordinate phases. `test:AppCi.WorkerKickoff`; `test:AppCi.WorkerBoundary`; live step 6.1. | 2.1, 6.1 |
| REQ-5 | Preserve immutable criteria checks, source identity, and worktree safety. | Coordinator and worker check the confirmed Git baseline before mutation; dirty source, HEAD mismatch, missing confirmed criteria, or wrong isolation stops without stash/reset/copy. `test:AppCi.CriteriaAndIdentity`. | 2.1, 2.2 |
| REQ-6 | Integrate accepted phase progress serially with verified local fast-forward. | Idle/messages are not success. Verify clean committed scoped progress, evidence and ancestry; full close uses canonical phase-close proof. Integration checkout does not move during work; divergence stops. No phase PR is created. `test:AppCi.SerialIntegration`; `test:AppCi.CloseRefusal`; live step 6.1. | 2.2, 5.2, 6.1 |
| REQ-7 | Resume without duplicate workers, integration, or finalization. | Reconcile native identity and committed state; all-closed and already-integrated states do not repeat work. Ambiguous lost active-child ownership stops for reconciliation. Preserve child work; do not silently archive work-bearing sessions. `test:AppCi.ResumeAndRetention`. | 2.2, 4.1, 5.2 |
| REQ-8 | Unattended execution continues dependency-ready AI work around human blockers within existing phase boundaries. | Independent AI siblings in the first unfinished phase and independently admitted epic siblings run; human and human-dependent steps stay pending. Later phases remain blocked until every earlier phase closes, even with no explicit unmet dependency. Partial phases remain open. No-ready-work ends with an incomplete/blocker outcome, not success. `test:AppCi.HumanBlockerReadiness`; live step 6.1. | 3.1, 5.2, 6.1 |
| REQ-9 | Record bounded execution decisions and present the final handoff. | Create `assets/unattended-decissions.md` only when needed; entries identify affected step/criterion, choice, rationale and consequence, without secrets or criteria mutation. Report decisions and remaining blockers on exhaustion/completion. `test:AppCi.UnattendedDecisions`; live step 6.1. | 3.1, 5.2, 6.1 |
| REQ-10 | Material intent/acceptance/scope decisions remain operator-owned. | Preserve affected progress and use the existing CIP correction/reconfirmation gate; continue only independently admitted unaffected work. The decision log cannot override criteria or mark human work done. `test:AppCi.MaterialChoiceStop`. | 3.1 |
| REQ-11 | Epics use the same app-native execution and local integrated completion. | No host-only wrapper dispatch; ready children obey dependencies. New child closure is committed and integrated, not gated on a child PR. Preserve archived history and epic archive checks. `test:AppCi.EpicLocalExecution`; `test:AppCi.EpicBlockedSibling`. | 3.2, 5.2 |
| REQ-12 | One finalization target per standalone or epic-child plan and one requested-run PR own delivery. | Each plan finalizes after its phase closures, skips duplicate unchanged-scope review, and owns evidence, conditional compaction, learning and plan archive commits. All-closed unarchived children still finalize; finalized archived children are skipped without child PRs. After all child finalization commits are integrated and children archived, coordinator owns the distinct epic Goal/Definition-of-done/coherency check/index archival. Pending epic completion resumes; unchanged completed boundaries/publication do not repeat. Publish at most one final PR for the requested plan/epic. No PR merging or deployment. Dispatch is separate from bounded review/escalation budgets. `test:AppCi.FinalizationAndDelivery`; live step 6.1. | 2.1, 3.2, 4.1, 5.2, 6.1 |
| REQ-13 | Preserve completion gates and visible incomplete outcomes. | Human compaction/deletion/push gates are not self-approved. Headless PFB remains skipped. Failed evidence/review cannot archive. Learning precedes archive; archived paths re-resolve. `test:AppCi.CompletionGates`. | 4.1 |
| REQ-14 | Consolidate retained payload ownership and retire legacy autopilot execution. | Continue-implementation no longer depends on autopilot; retained installed paths have one owner. Retire old plugin/runtime payloads and update active generator/config/consumer references; new install and existing-install migration are explicit. `test:AppCi.RuntimeRetirement`; `test:AppCi.ConsumerMigration`. | 4.2, 5.1 |
| REQ-15 | Preserve unrelated tooling and historical/user-owned artifacts. | Archived plans and exact old ledgers remain unchanged; app runs do not fabricate usage. No deletion of local credentials/configs or unrelated CLI lifecycle/eval tooling. Obsolete runtime markers/settings are explained or refused explicitly. `test:AppCi.RetirementBoundaries`. | 4.2, 5.1 |
| REQ-16 | Source, distribution, documentation and live app behavior agree. | Owner-generated model/bundle/registry/marketplace/dogfood checks pass; active architecture/operator notes match the new path. Complete explicit live step 6.1 before declaring the plan completed. `test:AppCi.DistributionConvergence`; `review:cr`. | 5.1, 5.2, 6.1 |
