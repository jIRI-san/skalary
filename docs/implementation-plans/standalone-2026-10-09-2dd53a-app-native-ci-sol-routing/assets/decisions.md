# Decisions

- Operator-confirmed: app-only replacement; migrate epic execution and retire the legacy host/container/Sandbox routes in the same change.
- Operator-confirmed: serial local phase integration and one final plan PR, not a GitHub PR/merge per phase.
- Operator-confirmed: create a reviewed implementation plan before source implementation.
- Operator-confirmed: all primary and secondary model categories use GPT-6.1 Sol.
- Operator-confirmed through the selected model policy: retain current category efforts initially; unavailable Sol stops visibly rather than claiming a same-model alias is an availability fallback.
- Operator-specified: phase children use GPT-6.1 Sol, high effort, default context. This supersedes the earlier Auto/Intelligence proposal.
- Operator-specified: unattended execution proceeds as far as possible without human input and records choices in the exact supplied `assets/unattended-decissions.md` filename for the final handoff.
- Confirmed design interpretation: unattended discretion stays inside confirmed scope; material intent/acceptance choices and human steps are not silently decided/completed.
- Implementation direction: reuse public model aliases and source generators; their names remain compatibility categories, not a price ranking or proof of different models.
- Implementation direction: retain distinct read-only planning/review contexts without promising cross-model diversity.
- Operator-selected pre-confirmation correction: dependency-ready AI siblings in the first unfinished phase and independently admitted epic siblings can proceed around human blockers. Later phases wait until all earlier phases close; missing dependency annotations do not exempt that gate.
- Operator-selected pre-confirmation correction: each standalone or epic-child plan has one high/default finalization child and the complete terminal lifecycle. After integrating every child finalization and archiving all children, the coordinator owns the distinct epic completion check/index archive and one requested-run PR.
- Implementation direction: missing native app capabilities stops explicitly. There is no silent CLI/direct fallback.
- Implementation direction: no new execution journal, receipt schema, app extension, scheduler, or dynamic workflow. Resume uses native session context and committed Git/Markdown progress; ambiguous child ownership requires operator reconciliation.
- Implementation direction: historical CLI credit ledgers stay readable; exact app usage accounting is not fabricated or made a completion prerequisite.
- Implementation direction: native app behavior requires an explicit live human acceptance step; deterministic/static tests alone are insufficient.
