# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- **Extend `b0c0d3`; do not supersede it.** Preserve REQ-8 (seven model-agnostic concern agents with local safety guards), REQ-10 (deterministic concern-to-ledger mapping), explicit-model dispatch, and the settled seven-concern taxonomy. This plan changes authorship and generation only.
- **Separate content authority from policy oracles.** `tools/review-concerns.json` owns guidance and mappings; `schemas/authoring/review-concerns.schema.json` independently pins the exact seven ids; `tools/model-allowlist.psd1` remains host authority. A taxonomy change therefore needs explicit policy edits and remains outside this plan.
- **Use one shared agent template.** `tools/review-concerns.agent.template.md` owns common structure and guardrails; registry records carry bounded code-review and design-review data substituted literally once. A provenance fixture binds immutable pre-generation Git bytes, while separate live checks bind generated outputs.
- **Use type-specific generated boundaries.** Agents are whole-file output; Markdown adopts the repository's `BEGIN/END GENERATED: <owner>` grammar; manifests are parsed and reconcile only concern-agent `files[]` records; PowerShell tests and validators read the registry at runtime. A vague cross-format marker convention is rejected.
- **Use a dedicated sync-and-drift command.** `Sync-ReviewConcerns.ps1` requires PowerShell 7.6+, validates and renders the whole graph before writes, rejects links/reparse points, prunes only plugin-source concern agents, emits bounded outcomes, and fails non-mutating `-WhatIf` runs on drift. It does not absorb `Sync-PluginScripts.ps1` responsibilities.
- **Keep downstream authorities separate.** `Sync-Dogfood.ps1`, `Build-Registry.ps1`, and `Build-Marketplace.ps1` retain their current ownership and run after concern generation.
- **Generated whole files carry durable ownership twice.** Every generated agent includes a template-owned marker and appears with its SHA-256 in `tools/review-concerns.generated.json`; dogfood pruning reads that inventory from the explicit prior base (or dirty-run `HEAD`), so a committed manifest/inventory removal does not erase prior generated authority.
- **Dogfood pruning never outranks installer or user ownership.** Under the mutation lock, `Sync-Dogfood.ps1` may delete only a generated, undeclared, Git-tracked concern agent whose current bytes match the prior-base inventory and current `HEAD`, and whose destination appears in no validated receipt. Receipt-store uncertainty, receipt ownership, modification, untracked state, links, or unprovable authority return a typed refusal and remedy.
- **Dogfood preflight is atomic; convergence is resumable.** All known refusal conditions are evaluated before the first payload mutation. An unexpected I/O failure after copying or deleting may leave partial dogfood convergence, reports exactly what completed, never edits receipts, and is repaired by an idempotent rerun.
- **Use per-plugin version-first Git-baseline convergence instead of a journal.** Resolve full `HEAD` for dirty/local generation and a full-hex explicit event base for CI. When one plugin's desired managed bytes differ and its version equals baseline, atomically replace that manifest with the incremented version before its payload writes. Interruption can leave a harmless version-only state; same-baseline rerun completes outputs without another bump.
- **Keep version ownership domain-specific.** The concern generator advances versions only for its managed payload delta; other generators retain their domains. Candidate-vs-base validation proves every concern payload change has some version advance, while a joint-writer fixture prevents lost manifest updates.
- **Serialize plugin-source manifest writers.** All writers use one worktree-scoped lock resolved by Git and hold it across manifest read/merge/version/write. Atomic replacement prevents torn bytes; serialization prevents last-writer-wins loss across generator domains.
- **Register the new gate where it runs.** `gate:review-concern-generation` lives in `scripts/validate.ps1` and receives a machine-checked `ci-gates.design.md` inventory row. Process-heavy mutation/distribution evidence belongs to Slow; the Fast drift gate must fit existing platform ceilings.
- **Use the existing bounded Fast/Slow CI contract.** `gate:repository-validation` already runs `scripts/validate.ps1` on Linux and Windows, and `gate:slow-suite` enforces archived plan `31a3ef`'s manifest-owned 1,800-second ceiling with exit 5 on overrun. New process-heavy files enter Slow before first execution. This plan does not conditionally promise a supplemental receipt; CI gate results remain authoritative.
- **Give payload-version comparison its own CI gate.** `gate:review-concern-payload-version` runs in `registry-ci.yml` because that host owns the event base SHA. The generator's local `HEAD` comparison cannot substitute for candidate-vs-base CI evidence.
- **Bound recurring context at 8 KiB per agent.** The current agents are roughly 4 KiB; 8 KiB leaves room for explicit surface variants without doubling review fan-out context again. Larger content requires a reviewed budget change.
- **No review-run contract change.** The registry is build-time authorship only; `ARCH-Review-Run-V1`, review schemas, frozen task truth, dispatch, publication, and retained evidence remain unchanged.
- **Execute autonomously without new packages.** Default to container autopilot for the whole plan; every step is `@ai-agent`, expected packages are `none`, and rollback is git revert.
- **Rejected: registry-only centralization.** A registry that generates nothing is another copy and does not make drift structurally impossible.
