| REQ-5 | Every plugin-source manifest writer, including `Sync-ReviewConcerns.ps1` and `Sync-PluginScripts.ps1`, resolves one worktree-scoped generation lock through `git rev-parse --git-path skalary-plugin-generation.lock` and holds it across manifest read/merge/version/write. Under that lock, the concern generator resolves its immutable baseline and computes desired state independently for `code-review` and `design-review`. Dirty/local generation compares against full `HEAD`; CI accepts only an explicit 40- or 64-hex base commit. Only a plugin whose desired managed bytes differ from baseline enters version comparison. If current version equals baseline, atomically replace the merged manifest with its incremented version **before** that plugin's payload writes; a version above baseline satisfies same-baseline debt. | Fault seams independently cover each plugin at lock acquisition, pre-bump, atomic replacement, post-bump, every output family, and clean replay. Lower/incomparable versions, missing/invalid baseline, and changed payload without version advance are typed zero-write failures. A forced two-writer interleaving proves serialization preserves both domains' entries and version movement. `test:ReviewConcerns.VersionBaselineAndRecovery` · `test:ReviewConcerns.PayloadVersionGate` · `test:ReviewConcerns.ManifestWriterSerialization` | 1.2, 2.1, 3.1 |
| REQ-6 | `Sync-Dogfood.ps1` remains installed-copy authority and accepts an optional full-hex `-BaselineRef`. It considers at most 32 candidates with one bounded Git batch. Deletion requires manifest absence, a prior-inventory path/hash, whole-file generated marker, current bytes equal to the prior hash and current `HEAD` blob, and no receipt owner. Fault seams after first copy/delete prove partial runs converge. `test:ReviewConcerns.DogfoodAuthorityAndDistribution` · `test:ReviewConcerns.DogfoodRefusalMatrix` · `test:ReviewConcerns.DogfoodPartialRecovery` · `test:unit` · `test:validate-all` | 2.2, 3.1 |
