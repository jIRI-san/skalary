# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | A manifest, receipt, temporary path, or linked parent escapes `.github` or writes a workflow. | Medium | High | Reuse and tighten physical canonicalization before every read/write; preflight complete path sets; retain focused traversal/root/link/workflow refusal fixtures. | 1.2, 1.3, 2.2, 3.3 |
| RISK-2 | A malformed receipt or unavailable immutable source/ref makes installed identity or exact removal paths unknowable. | Medium | High | Validate the closed receipt shape and source identity directly; materialize the pinned manifest before mutation; fail visibly without advancing/deleting the receipt or guessing paths. | 1.1, 1.3, 2.2, 3.1, 3.3 |
| RISK-3 | Removing transactions and locks leaves partial payload changes after interruption. | Medium | High | Preflight the full operation, mutate receipts last, verify final filesystem state, preserve the prior/no-receipt truth on failure, expose the partial state, and prove convergent retry; claim no rollback. | 1.2, 1.3, 2.2, 3.1, 3.3 |
| RISK-4 | Explicit update overwrites an operator edit inside a receipt-owned plugin path. | Medium | High | Treat matching plugin/source receipt plus explicit update as overwrite authority, document the behavior before invocation, refuse unowned collisions, and keep this accepted tradeoff in `## Dubious decisions`. | 1.2, 2.2, 3.1, 3.3 |
| RISK-5 | Removal begins deleting before discovering a modified target or retirement mutates an unrelated plugin. | Medium | High | Compare the complete pinned manifest set before unforced deletion; abort with all differing paths; require `-Force`; delete automatic retirement reconciliation and test unrelated commands for zero retirement mutation. | 1.3, 2.2, 3.3 |
| RISK-6 | Deleting lifecycle state leaves hidden callers, schemas, plugin bundles, or docs expecting old fields and switches. | High | High | Treat canonical source, manifests, bundles, dogfood, catalogs, tests, approvals, and active docs as one cut; add a closed active-residue assertion; do not add adapters. | 1.1, 2.1, 2.3, 3.1, 3.2, 3.3 |
| RISK-7 | Test pruning or generated updates weaken external catalog/distribution coverage or exceed focused timing. | Medium | High | Retain behavior/external-format/high-impact cases, reuse the manifest-derived foreign fixture and existing generators, run selected tests through focused commands, and keep broad/premium routes operator-only. | 2.2, 2.3, 3.2, 3.3 |
