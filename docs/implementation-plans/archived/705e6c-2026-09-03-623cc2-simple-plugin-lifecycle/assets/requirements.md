# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Every plugin lifecycle filesystem access is physically confined to the consumer `.github` tree. | Install, update, remove, receipt, temporary, and retired-manifest paths reject traversal, rooted/drive/UNC/ADS forms, links/reparse points in any existing component, destinations outside `.github`, and `.github/workflows/**` before state reads or mutation; focused negative tests cover each boundary. `test:PluginLifecycle.Confinement` | 1.2, 1.3, 2.2, 3.1, 3.3 |
| REQ-2 | One minimal per-plugin receipt remains solely for installed identity and version detection. | `.github/.skalary/receipts/<name>.json` has exactly `name`, `version`, `sourceIdentity`, and immutable `ref`; direct validation rejects unknown, missing, malformed, mismatched, linked, and legacy-shaped receipts; `Get-Plugin`, `Find-Plugin`, dependency guards, update, and remove consume this shape; `schemas/receipt/receipt.schema.json`, file hashes/outcomes, `degraded`, timestamps, eval status, migrations, and dual readers are absent. `test:PluginLifecycle.MinimalReceipt` | 1.1, 1.2, 1.3, 2.1, 2.2, 3.3 |
| REQ-3 | Install is a direct, receipt-last, convergent operation. | It resolves one immutable source and dependency order, preflights the complete manifest, refuses existing paths without a matching plugin/source receipt unless `-Force`, applies confined payload bytes, verifies all expected hashes in memory, writes receipts only after verification, and makes no change on an unchanged rerun. `test:PluginLifecycle.Install` | 1.2, 2.2, 3.3 |
| REQ-4 | Update uses the minimal receipt to detect and replace an installed plugin version without file-level ownership state. | It compares installed version/ref to the resolved target, materializes old and new manifests, refuses source-identity mismatch, replaces/removes their manifest-path union for the matching receipt even when locally edited, verifies the target bytes and old-path absence, advances the receipt last, and is a no-op when version/ref and payload already match. `test:PluginLifecycle.Update` | 1.2, 2.2, 3.1, 3.3 |
| REQ-5 | Remove is explicit, preflighted, and non-destructive by default. | It materializes the exact installed manifest from the receipt source/ref; missing targets count as already removed; if any present target differs from the pinned payload, an unforced call reports all differing paths and performs no deletion; `-Force` deletes the confined manifest set; dependency refusal remains unless forced; the receipt is deleted only after result verification; retry converges. `test:PluginLifecycle.Remove` | 1.3, 2.2, 3.1, 3.3 |
| REQ-6 | Retirement is published refusal metadata plus explicit removal, not an automatic state machine. | `registry-retirements.json` remains the direct source for generated retired-name and pinned-manifest metadata; registry/lookup preserve exact retired status; install/update of a retired target fail visibly with the explicit removal command; an installed retired plugin is removed only by `Remove-Plugin`; `-ApplyRetirements`, previews, cursors, replay, result state, unrelated-command mutation, and terminal retirement records are absent. `test:PluginLifecycle.Retirement` | 1.3, 2.1, 2.2, 2.3, 3.3 |
| REQ-7 | Transactional and compatibility lifecycle machinery is deleted as one closed cut. | Active source, plugin manifests, bundled/dogfood copies, schemas, docs, and tests contain no mutation lock, journal, backup, rollback/recovery, CAS, file-ownership/degraded receipt, retirement runtime state, or compatibility reader; retained shared source/semver/confinement helpers remain direct. `test:PluginLifecycle.RetiredStateResidue` | 1.1, 2.1, 2.2, 3.1, 3.2, 3.3 |
| REQ-8 | External plugin catalogs and generated distribution remain compatible and converged. | `plugin.json`, `registry.json`, `.github/plugin/marketplace.json`, retirement catalog source, README/catalog, plugin-manager bundles, and dogfood are produced through the existing sync/build sequence; registry and marketplace validation plus foreign-consumer installation pass without hand-edited generated output. `test:PluginLifecycle.Distribution` `test:ConsumerInstall.ForeignFixtureInventory` | 2.3, 3.2, 3.3 |
| REQ-9 | Validation and guidance close with the direct lifecycle. | Retained tests map to current user behavior, required external formats, or high-impact confinement regressions; routine commands use explicit affected paths, target under 30 seconds, and time out distinctly at 60 seconds; architecture/design notes and plugin-manager skills describe the shipped parameters, visible partial-failure behavior, and accepted simple-over-safe tradeoffs. `file:docs/architecture-notes/arch-install-confinement.md#contains:minimal receipt` `file:docs/design-notes/architecture/plugin-registry.design.md#contains:Dubious decisions` `review:cr` | 2.2, 2.3, 3.1, 3.2, 3.3 |
