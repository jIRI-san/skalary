# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | A host-owned loop uses existing `Get-PlanState` epic rollup/`NextChild` and the existing per-plan launcher; it never reimplements plan parsing, child selection, or container execution. | Focused tests prove the same rollup child is launched and no second child starts concurrently. `test:EpicAutopilot.HostLoop` | 1.1, 1.2, 3.2 |
| REQ-2 | One resumable JSON record contains only `epic`, `target`, `currentChild`, `branch`, `run`, and `outcome`; it supports status and resume for the current sequential run. | State tests prove exact fields, restart/resume, stale-target refusal, and no parallel-child state. `test:EpicAutopilot.ResumeState` | 1.1, 1.2, 2.2, 3.2 |
| REQ-3 | After existing terminal verification of the child result, evidence, branch, and remote head, the host stops for operator merge and performs no merge or target push itself. | Terminal-gate tests prove success stops awaiting merge and invalid/degraded results stop without selecting another child. `test:EpicAutopilot.MergeGate` | 2.1, 3.2 |
| REQ-4 | After operator merge, the host refreshes the target and dependency graph, then repeats with the new `NextChild`; blocked, failed, or degraded outcomes remain resumable and are never silently skipped. | Two-child and graph-change fixtures prove refresh, ordering, stop/resume, and no stale selection. `test:EpicAutopilot.RefreshAndRepeat` | 1.2, 2.2, 3.2 |
| REQ-5 | After the final merge, the host invokes simplified epic coherency review when available or performs an epic-intent/definition-of-done crosscheck, then records the result through existing workflow evidence. | Final fixtures prove both available-review and fallback-crosscheck paths and absence of an evidence-only finalization branch/PR. `test:EpicAutopilot.FinalCrosscheck` | 3.1, 3.2 |
| REQ-6 | Changed host/skill payloads converge through existing launcher distribution, plugin generators, dogfood, registry/catalog, installed-consumer, and test infrastructure. | Generated-drift and installed-host checks pass without new provider/state contract families. `test:EpicAutopilot.ConsumerInstall` `test:bundle-no-drift` `test:dogfood-no-drift` | 3.2 |
