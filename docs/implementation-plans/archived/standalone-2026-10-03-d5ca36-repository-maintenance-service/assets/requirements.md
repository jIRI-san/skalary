# Requirements

Stable test IDs below are implementation targets, not claims that these tests already exist. Implement
focused Pester cases under the current runner convention; structural checks protect instructions while
scenario evidence demonstrates the cited behavior without claiming a measured model-quality gain.

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | `/rcs` provides repository-wide inventory/survey plus risk-selected deep traces, not an exhaustive quality guarantee. | `test:RCS.InventoryCoverage` covers plan/subsystem discovery from existing indexes/manifests/entry points or foreign project/layout evidence, explicit surveyed/traced/skipped/blocked distinctions, no-plan consumer without invoking an absent-corpus index, and incomplete selected trace; a disposable scenario shows actual citations and no clean claim for unread areas. | 1.1, 1.2, 3.1 |
| REQ-2 | Reuse existing current plan/epic discovery and bounded historical intake with provenance; legacy missing intent is not reconstructed. | `test:RCS.HistoricalDiscovery` checks active/archived/no-intent/malformed candidates, explicit errors, max-three-artifact intake and data-only framing; current helpers support selected intent reads without enhanced snippets, their absence is a disclosed search/epic-context gap, and incompatible current helper APIs stop before mutation. | 1.1, 1.2 |
| REQ-3 | Compare human intent, requirements, scoped decisions, contracts and relevant docs against current code; distinguish defects, alignment questions, unfinished work and optional improvements. | `test:eval:RCS.AlignmentContract` protects citation, trigger, impact, exception/counter-evidence and missing-context guidance; disposable cases report a real mismatch, honor an exception, and leave conflicting human statements as an operator question. | 1.2, 3.1 |
| REQ-4 | Include codebase-wide architecture/design improvement proposals and coding-standard drift in proposed actions, not only plan-related findings. | `test:eval:RCS.CodebaseQualityContract` protects local-standard precedence, Simplicity First, and fix/won't-fix actions; a scenario cites a concrete cross-subsystem opportunity and its smallest useful correction/tradeoff without claiming a requirement violation. | 2.1, 3.1 |
| REQ-5 | Detect dead-code candidates through supported-entry-point and indirect-use investigation; recommend planned removal only with justified reachability evidence. | `test:eval:RCS.DeadCodeContract` checks no-reference-is-insufficient guidance and public/manual/generated/dynamic/external roots; scenarios distinguish an unused private helper, exported manual tool and registered indirect handler, and preserve uncertainty where needed. | 2.1, 3.1 |
| REQ-6 | Inspect plan/epic state and propose archival of implemented work through existing completion/archive contracts, with separate explicit approval. | `test:RCS.ArchiveHandoff` covers incomplete/unknown evidence, archived no-op, unarchived epic children, collisions/links, absent capability, and selected success; persisted clean reports or a clean worktree do not prove completion; no archive runs without the selected action. | 2.2, 3.1 |
| REQ-7 | Publish actionable evidence-backed recommendations with category, subject, citations, current behavior/reachability, impact, uncertainty, proposed action, benefits/tradeoffs, effort and complexity. | `test:eval:RCS.RecommendationContract` checks required fields and categories; scenario output includes drift, dead-code and architecture/design proposals with concrete citations, 1-10 effort/complexity, and explicit limitations. | 1.2, 2.1, 3.1 |
| REQ-8 | Preserve findings and dispositions in one confined advisory `docs/repository-maintenance.md` record. | `test:RCS.RecordRoundTrip` proves create/read/update, exact stable-ID/subject/scope/citation matching, preserved human prose/decisions, idempotence, empty/partial run handling, no deletion of unseen entries and operator choice for ambiguous ID reuse; `test:RCS.RecordRefusal` proves compile-time fixed path, physical-link refusal with `Resolve-PhysicalRepoPath` and per-component checks, malformed/invalid UTF-8/secret/128-KiB refusal and original-file preservation. | 1.2, 2.2, 3.1 |
| REQ-9 | Accept intentional drift or won't-fix only by explicit scoped operator decision; honor unchanged decisions and revisit on changed basis without erasing history. | `test:RCS.DispositionRoundTrip` covers pending/silence, dated rationale/scope/revisit condition, unchanged suppression, changed evidence/assumptions, preserved old rationale, and no blanket exemption for future defects or silent contract/criteria edits. | 2.2, 3.1 |
| REQ-10 | Fix means normal corrective planning, with active-plan overlap checks and established criteria/contract approval flows. | `test:RCS.CorrectivePlanHandoff` covers existing-plan link/update/new choices, operator-selected handoff, original intent/evidence retained, failed/cancelled planning left pending, successful plan link, and affected criteria reconfirmation. Code is not changed and plan creation is not recorded as fix completion. | 2.2, 3.1 |
| REQ-11 | Keep review read-only outside the fixed report, repository content untrusted, secrets screened, and mutations/direct commands operator-controlled. | `test:eval:RCS.BoundaryContract` protects direct-first/current aliases/three-call budget, single `ConvertTo-UntrustedReviewBlock` framing with preserved already-framed history, proportional security, explicit mutation choices, no direct code delete/fix/commit or unapproved broad/premium/network crawl; `test:RCS.RecordRefusal` exercises guards and failure outcomes. | 1.1, 1.2, 2.1, 2.2, 3.1 |
| REQ-12 | Ship a documented independently installable plugin with focused evidence and generator-owned distribution closure. | `file:plugins/repository-maintenance/plugin.json#exists` and `file:docs/design-notes/architecture/repository-maintenance.design.md#exists`; `test:RCS.ConsumerInstall` verifies installed payload/script closure, sole record literal scaffold without a scaffold confine helper, declared consumer-owned read exceptions in the existing optional-input table, foreign-consumer smoke, no sibling/source imports, generated convergence and SKILL size; `review:cr` is one current-source whole-plan final review. | 3.1, 3.2 |
