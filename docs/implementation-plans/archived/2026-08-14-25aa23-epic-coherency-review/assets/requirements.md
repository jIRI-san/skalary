# Requirements

> **Superseded 2026-09-06.** These requirements describe the review-run architecture delivered by
> this plan and later retired by plan `367e9a` in commit
> `a652134251e217e8227e184dae1bf49a32b294df`. Current review behavior is governed by
> `ARCH-Direct-Workflow` and the repository-wide Simplicity First rule. The table remains as historical
> intent and is not an active implementation backlog.

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | `/cep` invokes existing design-review agents through review-run v1 with a fixed epic-coherency scope after the operator accepts a proposed cut, after the epic-only canonical source is complete, and before child scaffolding or finalization. | Focused tests prove the exact-byte frozen scope covers goal/done coverage, verticality, independence, overlap, ownership, dependencies, MVP/final route, and prior-art reuse; degraded, incomplete, unpublished, unreadable, or stale review authority blocks. `test:EpicCoherency.FixedScope` `review:dr` | 1.1, 2.1, 3.2 |
| REQ-2 | The review compares every proposed mechanism and dependency to confirmed operator intent, detects duplication across children, requires one owner for each shared mechanism, challenges infrastructure-only edges, and prefers deletion, reuse, or a local fix. | Fixtures surface duplicated platforms, owner ambiguity, and dependencies unsupported by delivered behavior. `test:EpicCoherency.IntentAndOwnership` | 1.2, 2.2, 3.2 |
| REQ-3 | Every finding receives one proportionality class: `local fix`, `required shared contract`, or `speculative platform`. Only a demonstrated cross-plan invariant may justify shared architecture; minor/local findings cannot justify new schemas, protocols, stores, state machines, compatibility layers, providers, or dependencies. | Regression fixtures reproduce minor design-review findings escalating into platform machinery and require rejection unless a cross-plan invariant is demonstrated. `test:EpicCoherency.ProportionalityGuardrail` | 1.2, 2.2, 3.1, 3.2 |
| REQ-4 | Before review, the accepted epic source contains one compact provisional `keep`, `simplify`, `split`, or `defer` decision section; verified findings update that same section with operator resolutions, and every source-changing resolution requires a fresh review. Finalization blocks until a verified finding-free run is bound to the unchanged current source. | Tests prove confined deterministic full-block replacement through the existing epic writer, exact finding-to-resolution binding, stale-source invalidation, unresolved-block behavior, operator return, rerun after source-changing resolutions, and no post-clean-review source mutation. `test:EpicCoherency.VerdictAndResolution` | 2.1, 2.2, 3.2 |
| REQ-5 | Existing review agents, fixed concerns, dispatch planning, and review-run v1 remain authoritative; no generated concern version or new epic review authority is required. | Installed-review tests prove reuse of existing agents/publication and absence of a second scheduler or review lifecycle. `test:EpicCoherency.ExistingReviewPath` | 1.1, 3.1, 3.2 |
| REQ-6 | Changed skill payloads and compact epic output converge through existing plugin generators, sync writers, registry/catalog paths, and test infrastructure. | Generated-drift and installed-consumer checks pass without a new schema, activation path, or CI workflow. `test:EpicCoherency.ConsumerInstall` `test:bundle-no-drift` `test:dogfood-no-drift` | 3.1, 3.2 |
| REQ-7 | After deterministic `/ci` admission and before each epic child run, `/ci` applies the same intent, duplication, ownership, dependency, and proportionality check to the admitted plan plus existing epic rollup/verdict metadata; it does not read sibling plan bodies. The compact result is recorded through existing epic verdict or current-plan decision prose and unresolved overcomplication blocks the run, including headless execution. | A stale-plan fixture reintroduces a speculative mechanism and infrastructure-only edge after epic approval; the `/ci` pre-run check uses the verified epic source digest and current Git history as its baseline, blocks it, and an unchanged simple plan records `keep` without creating a state store or prompt-only admission authority. `test:EpicCoherency.PreRunSimplicityCheck` | 2.3, 3.1, 3.2 |
