# Intent

## Goal

Improve planning and review quality while keeping Skalary simple, understandable, locally operated and cost-conscious.

## Desired outcome

Catch operator/agent interpretation drift before design and implementation effort is spent. Persist meaningful intent and an operator-readable lightweight RFC in existing plan assets. Reconcile relevant earlier intent without giving history veto power. Technical reviews produce evidence-backed findings, fit the existing codebase, and consult applicable official documentation for consequential uncertainties.

Selected operator statements from the 2026-10-03 planning conversation:

> "the earlier we catch the issue the better"
>
> "we want to be sure, that we catch possible drift of what op and agent are understanding as soon as possible"
>
> "the rules and conventions of the existing code take priority and agents work in concert with them, not against them"
>
> "we still want to keep this simple, understable, not overengineered"
>
> "normal development cycle should not be stuck for minutes on running evals every single time"
>
> "no new github ci should be created, we run these locally"

The operator confirmed the proposed complete scope on 2026-10-03 before drafting: surrounding planning/execution skills, historical comparison, existing intent/design assets, stronger reviews and 12-20 scenarios. The operator selected a full authored suite with separately approved paid comparisons, not routine paid execution.

After the required draft review and all four selected corrections, the operator confirmed the complete intent/design/requirements/risks/decisions on 2026-10-03 and requested a plan-only commit, without starting implementation.

## Success signals

- Planning asks a targeted question when two plausible interpretations change consequential outcomes; it respects explicitly bounded discretion and deferment.
- Draft review compares with selected operator statements/answers, not only an agent-written summary.
- Historical intent-only conflicts are discoverable; reported conflicts cite old/new statements and overlapping scope. Operator-approved supersession is explicit.
- Implementation stops for a material unresolved intent choice, not every internal coding detail.
- Findings identify trigger, failure path/contract conflict and impact, and consider disconfirming evidence. Optional preferences do not become defects.
- Implementation/review share scoped local conventions; documentation checks are targeted, version-aware, read-only and non-leaking.
- Development uses exact local selectors. Ordinary deterministic commands retain the under-30-second target and existing timeout behavior. Paid selected-case execution never widens into unrelated packs.
- Improvement claims are supported by observed comparisons or explicitly withheld when paid execution is deferred.

## Non-goals

- New review plugin, mandatory intent reviewer, model panel, judge stage or higher call ceilings.
- Intent registry, RFC service, persistent search index, semantic store, policy engine, generalized rule schema, receipts or extra confirmation markers.
- Separate duplicated RFC or language handbook; replacing the existing standards grammar.
- Exhaustive archive replay, automatic policy promotion, routine web browsing or unrelated modernization.
- GitHub CI, aggregate local gates, routine full-suite/premium runs or new eval harness.

Authorized discretion: wording, focused fixture organization, existing scoped note placement and local implementation details may be selected by the implementer within these boundaries. Paid case selections and any full final run remain operator decisions. Active-contract changes or expanded storage/tooling require an explicit decision.

## Definition of done

All requirements in this plan are delivered through existing skills/assets/tools, shipped to installed consumers and verified with scoped deterministic checks. The existing pre-confirmation calls and review budgets remain. An operator paid-eval decision is recorded; deferral is permitted but is not empirical quality evidence. Delivery is compared with this original intent without rewriting it to match shipped behavior.
