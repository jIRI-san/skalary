# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | CR/DR produce direct advisory Markdown with fixed source, scope, completed-task, finding, and verdict sections. | Plan-associated phase/final paths are resolved under the canonical plan; Source names one full reviewed commit; Verdict is `clean`, `findings`, or `incomplete`; generic runs return chat output unless explicitly saved; a clean result requires every selected task to complete. `test:SimpleReview.MarkdownReports` | 1.2, 1.3, 2.1, 2.2 |
| REQ-2 | Review selection and delegation implement the accepted agent-cost budgets. | Tasks use 2 delegated calls by default and at most 5 including replacements, at most 5 supporting artifacts, a 600-word prompt target, and a 1,200-word hard cap; availability fallback replaces rather than adds a call. `test:SimpleReview.AgentBudgets` | 1.1, 1.2, 2.1 |
| REQ-3 | Model roles are OpenAI-first with independent non-OpenAI review only where it adds value. | Representative cost, latency, availability, and useful-result observations precede operator approval of exact role bindings; routine work uses approved OpenAI models and Claude is limited to terminal or stated concrete high-risk review. `test:SimpleReview.ModelPolicy` `file:docs/design-notes/explorations/agent-cost-optimization.design.md#contains:Observed` | 1.1, 1.2 |
| REQ-4 | Plain instructions and native agent calls replace Fleet scheduling. | `/cip`, `/ci`, autopilot, CR, and DR express dependencies and expected outputs directly; Designer/Validator are combined when useful, the orchestrator performs ordinary work, and Judge is the normal second call; native flow and recovery exist before activation; no Fleet module, descriptor, attendance, or generated concern scheduler remains afterward. `test:SimpleWorkflow.NativeDelegation` | 1.2, 1.3, 2.1, 2.2, 5.2 |
| REQ-5 | Stuck delegation is detected by progress evidence without killing long-running work. | For observable background tasks, new tool output, file/commit change, completed subtask, or materially new blocker counts as progress; two explicit no-progress checks cause one same-agent redirect, then at most one replacement within budget, then an operator stop. Synchronous calls return or rely on host/operator interruption rather than a claimed polling ability. Elapsed time alone never kills an agent, while declared deterministic command timeouts remain. `test:SimpleWorkflow.StuckRecovery` | 1.2, 1.3 |
| REQ-6 | Review cadence avoids duplicate terminal work and has a closed exhaustion outcome. | Non-terminal review is omitted unless a concrete changed-scope risk triggers one event plus at most one corrective replacement; the terminal phase skips post-phase CR and finalization writes exactly one whole-plan review event; unchanged scope is never rerun; exhausted calls, incomplete attendance, or unresolved findings stop with `findings`/`incomplete`. `test:SimpleWorkflow.SingleTerminalReview` | 1.2, 1.3, 2.1, 2.2, 5.3 |
| REQ-7 | Confirmed plan criteria remain immutable during execution while progress remains resumable. | `/ci` and every autopilot mode locate the unique Git commit that introduced the current planning-confirmation marker, compare intent/requirements/risks/decisions to that tree before mutation, and refuse missing/uncommitted/ambiguous/drifted baselines; checklist/worktree/stage markers remain mutable. Tests alter each protected file independently across interactive and autonomous modes. `test:SimpleWorkflow.CriteriaProtection` | 1.2, 1.3, 2.1, 2.2 |
| REQ-8 | Typed evidence is verified directly without receipt authority. | `test:`, `file:`, and `review:` remain the only evidence markers; current commands/files and the active complete clean review result for the requested current scope are checked directly; persisted Markdown remains advisory; evidence/review receipts, stores, manifests, digests, and repair paths are absent. `test:SimpleWorkflow.DirectEvidence` | 1.2, 1.3, 2.1, 2.2, 5.2 |
| REQ-9 | Interactive and autonomous outcomes fail visibly. | Completed, refused, blocked, stuck, and interrupted outcomes are distinct; exit `0` means completed, operator-action stops retain exit `42`, and every other failure remains nonzero with readable progress left in Git/Markdown. `test:SimpleWorkflow.VisibleOutcomes` | 1.2, 2.1 |
| REQ-10 | Complex operator questions provide enough information for an educated decision. | Both hosts receive equivalent context, concrete examples, benefits, pros/cons, and 1-10 effort/complexity; a Mermaid diagram is included when relationships or sequencing matter. `test:SimpleWorkflow.DecisionReadyQuestions` | 2.2 |
| REQ-11 | Active policy language distinguishes unconditional invariants from conditional and fuzzy requirements. | Active skills, agents, instructions, design notes, and architecture notes are inventoried for absolutes and the seeded fuzzy vocabulary; confirmed absolutes remain, conditional rules use explicit condition/behavior/exception form, and fuzzy terms gain an observable criterion, threshold, example, or operator interpretation. `test:SimpleWorkflow.InstructionLanguage` | 2.2, 4.2 |
| REQ-12 | Security review is concrete and proportionate to the trusted single-operator repository. | Before direct-workflow activation, findings require attacker/input, reachable capability, affected asset, and plausible impact; prompt-injection framing, secret redaction, read-only review, destructive-action approval, canonical plan/report write confinement, and external-format checks remain; absent boundaries do not justify enterprise machinery; material tradeoffs are presented to the operator. `test:SimpleReview.ProportionalSecurity` `test:SimpleReview.RetainedGuards` | 1.2, 1.3, 3.1 |
| REQ-13 | Edited AI-facing design notes receive one bounded semantic compaction pass at finalization. | The pass runs only when `docs/design-notes/**` changed, inventories the active index without loading the corpus wholesale, compares at most five candidate notes per batch, preserves unique decisions/contracts/constraints/exceptions/minimal examples, shows the Git diff, updates the index, and asks before cross-note merge/delete; cancellation/failure leaves a visible diff for correction or Git revert; `docs/operator-guide/**` is excluded. `test:SimpleWorkflow.DesignNoteCompaction` | 4.1 |
| REQ-14 | Human-readable documentation explains the complete delivered process. | `docs/operator-guide/README.md`, `planning.md`, `implementation.md`, and `reviews.md` describe every artifact, gate, sequence, budget, model rule, review/retry limit, and stop/resume path with linked Mermaid flows. `test:SimpleWorkflow.OperatorGuide` | 4.1 |
| REQ-15 | Completion produces one bounded learning handoff for `/si`. | `/ci` and autopilot replace `docs/feedback/recent-learning.md` with source plan/commit plus at most 10 cited items and 16 KiB UTF-8; missing, explicit-empty, and source-mismatch/stale outcomes are distinct; child `3a4498` fences it as untrusted at read time; review-ledger, overflow, replay, receipt, repair, and lifecycle services are absent. `test:SimpleWorkflow.RecentLearning` `file:docs/feedback/recent-learning.md#exists` | 4.2 |
| REQ-16 | The old workflow machinery is removed atomically with all owned consumers and copies. | New dormant paths are proven before activation; one activation step switches every producer/consumer and removes review-run schemas/store, receipts, Fleet copies, generated concern registry/agents, JSON checkpoints, phase-harvest/evidence receipts, repair machinery, manifest entries, dogfood copies, and historical-adapter receipt dependencies. Focused residue and installed-consumer checks independently enumerate forbidden paths and retained host/external-format behavior. `test:SimpleWorkflow.RetiredMachinery` `test:SimpleWorkflow.ConsumerInstall` `review:cr` | 1.2, 1.3, 2.1, 2.2, 5.2, 5.3 |
