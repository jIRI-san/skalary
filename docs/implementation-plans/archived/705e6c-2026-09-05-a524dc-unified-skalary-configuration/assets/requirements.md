# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | One human-readable catalog describes every accepted configuration category without becoming authority for its values. | The catalog covers autopilot, model/review roles, local review standards, terminal approvals, evals, note scaffolds, plugin distribution, and repository/toolchain policy; every row names canonical/default/generated paths, precedence, sensitivity, bootstrap behavior, writer/synchronizer, validator, and installed-consumer availability; unknown surfaces are unsupported rather than guessed. `test:SkalaryConfig.Catalog` `file:plugins/skalary-config/plugin.json#exists` | 1.1, 4.1, 4.2 |
| REQ-2 | Guided and direct read-only operations resolve effective configuration in source and installed layouts. | `/skalary-config` plus direct `show`, `validate`, and `diff` routes report effective values, source/default/precedence, consumers, and unsupported prerequisites without mutation; host-equivalent complex choices include context, example, benefits, pros/cons, effort, and complexity. `test:SkalaryConfig.ReadOnly` | 1.2, 4.2 |
| REQ-3 | Every mutation is previewed as one category-scoped secret-redacted proposal before one Apply/Cancel decision. | `bootstrap`, `edit`, and per-key `reset` show the complete intended canonical diff, synchronizers, validators, risks, and transient source digest; Cancel is byte-clean; Apply refuses a changed digest and cannot widen category or accept an arbitrary target path. `test:SkalaryConfig.Preview` `test:SkalaryConfig.Mutation` | 1.2, 2.1, 3.2, 4.2 |
| REQ-4 | Routine project configuration composes existing subsystem formats and writers. | Autopilot, local review standards, terminal approvals, eval credential targets, and note scaffolds support the applicable show/bootstrap/edit/validate/diff/apply/reset routes; missing optional files are created only when selected; unknown and unrelated fields/content survive. `test:SkalaryConfig.Autopilot` `test:SkalaryConfig.Categories` | 2.1, 3.1, 4.2 |
| REQ-5 | Model routing is one complete first-class configuration category. | The façade exposes all six aliases, CLI/VS Code bindings, Routine/Standard/Deep/Independent primary/fallback/effort assignments, autopilot default, CR/DR routing, and Waza executor/judge assignments from `tools/model-allowlist.psd1`; Apply runs existing model/distribution synchronization and focused checks; invalid combinations fail before write. Shipped/reset context is `default`, while `long_context` requires a cost-warned advanced opt-in. `test:SkalaryConfig.Models` `test:SkalaryConfig.ModelSynchronization` | 2.2, 4.2 |
| REQ-6 | Maintainer-only configuration is clearly separated and remains subsystem-owned. | Plugin manifests, eval specs/pins, allowlists, toolchains, and repository policy are labeled advanced; the façade delegates to existing direct scripts and validators; installed-consumer mode reports unavailable maintainer prerequisites rather than assuming repository source. `test:SkalaryConfig.Categories` `test:SkalaryConfig.ConsumerInstall` | 3.1, 4.1, 4.2 |
| REQ-7 | Retained safety boundaries are enforced before any write. | Credential values never enter prompts, output, diffs, or files; executable autopilot settings require an extra warning; mutating or secret-bearing auto-approval, workflows, generated/dogfood/catalog writes, plans/runtime state, receipts, retirement history, linked/escaped paths, and architecture lock promotion are refused. `test:SkalaryConfig.Safety` | 1.2, 2.1, 2.2, 3.1, 3.2, 4.2 |
| REQ-8 | Apply runs required synchronization and focused validation and fails visibly without pretending to roll back. | Each category has a closed canonical-write → existing synchronizer → focused-validator sequence; success reports the final diff; write, sync, or validation failure returns non-success, leaves the actual Git diff, and prints the exact direct recovery command; no journal, backup, retry service, or rollback claim exists. `test:SkalaryConfig.Failures` | 2.1, 2.2, 3.2, 4.2 |
| REQ-9 | The façade is independently installable and removable without changing subsystem semantics. | Plugin source, manifest, registry, marketplace, dogfood, README, operator guide, and configuration design note converge; consumer fixtures prove the installed skill works with only declared payloads; uninstall removes the façade while direct configuration paths remain. `test:SkalaryConfig.Distribution` `test:SkalaryConfig.ConsumerInstall` `file:docs/design-notes/architecture/skalary-config.design.md#exists` `review:cr` | 1.1, 4.1, 4.2 |
| REQ-10 | Autopilot secret setup is explicit, external to the agent session, and validated before readiness is claimed. | Based on the effective `copilotAuth`, `gitProvider`, and `gitAuth`, the skill prints official GitHub fine-grained PAT/OAuth or ADO acquisition links, required permissions, placeholder-only Credential Manager/login commands, and a separate-shell handoff. After the operator selects Ready to validate, an installed secret-safe wrapper composes the existing credential reader and `validate-auth.ps1`; it reports only availability/capabilities, fails with exact remediation, and never places a token in prompts, command arguments, logs, diffs, or output. Mocked fixtures cover each supported auth/provider path, already-valid skip, failed probes, and redaction. `test:SkalaryConfig.AutopilotAuth` | 2.1, 4.2 |
