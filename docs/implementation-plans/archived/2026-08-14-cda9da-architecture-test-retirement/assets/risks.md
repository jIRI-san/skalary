# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | A tombstone from one catalog deletes a same-named plugin installed from another source, or raw source identity leaks credentials. | Medium | High | Use one versioned credential-free source identity; foreign/ambiguous legacy receipts are never mutated and sentinel secrets must be absent from all state/output. | 2.1, 2.3 |
| RISK-2 | A modified file preserved during cleanup is deleted on replay or loses destination ownership. | Medium | High | Keep the existing degraded receipt, persist separate residue evidence, make replay metadata-only, and require explicit shared-engine force removal. | 2.1, 2.2, 2.3 |
| RISK-3 | Crash, hard kill, hostile journal, or mixed-version operation leaves half-removed payload, authority, journal, or backups. | Medium | High | Treat journals as untrusted; bind plugin/source/pre-state; recover under lock; use deterministic fault seams plus one hard-kill; permit retry only after exact recovery. | 2.2, 2.3, 3.3 |
| RISK-4 | Tombstone/source changes are not atomic, or removing explicit `arch:` extraction makes mixed markers false-green. | Medium | High | Land the real tombstone with source deletion; history-gate permanence; tokenize every marker occurrence; prove paired red fixtures. | 1.3, 3.1, 3.3 |
| RISK-5 | Removing executable enforcement weakens human-owned authority or invites a false claim that Git metadata proves human approval. | Medium | High | Keep one canonical digest plus always-on integrity sweep; state human promotion as reviewer-enforced policy and never infer trustworthy identity from local author metadata. | 1.1, 1.2 |
| RISK-6 | Shared deletion/schema edits leave active contradictions, stale bundles, generated catalogs, or suite metadata. | High | High | Decouple/preserve architecture-notes before deletion; regenerate each owning surface in-step; finish with exact discovered-test and drift checks. | 1.1, 1.2, 1.3, 3.1, 3.2, 3.3 |
| RISK-7 | Cleanup scans growing history or rewrites historical evidence. | Medium | Medium | Scan only explicit active roots and verify a bounded pre-change path/hash manifest for the actual historical corpus. | 1.2, 3.2, 3.3 |
| RISK-8 | Automatic cleanup blocks unrelated work, exceeds the existing suite budget, or cannot be undone after release. | Medium | High | Preview before apply; propagate rollback-complete failures; index metadata/no residue rehash; cap subprocesses at four; use existing platform ceilings; retain recovery metadata/runbook. | 1.3, 2.1, 2.2, 2.3, 3.2, 3.3 |
