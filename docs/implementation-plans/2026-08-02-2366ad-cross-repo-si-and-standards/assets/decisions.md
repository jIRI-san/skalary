# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- **Split harvest from proposal.** Consumer-side free-text collection gets a narrow write scope and emits a typed artifact; proposal runs in an upstream-rooted workspace under upstream rules.
- **Extend `1936cb`; do not create a parallel SI store.** The interchange artifact is a bounded, JCS content-addressed projection of its immutable run and resolver receipt. SI state, dispositions, retention, repair, trusted sync, exact-head checks, and operator-only merge remain owned by `1936cb`.
- **Always produce the projection.** Same-repo and cross-repo runs use one derivation path; imported projection identity and terminal outcomes are recorded in existing SI state.
- **Large proposals become plans.** Rejected: a new free-form autopilot mode for `/si`. Large changes run `/cip` in the upstream checkout and use normal plan/autopilot controls.
- **Treat cross-repo evidence as a claim.** It cannot be verified against absent consumer records, so upstream re-judgment and promotion criteria remain required.
- **Transport uses a disposable upstream checkout with no harvest-time push.** Target identity comes only from a verified self-improvement installation receipt; the mapping fallback is removed. All mutation stays under one machine-owned OS cache root. A sanitized Git wrapper uses immutable cache generations or a 120-second full-clone fallback, caps fetch at 60 seconds, disables executable Git surfaces, and owns locks, reclaim, quarantine, inventory, and cleanup.
- **Target and source identities are distinct.** The verified installation receipt identifies the upstream target; a credential-stripped consumer remote hash identifies recurrence source. A local-path hash may correlate a run but never establishes either authority.
- **Evidence is bounded and never declassified into a proposal.** Projection is capped at 64 KiB and each excerpt at 4 KiB. Every value is validated, redacted, and untrusted. The earlier disclosure exception is removed: proposal diffs may contain only evidence re-derived from upstream.
- **Harvest confinement is script-owned.** The projection writer derives one exact SI run root, compares before/after bytes including ignored files, rejects every other mutation/reparse, and emits a content-addressed scope receipt. Extending the Git proposal gate to ignored state is rejected as the wrong abstraction.
- **Handoff has one closed recovery contract.** Typed reason codes, exits, retryability, cleanup state, manual carry, supersession, startup reclaim, and terminal publication identity live in a bounded result schema and operator runbook. A newly authored plan is not terminal until durably published.
- **Publication reuses trusted sync.** Credentials stay outside author/reviewer agents; `1936cb` validates the exact pushed head and operator completion rechecks the live PR OID. Building another credential broker is rejected.
- **Promotion eligibility is snapshot-derived, not a second index.** Bounded projection/fingerprint records persist in existing SI authority. Recurrence scans immutable snapshot-bound pages with digest memoization and maximum-history tests. A correlated SI decision receipt binds the fingerprint, corroboration digest, operator selection, and spawned `/cip` plan; only that plan can change authority.
- **Depend on and extend `79cfe1`.** Its concern registry/schema/template and `Sync-ReviewConcerns.ps1` remain authoring authority for all 14 agents and now generate the runtime standards inventory in the same atomic graph. `Sync-PluginScripts.ps1` still bundles the shared resolver and schema closure; it does not author standards Markdown.
- **Repo-specific standards live in `docs/review-standards.md`.** They are consumer-authored and never overwritten by plugin update. Ledger categories remain append-only evidence; they cannot safely host standards because the ledger writer canonically rewrites parseable entries.
- **Local standards extend by default under trusted-base authority.** Generic rows declare `locked` or `overrideable`; only active overrideable ids accept replace/suppress with rationale. A policy-changing branch is reviewed under the previous trusted-base policy, so it cannot exempt itself.
- **Rule IDs are permanent and capacity is partitioned.** Generic `STD-<CONCERN>-NNN` and local `LOCAL-<CONCERN>-NNN` ids are never renamed/reused; semantic replacement leaves tombstones. Generic inventory may use 96 rules and local standards reserve 32. Promotion records immutable local-to-generic mapping.
- **The resolver admits bounded per-review authority.** Each source is capped at 128 KiB, combined rule/rationale at 1,536 bytes, every concern for every review type must retain a rule, and each concern dispatch is capped at 24 rules/48 KiB/12K estimated tokens with a 5-second resolver deadline; the frozen generation is capped at 336 KiB. Admission failure writes a replayable bounded attempt receipt before Freeze.
- **Review-run v2 freezes standards bytes.** A versioned successor publishes content-addressed standards generations, per-task digests, overrides, and typed finding rule ids through manifest-last authority. V1 readers remain for history; vocabulary, limits, maxima, corpus, goldens, capability, and interoperability move together. Architecture contracts outrank agent mechanics, which outrank frozen standards. Ledger entries are promotion evidence only.
- **Standards adoption is atomic per plugin.** A mechanical migration baseline first binds all 14 pre-edit agent blobs and extracts criteria. Existing agent prose remains bootstrap authority until each plugin atomically lands complete mapping, generated standards, orchestrator switch, seven-agent extraction, installed closure, and structural proof. The baseline is deleted after both migrations verify.
- **First-generation bootstrap is frozen from the trusted base.** The adopting branch binds base OID and generated-agent digests and derives standards-equivalent authority from those bytes once. Later policy-changing branches use the merged inventory; first adoption and self-exemption are separate fixtures.
- **Review authoring runs in an isolated upstream-rooted container.** Only the disposable checkout is mounted; consumer tree and user profiles are absent. Root/instruction attestation failure becomes retryable `handoff-required` rather than continuing in the consumer session.
- **Source recurrence is a claim, not verified identity.** Distinct replay-bound consumer hashes make a candidate eligible for human review; they do not auto-promote or claim independent verification.
- **Evidence attendance is registry-owned.** A typed registry gives each id one runner/review owner and allows matrix assertions under that owner; aggregate gates are not forced into a one-assertion fiction.
- **Standards admission belongs to review-run v2.** One engine-owned admission/generation lifecycle covers schema, reasons, exits, replay, readers, publication, and cleanup instead of adding a parallel resolver authority.
- **Review-run v2 keeps existing byte ceilings.** Standards bytes live in one external manifest role; tasks reference digests, findings carry at most four rule ids and 3,584-byte bodies, and exact maximum arithmetic/goldens prove the 2 MiB input and existing view budgets.
- **Optional local standards are runtime inputs, not scaffolds.** Plugin and registry schemas gain `optionalInputs`; installation never creates or owns `docs/review-standards.md`.
- **Operational limits are registered, not prose-only.** Owner descriptors carry SI 64/4 KiB, standards 128 KiB/96+32/2 KiB, per-concern 32/48 KiB, total 336 KiB, fetch 60 seconds, and clone 120 seconds. Process-heavy Git/install matrices run in Slow with measured budget rows.
- **Phase budget is 12 points.** Phase 2 is four `L` steps whose checkout, isolation, import, publication, and cleanup invariants form one recoverable transport boundary. Splitting the phase would permit a crosscheck between incomplete authority transitions; the higher advisory cap is explicit rather than understating the work.
- **Cross-repo transport is an architecture boundary.** Add `ARCH-Si-Cross-Repo-Transport`, cross-reference install confinement, update review-run authority for v2, regenerate the human architecture doc, and retire both explorations into self-improvement/review-reporting notes with index and Cluster F/G status updates.
- **Manual step execution.** This plan introduces trust and persistence contracts, so `/ci` defaults to manual step scope. It adds no third-party packages.
