# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | Cross-repo work forks a second SI lifecycle and diverges from `1936cb` state, retention, repair, and trusted synchronization. | High | High | Phase 0 verifies dependency contracts; projection is derived and non-authoritative; all transitions, dispositions, archive/prune, sync, and completion extend the existing SI owner. | 0.1, 1.1, 1.2, 2.3 |
| RISK-2 | Harvested model/operator text carries prompt injection or consumer secrets into upstream authority. | High | High | JCS-validated typed projection, 64 KiB/4 KiB bounds, redaction, hostile-content fixtures, absolute proposal-diff nondisclosure, trusted-base enforcement, and mandatory `/cip` gate for authority changes. | 1.1, 1.2, 2.2, 2.3 |
| RISK-3 | Consumer evidence is unverifiable upstream, replayed as corroboration, or requires an unbounded history scan. | High | High | Bind immutable source receipts, separate target/source identities, persist bounded fingerprints in existing SI state, page under a snapshot digest, memoize derived results, test maximum history, and bind approval to a correlated plan. | 1.2, 2.3, 5.1 |
| RISK-4 | A poisoned cache, Git execution surface, reparse point, stale checkout, or mismatched remote roots proposal execution in attacker-controlled state or leaks capacity. | Medium | High | Verified receipt-only target, machine-owned root, sanitized Git wrapper, disposable checkout, immutable cache generations, full-clone fallback, locks, atomic promotion, reclaim/quarantine/inventory, 60s fetch/120s clone limits, and crash/escape tests. | 2.1, 2.2 |
| RISK-5 | Proposal credentials become visible to harvest, author, reviewer, Git helper, or checkout files. | Medium | High | Harvest never pushes; sanitized Git disables credential execution surfaces; trusted sync/operator completion own publication; canaries cover all process environments and files. | 2.1, 2.3, 2.4 |
| RISK-6 | A crash between transfer, proposal, plan publication, PR creation, disposition, and cleanup produces duplicate, lost, or ambiguous outcomes. | Medium | High | Closed handoff schema/reason codes/exits, stable correlation, idempotent replay, startup reclaim, explicit manual-carry runbook, durable plan publication before cleanup, and exact terminal receipts. | 1.2, 2.2, 2.3 |
| RISK-7 | A reviewed branch changes local standards to exempt itself, suppresses a locked rule, or fills all generic/local capacity. | Medium | High | Trusted-base self-review, locked/overrideable policy, permanent STD/LOCAL namespaces and tombstones, 96/32 reserved capacity, migration diagnostics, bounded admission status, and asymmetric review-type tests. | 3.2, 3.3, 4.1, 4.2 |
| RISK-8 | Mutable standards paths or free-text citations make published review authority unverifiable or break historical v1 artifacts. | High | High | Review-run v2 publishes manifest-bound standards bytes/digests/overrides and typed rule ids; retain v1 readers; update shared vocabulary, maxima, corpus, goldens, and interoperability fixtures atomically. | 4.1, 4.2, 4.3 |
| RISK-9 | Extracting criteria from 14 agents drops rules, changes CR/DR meaning, or leaves temporary dual authority. | Medium | High | Bind exact pre-edit blobs, mechanically extract and prove complete mapping, switch each plugin atomically with its installed closure, mutation-test omission/deletion, and retire the migration baseline after both adoptions. | 3.1, 3.2, 4.2, 4.3 |

| RISK-11 | Script/schema edits leave broken intermediate installed/architecture surfaces, stale generated catalogs, or evidence IDs that never execute. | High | High | Update each behavior step's complete closure, exact-once/no-skip attendance-gate every test id, register limits/tier/runtime ownership, make final convergence detect-only, and generate catalogs only after drift is zero. | 1.3, 2.4, 3.3, 4.2, 4.3, 5.2, 6.1 |
