# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | A script classified as unused has an unsupported external caller not represented in the repository. | Low | Medium | Remove only commands outside current manifests, skills, operator guidance, and supported public contracts; if an active documented consumer is found, stop and retain that command rather than adding compatibility indirection. | 1.1 |
| RISK-2 | Deleting historical fixture bytes weakens proof that retired architecture-test runtime cannot return. | Low | Medium | Keep one explicit active-root absence test covering the retired paths and symbols; rely on Git history for former bytes. Stop if a current test consumes fixture semantics beyond historical byte identity. | 1.2 |
| RISK-3 | Removing the human-doc chain accidentally removes direct validation of the remaining JSON architecture contract. | Medium | High | Separate compatibility generation/digest code from `Test-ArchContract.ps1`; retain focused JSON validation tests. Stop if a proposed deletion makes the contract unreadable or unvalidated rather than merely removing its generated Markdown mirror. | 2.1, 2.2 |
| RISK-4 | Module reduction changes behavior hidden in private orchestration or recovery paths. | Medium | High | Trace each candidate branch to current callers and focused tests, make one module-sized cut at a time, and run its smallest complete behavior suite before continuing. Stop and restore the local candidate when equivalence cannot be demonstrated. | 3.1, 3.2, 3.3 |
| RISK-5 | Structural metrics are gamed through dense formatting, comment deletion, or code relocation. | Low | Medium | Count token-bearing lines and private functions, inspect readability in final CR, prohibit new production modules, and require deletion rationale for each removed path. | 3.1, 3.2, 3.3, 4.2 |
| RISK-6 | Canonical deletions leave stale plugin, registry, marketplace, or `.github` copies. | Medium | Medium | Change manifests/canonical sources first, run existing generators in ownership order, then use detect-only and consumer-install checks. | 2.1, 4.1, 4.2 |
| RISK-7 | Cleanup expands into removal of supported modes or safeguards. | Low | High | Hold the explicit non-goals and exact export sets; any proposed capability deletion requires a new operator decision and is not justified by line-count targets. | 3.1, 3.2, 3.3 |
