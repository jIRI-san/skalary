# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- **Ship one canonically named plugin and skill.** `work-hierarchy-sync` is the product/plugin/skill/config/store slug; PowerShell uses approved `*-WorkHierarchySync*` nouns. `/cep` and `/cip` remain side-effect free. Canonical scripts reuse bundled `PlanState.psm1`; `Sync-PluginScripts.ps1` owns the parser/schema/tool sidecar closure and version coupling.
- **GitHub first, provider-neutral core.** V1 targets organization-owned GitHub Projects v2 and repository issues. Core records/actions/outcomes contain no GitHub assumptions; `work-hierarchy-sync.design.md` owns the port until a second real provider and two consumers justify architecture-tier promotion. Live Azure DevOps is out of scope.
- **Map epic to plan only.** One configured repository holds one parent epic issue and one child-plan sub-issue per plan. Phases and steps remain managed body content. One epic plus 100 child plans is the closed v1 local bound.
- **Require an existing product project.** Product synchronization resolves a configured organization Project v2 and never creates that container. Disposable project/repository creation exists only inside the pre-journaled live-smoke harness.
- **Separate target authority from sync state.** Consumer-owned `.github/work-hierarchy-sync.json` is the only target/status authority and is registry-declared through new `consumerFiles[]` semantics. This plan depends on and extends `25aa23`'s sole `Resolve-EpicAssetPath` owner with `WorkHierarchySync`; epic-less and re-parented authority fails loud.
- **Treat remote markers as untrusted hints.** Explicit prelinks are validated. A unique marker may propose one immutable issue node, but the operator must confirm adoption before it becomes trusted mapping state; automatic marker adoption is rejected.
- **Keep local content authoritative without owning the whole body.** Synchronization owns the exact title plus one v1 delimited region. Outside content is preserved; exact typed fingerprints drive three-way conflict decisions. Raw remote text remains in deterministic code and never enters an instruction-bearing model context.
- **Project progress, not issue closure.** Local progress maps to configured Planned/In progress/Done options. Issues remain open. Dependencies are managed body links. Removed/re-parented plans conflict; v1 never auto-deletes, closes, detaches, or reparents.
- **Approve one capability, not a prose summary.** Dry run publishes a bounded action digest bound to actor, host, immutable targets, source/config/store digests, nonce, and expiry. Owner-only ignored host state keeps approval custody. Normal product runs confirm resolved IDs once; smoke confirms the namespace before creation and the exact created targets before product mutation.
- **Journal before non-idempotent mutation.** Every write intent is durable first. Reads have bounded retry; mutations retry only after remote reconciliation proves replay safety. Unknown outcomes stop in a closed partial/recovery state rather than guessing.
- **Use bounded append records plus terminal snapshots.** Two 2 KiB records per action keep the 403-action maximum below a 2 MiB journal. Completed runs compact action history after verified snapshot/receipt; 20 terminal pairs plus one maximal pinned recovery run fit the 96 MiB aggregate cap. Unsafe pruning refuses the next run.
- **Use forward recovery, not compensating deletes.** Verified remote writes checkpoint and resume; product apply never deletes created issues to imitate rollback. Closed states/exits give the operator exact reapproval, resume, conflict, auth, budget, and residue guidance.
- **Keep broad credentials out of autonomous runtimes.** The operator chose active ambient `gh` auth; therefore product apply runs manually on the host. Preflight resolves immutable targets, local worktrees share a lock, and all clones contend on an atomically created fixed Git ref before mutation. Tokens are never persisted or printed.
- **Make live proof independently hosted.** Repo-root admin tooling records UUID/names, creates/deletes only journal-owned resources, and temporarily places ambient auth into an environment-protected Actions secret without output. A full-SHA-pinned exact-commit workflow installs generated-registry bytes; only an authenticated re-fetching verifier can publish final evidence.
- **Keep tests affordable and adversarial.** Fast owns pure behavior; measured Slow owns process, lock, fault, retry/wait, maximum-envelope, and installed-consumer matrices with injectable time. Independent seam/evidence maps bind every write, fault, marker, test, eval, tier, platform, and runtime receipt; seeded red controls prevent self-proof.
- **Leave every phase installable.** Every vertical phase updates tests/evals, plugin manifest, generated dogfood/registry/marketplace/catalog, suite maps, and named design notes before its checkpoint. A late horizontal packaging phase is rejected.
- **Reuse policy without runtime coupling.** The GitHub adapter does not import the PR-comment plugin. Machine policy fixtures enforce intentional parity for auth, response validation, rate-limit classification, pagination, and token-safe diagnostics.
- **Use manual execution with no new packages.** Human gates authorize the organization namespace and exact created targets; deterministic host/hosted scripts perform mutation, verification, and cleanup. PowerShell 7, `gh`, JSON Schema, Pester, and existing tools are sufficient.
- **Approve the program shape.** [program-design.md](decisions/program-design.md) defines ownership, data flow, fingerprints, admission, journaling, locking, and publication.
