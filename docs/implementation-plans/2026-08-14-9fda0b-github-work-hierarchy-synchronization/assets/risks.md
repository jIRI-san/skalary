# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | Active `gh` auth lacks organization project or disposable-resource permission, or the selected identity is broader/different than the approved target. | High | High | Preflight resolves actor and immutable target IDs with zero writes; the human gates confirm namespace then created targets; every request is allowlist-bound. Seed wrong-actor/target/scope failures in `test:WorkHierarchy.Phase2.GitHubAdmissionAndTimeouts`. | 2.1, 4.1, 4.2, 4.3 |
| RISK-2 | A stale mapping or forged/duplicate hidden marker adopts the wrong issue and overwrites operator content. | Medium | High | Treat markers as hints; require explicit immutable-node adoption confirmation, target binding, delimiter validation, and last-synced fingerprints. Seed forged/duplicate/wrong-owner and confirmation-refusal cases in `test:WorkHierarchy.Phase2.AdoptionAndConflict`. | 2.2, 3.1, 4.3, 5.1 |
| RISK-3 | Dry-run and apply diverge after concurrent remote edits or local/config/store changes. | Medium | High | Bind all inputs, acquire local and atomic remote-ref locks, re-admit before writes, and compare expected pre-state immediately before each action. Seed each drift/race in `test:WorkHierarchy.Phase3.EnabledApplyAndRecovery`. | 1.2, 2.2, 3.2 |
| RISK-4 | Store corruption, path traversal, reparse points, cross-branch/clone updates, interruption, or stale locks lose stable identity. | Medium | High | Use the canonical epic resolver, schemas, append records/manifest-last snapshots, local never-unlinked lock, remote-ref exclusion, pinned recovery, and explicit break-glass. Seed each boundary in `test:WorkHierarchy.Phase3.LockAndFaultCoverage`. | 1.2, 3.1, 3.2 |
| RISK-5 | GitHub changes API response shape, permissions, field semantics, cost reporting, or rate behavior. | Medium | High | Isolate one adapter, validate required fields, reject unknown/over-budget responses, maintain transport-policy parity fixtures, and require live proof. Seed missing/changed fields and status codes in `test:WorkHierarchy.Phase2.GitHubAdmissionAndTimeouts`. | 2.1, 4.2, 5.1 |
| RISK-6 | Secondary limits or a lost non-idempotent mutation response create duplicate issues/items on retry. | Medium | High | Classify operations, journal intent first, reconcile by immutable IDs/approved markers/membership under both locks, and retry only proven replay-safe actions within reserved caps. Seed lost-response at every boundary in `test:WorkHierarchy.Phase3.EnabledApplyAndRecovery`. | 2.1, 3.2, 3.3 |
| RISK-7 | Installed execution lacks parser, schema, descriptor, template, config metadata, or epic-store assets available in this repo. | Medium | High | Generalize the managed bundler sidecar table, bundle parser/schema/tool closure, add registry `consumerFiles[]`, depend on `25aa23` resolver ownership, and process-test clean consumers. Seed missing declaration/sidecar/resolver/fallback failures in `test:WorkHierarchy.Phase1.InstalledOwnership`. | 1.1, 1.2, 1.3 |
| RISK-8 | Partial remote mutation cannot roll back atomically and leaves mixed state or an operator without a safe next action. | Medium | High | Closed partial/blocked states retain bounded recovery identity, residual digest, blockers, and matrix-selected status/resume/reapproval guidance; resume forward and never compensate by deletion. Seed every transition in `test:WorkHierarchy.Phase3.StateExitRetentionAndDiagnostics`. | 3.1, 3.2 |
| RISK-9 | Plugin payload, dogfood, registry, marketplace, suite maps, eval inventory, or docs drift between vertical phases. | Medium | Medium | Each phase includes canonical generation/docs/tests; seeded stale-copy, omitted-marker, analyzer, and package drift must fail the phase evidence/distribution tests. | 1.3, 2.3, 3.3, 4.2, 5.1, 5.2 |
| RISK-10 | Live-smoke creation succeeds before resource identity is recorded, or cleanup fails and leaves organization resources. | Low | High | Publish intended UUID/names before create, reconcile returned or lost identities, update cleanup-pending generations, delete only journal-owned IDs, and block on exact residue URLs. Seed lost-create and cleanup failures in `test:WorkHierarchy.Phase5.LiveHostedAuthorityAndCleanup`. | 4.2, 5.1 |
| RISK-11 | Raw remote body or diagnostics reach an instruction-bearing model context or committed receipt with secrets. | Low | High | Parse/diff remote strings only in deterministic PowerShell; expose typed enums, opaque IDs, digests, and directive-neutral `UNTRUSTED_REMOTE_DATA`; central fail-closed redaction covers every publication path while the pre-write schema-minimal recovery record contains no free text. Seed every remote field/output path in `test:WorkHierarchy.Phase3.StateExitRetentionAndDiagnostics`. | 2.1, 2.2, 3.1, 5.1 |
