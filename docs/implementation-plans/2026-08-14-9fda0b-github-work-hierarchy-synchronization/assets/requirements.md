# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | A pure deterministic projector converts a resolved local epic and child plan assets into the desired GitHub parent/child issue hierarchy, dependency links, phases, purpose, and acceptance content. | Golden tests prove stable ordering and byte-identical projection for unchanged local inputs. `test:WorkHierarchy.Projection` | 1.1, 3.1, 3.2 |
| REQ-2 | A read-only dry run compares projected and current GitHub state and renders the exact ordered action set before any write; apply requires explicit operator confirmation of that action set. | Mocked tests prove zero writes during dry run and no writes when confirmation is declined or projection/state changes. `test:WorkHierarchy.DryRunAndConfirmation` | 1.2, 2.2, 3.1, 3.2 |
| REQ-3 | Stable epic/plan IDs map to remote IDs in one simple local mapping file, and tool-owned body content is confined to marker-managed sections. | Mapping/marker tests prove stable reuse, explicit adoption, no duplicate creation, and preservation of unmanaged content. `test:WorkHierarchy.MappingAndMarkers` | 1.2, 2.1, 2.2, 3.1, 3.2 |
| REQ-4 | Synchronization refuses ambiguous mappings, unmanaged changes inside managed sections, missing/replaced remote targets, or stale pre-apply state; a successful immediate second run performs no mutations. | Conflict and convergence tests cover refuse, partial failure, resume by fresh dry run, and second-run no-op. `test:WorkHierarchy.ConflictAndNoOp` | 2.1, 2.2, 3.1, 3.2 |
| REQ-5 | One narrow provider interface separates projection/actions from transport; v1 implements GitHub only through a small `gh` adapter. Azure DevOps remains a documented seam with no implementation or capability protocol. | Interface and adapter tests prove the core uses one boundary and no Azure DevOps product code is shipped. `test:WorkHierarchy.GitHubAdapter` | 1.1, 3.1, 3.2 |
| REQ-6 | Focused mocked tests are required; an operator-owned real GitHub smoke is optional and never required for deterministic validation. Existing plugin sync/registry/catalog paths distribute the feature. | Mocked installed-consumer and generated-drift checks pass without live credentials. `test:WorkHierarchy.ConsumerInstall` `test:bundle-no-drift` `test:dogfood-no-drift` | 3.1, 3.2 |
