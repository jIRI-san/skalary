| REQ-1 | `/ci` executes the complete implementation plan as ordered vertical phases: every completed phase is an inspectable usable increment, and neither interactive nor autonomous execution treats the MVP phase as plan completion while later steps remain. | Interactive progression reparses state and selects the next phase after MVP: `test:VerticalLoop.InteractiveCompletePlanProgression` (owner 1.2). | REQ-2 | Phase close composes the `57cc2c` intent/domain/design context reads, re-reads all five intent sections, computes their runtime digest, and derives applicable requirements plus marker ownership from completed steps. | The upstream current-value confirmation flag is prerequisite but not the digest producer. On first interactive close, `/ci` obtains confirmation and appends an interactive-only digest record; headless bootstrap persists a blocker and exits `42`. Missing/TBD/unconfirmed/stale digest blocks evidence-required plans and warns only for non-opted legacy plans. Bootstrap, stale digest, unattended refusal, pre-check, blocked-check, atomic commit, resume, and bounded diagnostics are proven by `test:VerticalLoop.InteractivePhaseCloseSeams` (owner 1.2). | 1.2 |
| REQ-3 | Implementation choices and uncertainty use one versioned typed Capture grammar parsed and reduced only by `CheckpointGate.ps1`; accepted free-text bodies are inert untrusted data and never appear in control outputs or control execution. | Closed transitions, blocker reuse after replacement, idempotent replay, stale/conflicting/cyclic link rejection, body-free control objects, and fixed untrusted-data framing in every reader are proven by `test:CheckpointGate.TypedRecordTransitionMatrix` (owner 1.2). Existing untyped entries remain display/harvest compatible but non-authoritative. | 1.2 |
| REQ-4 | High-impact uncertainty, unresolved intent drift, and concurrent review-cycle stops are durable and distinguishable in interactive, host, container, and sandbox execution; ordinary reversible choices may continue after capture. | `CheckpointGate` consumes the read-only `ReviewCycleGate` verdict, preserves all pending IDs, and emits one stop-reason token. A valid unresolved record with `resolution: blocked` yields verdict `operator-decision`/exit `42`; invalid grammar/link/cycle/capacity state yields verdict `blocked`/exit `46` with zero mutation; persistence/push failure exits `47`; `allow` exits `0`. Preflight rejects collisions with the complete installed inventory including `42-45`, `124`, `143`, and `863d97`. Container propagates exact exits; sandbox bootstrap writes a cleaned, bounded, validated session marker containing only `42`, `46`, or `47`, and the host returns it. Fresh-clone resume, stale sandbox marker, both-pending order, and mode propagation are proven by `test:VerticalLoop.ExecutionModeInterruptionMatrix` and `test:CheckpointGate.OperatorResolutionAuthority` (owner 2.2). | 2.1, 2.2 |
| REQ-5 | The record and checkpoint path is fail-closed, serialized, bounded, layout-confined, credential-safe, interruption-safe, and backward-compatible. | The writer uses an OS-released lock with a five-second bounded wait, same-directory atomic replacement/read-back, and rejects any symlink/junction/reparse component for Capture, lock, temp, or replacement paths. It extracts `Find-HighConfidenceSecret` into shared `SecretGuard.psm1`, bundled with CI/CIP and review consumers, and fails unavailable/credential-shaped writes before mutation. Every display/harvest path also guards typed, legacy, and manually altered bodies before emission, returns a blocker on a match, reports only type/location, and prohibits raw CI/autopilot reads. Ordinary typed records use 56/64 per-phase and 224/256 per-plan slots; reserved slots are blocker/resolution-only. Hard capacity returns verdict `blocked` with a bounded remedy and never drops unresolved blockers. Concurrency, killed-holder, limit, directive, write/read secret, legacy/current layout, and uncommitted-resume seams are proven by `test:WorkflowNote.AtomicTypedCaptureSecurity` and `test:WorkflowNote.TypedCaptureLimitsAndCompatibility` (owner 1.2). | 1.2, 3.1 |
| REQ-6 | Source, CI and CIP bundles, dogfood, manifests, catalogs, focused-test inventory, structural-eval registry, tests, and governing notes describe one synchronized contract. | Step 1.1 updates preflight docs/copies; 1.2 updates plan-workflow/copilot-customizations plus CI/CIP writer/gate copies and mandatory eval IDs; 2.1 updates autopilot source/dogfood/container/sandbox paths and autopilot notes. Every payload-changing commit runs required sync/version/catalog generation. Aggregate positive and one-copy mutation proof is `test:VerticalLoop.DistributionAndDocumentation` (owner 3.1); deterministic doc markers and exactly-once required-eval execution are `test:VerticalLoop.StructuralEvalRegistration` (owner 3.2), `file:docs/design-notes/architecture/plan-workflow.design.md#contains:CheckpointGate`, `file:docs/design-notes/architecture/autopilot-execution.design.md#contains:next-phase`, `file:docs/design-notes/architecture/autopilot-skill.design.md#contains:next-phase`, and `file:docs/design-notes/project/copilot-customizations.design.md#contains:typed Capture`. `review:cr` remains qualitative final evidence. | 1.1, 1.2, 2.1, 3.1, 3.2 |
| REQ-7 | `CheckpointGate` becomes the sole caller of `863d97` phase execution/publication through an atomic phased migration; prompts and agents add no executor, receipt writer, or evidence-v1 fallback. | Step 1.1 admits exactly the `863d97` predecessor CI/autopilot caller set and rejects additions. Step 1.2 reroutes interactive `/ci` and proves interactive batching with `test:VerticalLoop.InteractiveFocusedPhaseEvidence` (owner 1.2). Step 2.1 reroutes autopilot and atomically enables global residual-caller rejection; the gate unions and ordinal-deduplicates owned markers, invokes focused tests once, evaluates non-test markers once, and publishes once, proven by `test:VerticalLoop.FocusedPhaseEvidenceBatch` (owner 2.1). | 1.2, 2.1 |
| REQ-8 | Plan finalization runs the complete configured build/test gate once per finalization attempt and evaluated tree state, with idempotent resume and bounded platform cost. | Phase paths invoke it zero times; green unchanged finalization invokes it once; failure or implementation-state change reruns; unchanged published-green resume does not duplicate it.
