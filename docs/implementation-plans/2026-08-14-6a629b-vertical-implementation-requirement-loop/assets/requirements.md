# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Before phase mutation, `/ci` uses existing plan metadata/state to verify dependencies, step prerequisites, confirmed intent availability, and the requirements applicable to the phase. | No-mutation fixtures cover ready, blocked, missing, ambiguous, and stale-input states through the current parser. `test:VerticalLoop.PhaseAdmission` | 1.1, 3.1, 3.2 |
| REQ-2 | At phase close, `/ci` rereads confirmed intent and uses the existing evidence crosscheck to report each applicable requirement as passed, failed, skipped, stale, unrun, or waived according to the truthful evidence owner. | Focused crosscheck cases block unresolved non-pass results and preserve the existing receipt grammar. `test:VerticalLoop.EvidenceCrosscheck` | 1.2, 2.2, 3.2 |
| REQ-3 | Every phase records its usable increment, decisions, uncertainty, and operator disposition; high-impact uncertainty or failed evidence stops for operator action. | Checkpoint tests cover continue, revise, stop, and resume while retaining intent and evidence context. `test:VerticalLoop.OperatorCheckpoint` | 1.2, 2.1, 3.2 |
| REQ-4 | Decisions and lower-impact uncertainty are written through existing `Add-WorkflowNote` capture semantics; no new checkpoint parser, atomic capture format, or parallel log authority is added. | Capture tests prove the existing layout-resolved writer and closed kinds are used without changing its format. `test:VerticalLoop.WorkflowNoteCapture` | 2.1, 3.1, 3.2 |
| REQ-5 | Autopilot `next-phase` runs one admitted phase, performs the same phase-close checks, stops, and resumes from existing checklist progress; normal whole-plan mode continues only after the current gate passes. | Sandbox/container fixtures prove one-phase stop, interruption, resume, and no duplicate completed work. `test:VerticalLoop.AutopilotNextPhase` | 2.2, 3.1, 3.2 |
| REQ-6 | Changed `/ci` and autopilot payloads converge through existing bundling, dogfood, registry/catalog, installed-consumer, and test infrastructure. | Generated-drift and installed-consumer checks pass without another parity platform. `test:VerticalLoop.ConsumerInstall` `test:bundle-no-drift` `test:dogfood-no-drift` | 3.1, 3.2 |
