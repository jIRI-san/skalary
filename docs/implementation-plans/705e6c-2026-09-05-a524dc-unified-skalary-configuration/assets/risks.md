# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | The façade becomes a second source of truth or generic configuration framework. | Medium | High | Catalog points to subsystem authorities; use closed category-specific handlers and existing examples, writers, synchronizers, and validators; add no replacement schema/store. | 1.1, 1.2, 4.1, 4.2 |
| RISK-2 | Editing generated or dogfood files creates drift that later sync overwrites. | High | High | Classify canonical/default/generated paths; write canonical sources only; run required synchronizers before reporting success. | 1.1, 2.2, 3.1, 3.2, 4.1, 4.2 |
| RISK-3 | Secret values enter prompts, diffs, or committed files. | Medium | High | Report credential-source availability only; refuse value display/edit; secret-screen previews and output; route setup to approved external auth flows. | 1.2, 2.1, 3.1, 3.2, 4.2 |
| RISK-4 | Executable autopilot settings enable unsafe commands. | Medium | High | Reuse subsystem validation, show command effects, require an extra explicit warning, and never auto-create host-command or extension values. | 2.1, 3.2, 4.2 |
| RISK-5 | The catalog freezes stale dependency formats or exposes removed machinery. | Medium | High | Inventory only current active sources after all dependencies; test the closed category/source map; add no compatibility adapters for archived formats. | 1.1, 3.1, 4.1, 4.2 |
| RISK-6 | A broad or stale Apply partially synchronizes derived outputs. | Medium | High | Keep proposals category-bounded, bind Apply to a transient source digest, sequence canonical edit then existing synchronizers and focused checks, and surface failure without claiming rollback or success. | 1.2, 2.1, 2.2, 3.2, 4.2 |
| RISK-7 | Advanced maintainer controls overwhelm routine configuration or fail in an installed consumer. | Medium | Medium | Separate normal and advanced paths; include examples, benefits, risks, effort, and complexity; report unavailable maintainer prerequisites instead of guessing. | 3.1, 4.1, 4.2 |
| RISK-8 | A model edit changes one role source but leaves fallbacks, evals, allowlists, or dogfood copies inconsistent. | High | High | Treat model routing as one category-scoped proposal, enumerate every canonical source and consumer, run existing synchronizers, and fail visibly on any focused model-contract or consumer-install check. | 2.2, 4.2 |
| RISK-9 | The façade selects long context or an expensive model as an accidental routine default. | Medium | High | Derive valid options and defaults from current sources; keep every shipped/reset context at `default`; make `long_context` a cost-warned advanced opt-in; show relative cost and reject invalid role/fallback combinations. | 2.1, 2.2, 4.2 |
| RISK-10 | Secret setup guidance is incomplete, stale, or leaks a token while validating it. | Medium | High | Select instructions from active auth/provider settings; use official acquisition links and placeholder-only commands; require separate-shell setup; retrieve and validate internally through installed scripts; sanitize every result; test all paths with fake credentials and no live secret. | 2.1, 4.2 |
