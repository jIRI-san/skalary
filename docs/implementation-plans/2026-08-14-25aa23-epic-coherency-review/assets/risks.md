# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | Dependency `8a0644` is incomplete when implementation starts, so `/cep` cannot truthfully consume its shared fleet contract. | Medium | High | Keep the dependency marker blocking; implement no local scheduler or copied cap, and activate only after resolver-backed dependency state and the REQ-9 adapter are complete. | 2.1, 3.1 |
| RISK-2 | The proposed cut changes after its source digest is frozen, leaving a clean verdict attached to stale decomposition bytes. | Medium | High | Keep review input in stable `decomposition.rfc.md`; engine-derive its bytes and digest, start a new source generation on change, and require retained-pair/scaffold parity. | 1.2, 2.2 |
| RISK-3 | Provider throttling, typed host timeout, or malformed reviewer output silently reduces attendance while the orchestration still reports success. | Medium | High | Reuse the one typed throttle retry; publish every terminal outcome, retain degraded runs as blocked, and never claim the scheduler can interrupt a host call that does not return. | 2.1, 3.1 |
| RISK-4 | Three rounds end with unresolved decision-changing findings. | Low | High | Stop before child creation, retain all findings/dispositions, and require an explicit operator continue/stop decision; no automatic waiver. | 2.2 |
| RISK-5 | Epic text, cross-plan index records, or reviewer output contains prompt injection or suspected secrets. | Medium | High | Freeze the prior-art snapshot into the RFC, engine-scan source bytes before dispatch, generate read/search-only agents with local guards, redact suspected values, bound disposition fields, and preserve reviewer-authored trust labels. | 1.2, 2.2 |
| RISK-6 | `Get-PlanIndex.ps1` reports an unrelated malformed plan and a reviewer overstates prior-art completeness. | Medium | Medium | Persist every index error in the structured RFC with its topic impact; allow a scoped caveat but never translate an error into a complete-corpus claim. | 1.2, 3.1 |
| RISK-7 | Review runtime works in the repository but is absent, stale, or unapproved in an installed create-implementation-plan consumer. | Medium | High | Bundle the exact review script/module/schema closure into `/cep`, declare approval rules, run installed-consumer tests, synchronize dogfood/catalogs, and preserve design-review as a policy dependency rather than a runtime lookup. | 2.2, 3.2 |
| RISK-8 | Epic review support weakens plan-store confinement or mutates immutable v1 schema behavior. | Medium | High | Add a mutually exclusive `-EpicDir` path resolved through epic inventory with the same reparse/round-trip checks; keep schemas unchanged and prove existing plan/generic fixtures byte-identical. | 1.1, 1.2 |
| RISK-9 | Interruption loses round history, retained authority, or partially scaffolded children. | Medium | High | Use atomic script-owned state, retained report/receipt finalization before cleanup, fault seams at every transition, and idempotent scaffold replay with parity verification. | 1.2, 2.2 |
| RISK-10 | `79cfe1` is incomplete, so adding hand-authored epic agents creates a second concern-authoring path. | Medium | High | Add a hard dependency on `79cfe1`; extend its registry/schema/template/generator and never add unmanaged concern files. | 2.1 |
| RISK-11 | Persisted reviewer wording later steers `/cep` or `/cip` as trusted epic context. | Medium | High | Persist bounded dispositions and retained reports as reviewer-authored data, never interpolate their bodies into trusted intent/decision fields, and test planted directives and secret-shaped values directly. | 1.2, 2.2 |
| RISK-12 | A model or headless run fabricates an operator confirmation or resets review rounds by changing the RFC digest. | Medium | High | Count rounds across the operation id, bind confirmations to source digests, grant one round only from an interactive response, make headless grant mode unavailable, and state explicitly that interaction provenance is policy rather than cryptographic identity. | 1.2, 3.1 |
| RISK-13 | Concurrent `/cep` sessions race state transitions or scaffold the same children. | Medium | High | Serialize RFC/state/review/scaffold transitions through one epic lock, reject stale expected-state writes, and prove one winner plus resumable loser behavior. | 1.2, 3.1 |
| RISK-14 | Reviewer collation emits schema-invalid output, so a completed fleet has no canonical publication. | Medium | High | Keep raw outputs bounded before Publish, validate per-task references, publish no malformed manifest, retain the operation as blocked with typed diagnostics, and require a fresh UUID/round after correcting only the invalid result projection. | 2.2, 3.1 |
