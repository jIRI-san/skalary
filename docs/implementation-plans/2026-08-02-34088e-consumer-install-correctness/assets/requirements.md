# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Build one shared foreign-consumer fixture substrate whose sole materializer is the shipped production installer. It resolves the active registry, invokes real dependency/hash/confinement logic, and verifies output independently; source reads are confined to declared plugin roots and deletion is allowed only after the resolved root identity equals the indexed fixture root. | Missing, extra, duplicate, escaping, reparse-ancestor, or hash-mismatched mappings fail. Existing review/retirement fixtures migrate to this substrate or remain explicitly narrower adapters; no fixture copies source wildcards or implements a second installer. `test:ConsumerInstall.ProductionFixtureAndInventory` | 1.1, 2.1, 4.1 |
| REQ-2 | Make runtime-reference closure complete through a staged scanner migration. `tools/runtime-reference-policy.psd1` owns the closed roots, persistent exclusions, and exact refusal caps: 10,000 files, 64 MiB aggregate UTF-8 input, 100,000 references, and 256 exclusions. The plan asset records migration rationale only and is retired after zero unresolved entries. | Enumeration is one indexed traversal in the existing validation host; unsupported dynamic reads and every boundary-plus-one fail, parsed fenced examples remain first-party non-runtime data, and 1x/2x fixtures prove bounded scaling. Enforcement lands only after every violation is fixed or moved to the scanner-owned policy. `test:ConsumerInstall.RuntimeReferenceEnumeration` · `test:ConsumerInstall.RuntimeReferenceEnforcement` | 1.2, 1.3 |
| REQ-3 | Cover every active plugin through a closed owner-local probe descriptor. Schema and Test-Registry bind each direct entrypoint to the declaring plugin's own confined installed `files[].dest`, reject shell text/escaping arguments, and bind every scaffold one-to-one to a trigger and closed parameter cases. The harness runs deterministic ordinal waves of at most four processes, each capped at 30 seconds, with an allowlisted environment, isolated profiles, removed credential variables, capability preflight, network/credential/read canaries, and confined cleanup. | Required descriptors derive from active manifests; planned, launched, and terminal sets are equal with zero skips, including aggregate-interrupted queued probes recorded as `timed-out`. Entrypoint/argument escape, credential inheritance, linked-root reclaim, stale isolation state, and one corrupted asset per probe/scaffold class turn the run red. A bounded `skalary/consumer-probe-run@1` report records plugin/probe/outcome/duration/diagnostic/tree digest. `test:ConsumerInstall.ProbeDescriptorAndAttendance` · `test:ConsumerInstall.ActivePluginProbeMatrix` | 1.3, 2.1, 2.2 |
| REQ-4 | Prove first-use scaffolds are executable contracts through the one-to-one scaffold probe bindings. Literal targets are fixed; parameterized targets use only their closed value/segment domain and shipped confine helper. Before every mutation the owner rejects reparse ancestors and revalidates canonical parent identity; creation is idempotent and hostile input fails before mutation. | Clean-repo tests execute every installed owner and case, verify exact starter bytes, and cover plus-one segments, traversal, rooted/UNC/ADS forms, links/reparse points, parent replacement, existing modified files, interruption, cleanup, and retry. Capability is typed as `available`, `unavailable`, or `failed`; only `available` plus executed cases passes, while false capability claims fail. `test:ConsumerInstall.FirstUseScaffoldLifecycle` | 2.1, 2.2, 2.3 |
| REQ-5 | Consume, rather than redefine, `cda9da`'s source-bound retirement protocol. From its immutable previous-generation fixture, this plan proves only the post-transition installed entrypoint/probe view of same-source removal, foreign-source refusal, and modified-residue state. | `cda9da` tests remain authority for tombstone identity, deletion inventory, legacy receipt policy, durable journal, fault recovery, and outcome semantics. `test:ConsumerInstall.RetirementTransition` exercises only the delivered reconciler-to-installed-consumer delta. `test:PluginRetirement.ReconciliationStateMatrix` · `test:PluginRetirement.SourceIdentityAndSecretGuard` · `test:PluginRetirement.TransactionRecovery` · `test:PluginRetirement.ReaderRemovalAndResultContract` | 4.1 |
| REQ-6 | Resolve Cluster C through discoverable owner-local descriptors carrying `contract = skalary/workflow-limits@1`, values, exact active consumer paths/fields, registration tokens, and regeneration remedy. `scripts/skalary/PlanWorkflowLimits.psd1` owns plan-size/phase defaults; `schemas/review/review-limits.schema.json` owns the invocation budget in non-validating `x-skalary-limits.reviewInvocationBudget`. | The parity runner scans `.github`, `plugins`, `scripts/skalary`, `schemas`, `tools`, and `docs/design-notes`; implementation plans, fixtures, goldens, and generated catalogs are provenance/excluded. Every owner-value literal must map to an owner or descriptor registration token. Both-direction red mutations prove non-blindness without changing review v1 validation semantics. `test:WorkflowLimits.PlanOwnerParity` · `test:WorkflowLimits.ReviewOwnerParity` | 3.1, 3.2 |
| REQ-7 | Make `8a0644` depend on `34088e` and add a typed receiving-side requirement/risk for its scheduler-owned concurrency descriptor. Cross-epic mutation uses `New-Epic.ps1`, canonical plan IDs, refreshed mirrors, and graph tests rather than folder-bound evidence. | Resolver-backed evidence verifies `8a0644 -> 34088e`, both epic mirrors, receiving requirement/risk, and refusal of a copied active cap without a descriptor registration token in the REQ-6 active scan domain. The operation is idempotent and regenerating mirrors after marker revert is the rollback. `test:WorkflowLimits.FleetConsumerHandoff` · `test:Epic.WorkflowLimitsDependencyState` | 3.3 |
| REQ-8 | Keep scanner, probes, cleanup, diagnostics, and distribution bounded by machine-owned policy. The scanner runs in `validate.ps1` within 10 seconds. Probe ordinary aggregate deadlines are 30 seconds Linux/60 seconds Windows; blocking-tier deadlines are 120/240 seconds; concurrency is four and per-child time is `min(30 seconds, remaining aggregate)`. Diagnostics remain deterministic UTF-8 JSON, at most 2 KiB per probe and 64 KiB aggregate, with no secret sentinel in any channel or retained root. | Tree-bound Linux and Windows CI receipts exist before selecting `met` or `tier-required`; a contradiction reopens step 2.4. Peak-concurrency, ordinary/tier passing, all-hang terminal attendance, stale network-state startup reclaim, linked-root failed-root cleanup, and secret scans are executable. The existing `review-consumer-install` invocation, inventory, and design-note row change atomically. `test:ConsumerInstall.RuntimeAndDiagnosticBudget` | 1.3, 2.2, 2.4, 4.2 |
| REQ-9 | Complete distribution and authoritative evidence. Plugin sources, bundles, dogfood, manifests, versions, README, marketplace, registry, design/architecture notes, human architecture doc, suite metadata, and structural eval IDs converge without test-caused repair. Final proof uses CI-produced Linux/Windows receipts bound to an implementation candidate; at most one later commit may change only this plan's evidence/review assets and must name that attested parent. | Detect-only drift checks leave the tree unchanged. Removing any required copy/attestation or changing a non-evidence path after the candidate fails. Both CI legs match the parent candidate and configured ceilings; `review:cr` is published before approval. `test:ConsumerInstall.DistributionAndAttestation` · `review:cr` | 4.2, 5.1 |
