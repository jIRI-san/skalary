# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Build one shared foreign-consumer fixture substrate whose sole materializer is the shipped production installer. It resolves the active registry, invokes real dependency/hash/confinement logic, and verifies output independently; source reads are confined to declared plugin roots and deletion is allowed only after the resolved root identity equals the indexed fixture root. | Missing, extra, duplicate, escaping, reparse-ancestor, or hash-mismatched mappings fail. Existing review/retirement fixtures migrate to this substrate or remain explicitly narrower adapters; no fixture copies source wildcards or implements a second installer. `test:ConsumerInstall.ProductionFixtureAndInventory` | 1.1, 2.1, 4.1 |
| REQ-2 | Make runtime-reference closure complete through a staged scanner migration: enumerate newly visible `docs`/`schemas`/`tools` references from the closed grammar, record a disposition for every violation, then enforce installed-path, skill-relative, bundled sidecar, and first-use scaffold ownership. | Enumeration is deterministic and bounded to one indexed traversal; unsupported dynamic reads fail, parsed fenced examples remain first-party non-runtime data, and fixtures cover undeclared roots, traversal, reparse ancestors, stale bundles, and seeded violations in every root. Enforcement lands only after the inventory is empty or explicitly excluded. `test:ConsumerInstall.RuntimeReferenceEnumeration` · `test:ConsumerInstall.RuntimeReferenceEnforcement` | 1.2, 1.3 |
| REQ-3 | Cover every active plugin through a schema-validated owner-local probe descriptor. The harness launches at most one deny-by-default child process per plugin, with a 30-second deadline and process-tree termination, controlled `PATH`/home/auth variables, network and credential canaries, and read-observable source-fallback sentinels. | Required descriptors come from active manifests; planned, launched, and terminal probe sets are exactly equal with zero skips. An expected prerequisite refusal passes only after an installed payload-load sentinel. Corrupting one exercised asset in each probe class turns the run red. A bounded `skalary/consumer-probe-run@1` JSON report records plugin/probe/outcome/duration/diagnostic and tree digest. `test:ConsumerInstall.ProbeDescriptorAndAttendance` · `test:ConsumerInstall.ActivePluginProbeMatrix` | 1.3, 2.1, 2.2 |
| REQ-4 | Prove first-use scaffolds are executable contracts. Literal targets are fixed; parameterized targets use only their closed value/segment domain and shipped confine helper. Before every mutation the owner rejects reparse ancestors and revalidates canonical parent identity; creation is idempotent and hostile input fails before mutation. | Clean-repo tests execute each installed owner, verify exact starter bytes, and cover plus-one segments, traversal, rooted/UNC/ADS forms, links/reparse points, parent replacement, existing modified files, interrupted writes, cleanup, and retry. Unsupported link creation is a non-pass, never a skip counted as success. `test:ConsumerInstall.FirstUseScaffoldLifecycle` | 2.3 |
| REQ-5 | Consume, rather than redefine, `cda9da`'s source-bound retirement protocol. This plan proves only consumer transition from immutable fixture `tests/skalary/fixtures/plugin-retirement/architecture-tests-pre-cda9da-v1/`: same-source cleanup, foreign-source refusal, modified residue/degraded receipt, bounded diagnosis, crash-resume result, and idempotent retry through the production installer. | Tombstone identity, deletion inventory, legacy receipt policy, and durable journal remain `cda9da` authority. The consumer transition matrix uses the delivered reconciler and never rebuilds its state/fault model. `test:ConsumerInstall.RetirementTransition` | 4.1 |
| REQ-6 | Resolve Cluster C through discoverable owner-local descriptors carrying `contract = skalary/workflow-limits@1`, values, exact active consumer paths/fields, and regeneration remedy. `scripts/skalary/PlanWorkflowLimits.psd1` owns plan-size thresholds and phase-budget default; `schemas/review/review-limits.schema.json` owns review limits. Historical plans/transcripts are provenance, not consumers. | The parity runner discovers descriptors from allowlisted subsystem roots, reads installed authority where applicable, reports owner/consumer/value/remedy, and rejects unknown duplicate ownership or an unregistered copied active literal. Owner-side and every consumer-side red mutation prove non-blindness; existing frozen review-run v1 fixtures remain valid. `test:WorkflowLimits.PlanOwnerParity` · `test:WorkflowLimits.ReviewOwnerParity` | 3.1, 3.2 |
| REQ-7 | Make `8a0644` depend on `34088e` and add a typed receiving-side requirement/risk for its scheduler-owned concurrency descriptor. Cross-epic mutation uses `New-Epic.ps1`, canonical plan IDs, refreshed mirrors, and graph tests rather than folder-bound evidence. | Resolver-backed evidence verifies `8a0644 -> 34088e`, both epic mirrors, receiving requirement/risk, and refusal of an unregistered copied cap. The operation is idempotent and regenerating mirrors after marker revert is the rollback. `test:WorkflowLimits.FleetConsumerHandoff` · `test:Epic.WorkflowLimitsDependencyState` | 3.3 |
| REQ-8 | Keep probes, scanner, diagnostics, and distribution bounded. Scanner time is at most 10 seconds; the plugin matrix adds at most 30 seconds on Linux and 60 seconds on Windows; diagnostics are deterministic UTF-8 JSON, at most 2 KiB per probe and 64 KiB aggregate, and secret sentinels never reach stdout, stderr, or persisted reports. | Measurements run after the MVP and full matrix. If optimized work misses the allocation, a named blocking integration tier with its own inventory, platform ceiling, and CI gate lands before expansion continues; coverage is never dropped and the existing ceiling is not raised. `test:ConsumerInstall.RuntimeAndDiagnosticBudget` | 1.3, 2.2, 2.4 |
| REQ-9 | Complete distribution and authoritative evidence. Plugin sources, bundles, dogfood, manifests, versions, README, marketplace, registry, design/architecture notes, human architecture doc, suite metadata, and structural eval IDs converge without test-caused repair. Final proof uses current-tree, CI-produced Linux and Windows receipts plus tree-bound structural-eval and drift attestations; local container rows are supplemental only. | Detect-only drift checks leave the tree unchanged. Removing any required copy or attestation fails. Both CI legs match the final tree and remain under configured ceilings; `review:cr` is published before approval. `test:ConsumerInstall.DistributionAndAttestation` · `review:cr` | 4.2, 5.1 |
