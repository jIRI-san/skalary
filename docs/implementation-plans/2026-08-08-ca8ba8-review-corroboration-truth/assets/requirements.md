| REQ-1 | Introduce a closed, versioned boundary without mutating v1. Canonical files are `review-plan-v2.schema.json`, `review-result.schema.json`, `review-run-v2.schema.json`, `review-manifest-v2.schema.json`, `review-admission-v2.schema.json`, `review-receipt-v2.schema.json`, `terminal-status-v2.schema.json`, `review-v2-limits.schema.json`, `review-corroboration-policy.schema.json`, and descriptor `review-corroboration-policy.v1.json`. Pin an independent SHA-256 inventory of affected v1 schemas, fixtures, views, retained evidence, and discriminators. | Tests accept the exact role/version matrix, reject cross-version/unknown roles/fields, prove v1 inventory bytes unchanged, and pin each new `$id`, discriminator, closedness, role budget, confinement, limits embedding, and binding rule. `test:ReviewReport.CorroborationSchemaAndCompatibility` `file:schemas/review/review-plan-v2.schema.json#contains:skalary/review-plan@2` `file:schemas/review/review-result.schema.json#contains:skalary/review-result@1` `file:schemas/review/review-run-v2.schema.json#contains:skalary/review-run@2` `file:schemas/review/review-manifest-v2.schema.json#contains:skalary/review-manifest@2` `file:schemas/review/review-admission-v2.schema.json#contains:skalary/review-admission@2` `file:schemas/review/review-receipt-v2.schema.json#contains:skalary/review-receipt@2` | 1.1, 1.2 |
| REQ-2 | Ship one schema-validated `skalary/review-corroboration-policy@1` descriptor as sole policy owner. Policy@1 requires exactly two declared models; larger rosters require a new policy version. It fixes canonical field normalization, UTF-8 length-prefixed framing, ordinal order, ASCII `[a-z0-9]+` tokens after invariant folding, direction/format controls mapped to separators, 3-token field-prefixed shingles, integer Jaccard, threshold 9000, 12-token floor, maximum 16,384 cross-model pairs, schema-derived per-finding shingle/memory bounds, and witness limits. | Runtime version-map tests verify the descriptor's pinned SHA-256 before freeze and reject missing/mismatched/superseded policy bytes with exit 2. Unit tests derive 16,384 from two models/256 findings, directly reject synthetic count 16,385, pin schema-derived shingle bounds, and cover framing, controls, case, 8999/9000, and non-ASCII residual behavior. `test:ReviewReport.CorroborationPolicyDescriptor` `file:schemas/review/review-corroboration-policy.v1.json#contains:skalary/review-corroboration-policy@1` | 1.1, 1.2, 2.2 |
| REQ-3 | Derive suspicious similarity only within one existing merge group and across distinct declared model labels. Compare canonical `title`, `body`, and `action`; exclude merge-key fields, references, and task metadata. Exact normalized tuples are suspicious; otherwise field-prefixed 3-token-shingle Jaccard at `>= 9000` basis points applies only when both payloads contain at least 12 tokens. | Positive, boundary, and false-positive-negative fixtures pin field selection, normalization, exact matching, token floor, 8999/9000 behavior, group/model confinement, Unicode equivalence, culture independence, and input-order independence. `test:ReviewReport.CorroborationSimilarityPolicy` | 1.2, 2.1, 2.2 |
| REQ-4 | Make corroboration engine-owned and bounded. Raw input admits no derived fields. Each group persists orthogonal dimensions, length-framed digests, support ids, `suspiciousPairCount`, all-pairs digest, and one ordinal-first witness per affected finding. Witnesses contain only finding/task ids, declared models, integer score, and payload digests: derived identifiers, never reviewer text. Persist `comparedPairCount`, not timing. | Forged fields fail exit 2; canonical output/digests are order/culture stable; every suspicious finding has a derived-only witness; direction controls cannot spoof rendered columns; tampering fails verified read; shingle sets are capped by schema-derived limits, released per group, and stay inside memory evidence. `test:ReviewReport.CorroborationDerivedAuthorityAndCanonicalization` | 1.1, 2.1, 2.2, 4.1 |
| REQ-5 | Preserve every raw finding and maximum raw severity. Suspicious participants remain visible but cannot support elevation. Elevate at most one level, never above Critical, only with complete attendance and unsuspicious support from both policy@1 models. Hostile echo may suppress elevation but cannot suppress a finding or raise confidence. Engine-derived closed verdict vocabulary adds `needs-review`: any suspicion forces it and caller-supplied approval is rejected. | The matrix covers clean unanimous support, degraded attendance, single source, suspicious pairs, malicious echo, multiple findings per each of two models, Critical, short/empty fields, and zero findings. It excludes three-model policy@1 inputs as schema-invalid; blocked cases preserve raw/effective severity, exact reason, and non-approving verdict. `test:ReviewReport.CorroborationElevationMatrix` | 1.1, 2.1, 2.2, 3.1, 4.1 |
| REQ-6 | Use one engine-owned role/version map for freeze, publish, replay, structured/read-view verification, admission, finalization, cleanup, and distribution. Before activation, dual readers are added without changing new v1 freeze/write behavior. Activation atomically switches every new freeze to plan@2 + policy id/digest and every publish to v2. Already-frozen v1 or v2 runs always complete/replay under their bound version/policy. V2 replay identity is raw-result digest + frozen-plan digest + policy digest; changed input/policy under a used run id is exit 2. | Lifecycle tests cover pre-activation readers with v1 writes, activated v2 freeze/write, frozen-v1/v2 completion across rollback and policy updates, both replay bases, changed input/policy, structured corroboration reads, malformed/tampered bindings, all-field secret scanning, cleanup/repair/tombstones, and exact exits. `test:ReviewReport.CorroborationVersionedLifecycle` | 3.1, 3.2, 4.2 |
| REQ-7 | Keep admission fail-closed, versioned, and merge-group atomic. Validate bytes/schema/semantics and candidate count before scoring. A candidate-limit breach or single unpartitionable group writes permanent admission@2, exits 3, is not partitioned/published, and replays identically; changed input is exit 2. Terminal data includes reason, group digest, measured role/bytes/count, limit, and bounded rerun guidance. Deterministic child ownership preserves source scope/status; rollup verifies coverage/order/policy/digests/counts/states/reasons/commitments. | Tests exercise valid 16,384 and direct pure-gate 16,385, interrupted child replay, gaps/duplicates/version drift, all role overflows, permanent refusal/replay, and no raw generation left after secret rejection. The existing 10s Linux/30s Windows and 256 MiB limit applies once to the aggregate parent operation: up to 16 child derivations plus rollup. `test:ReviewReport.CorroborationAdmissionAndPartitioning` | 1.1, 2.1, 2.2, 3.2 |
| REQ-8 | Render/expose truthful corroboration and retain compact commitments. Verified structured reads and terminal-status@2 expose `verdict`, including `needs-review`, while process exit remains 0 for completed execution. Receipt@2 stores raw/effective severity, verdict/reason, policy/overall group-set digests, aggregate dimensions/counts, and bounded derived-only witnesses. Its mandatory floor always retains verdict, reason, suspicious count, group-set digest, and first witness when suspicious; per-group rows are all-or-nothing optional detail. | Structured/status/summary/full/rollup/receipt goldens are deterministic and verdict-consistent; finalization rejects caller approval when authority derives `needs-review`; maximum-cardinality receipt stays within 8 KiB or publication fails exit 3 before cleanup; summary refusal is durable exit 3 with no publication and identical replay. `test:ReviewReport.CorroborationRenderingAndGoldens` `test:ReviewReport.CorroborationRetainedVerdict` | 1.1, 3.1, 3.2, 4.1, 4.2 |
| REQ-9 | Use reader-first staged activation and explicit roles. Caller writes `review-result.input.json`; secret scanning of every raw field occurs before any addressed generation write, and rejection removes the fixed input without retaining raw bytes. The engine then commits `review-result.<sha256>.json`; manifest@2 binds closed role budgets. Engine version map pins every supported policy descriptor digest and exposes active writer/policy through verified capability/status output. Activation changes that default from v1 to v2; rollback reverts only activation, reruns sync, and retains readers. | Tests prove reader-only deployment leaves v1 writes unchanged, capability reports the active writer/policy digest, activation switches freeze+publish together, rollback completes v2, missing/mismatched policies and unknown roles fail, secrets leave no raw authority, `contentTrust` remains structural/rendered, and no authority is rewritten. `test:ReviewReport.CorroborationStagedActivation` | 1.1, 3.1, 4.2 |
