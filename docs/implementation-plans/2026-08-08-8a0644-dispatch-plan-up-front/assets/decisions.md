# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- **Use the detailed v1 contract.** State, exits, confinement, recovery, role handoff, disposable-worktree promotion, numeric budgets, ownership, suites, mutations, and document synchronization are fixed in [decisions/fleet-contract.md](decisions/fleet-contract.md).

- **One shared fleet scheduler.** `/cip`, `/ci`, `/cr`, `/dr`, and `/cep` coherency review use the same admission, wave, attendance, and throttling contract.
- **Bound one workflow run, not all sessions.** The owner cap limits at most four active invocations within one `/cip`, `/ci`, `/cr`, `/dr`, or future `/cep` fleet. Rejected: a repo/user-wide semaphore across unrelated VS Code sessions.
- **Cap admission leases at four and tasks at 128.** The scheduler proves orchestrator admission, not host-global provider concurrency. Provider concurrency is `unverified` unless typed host telemetry exists. Fleet capacity is compatible with, not owner of, review-run's 128-task maximum.
- **Declare the run before dispatch.** The plan lists selected roles or concern/model pairs, total invocations, omissions, cap, wave order, and retry policy before calls begin.
- **Never hide omissions.** Work dropped by scope or budget is named with a reason; throttling cannot silently convert a full run into partial attendance.
- **Preserve independent passes.** Reading batches do not multiply concern passes, and selected concern/model pairs still run independently once.
- **Retry one typed throttle, then report degradation.** Only explicit host `throttled` receives one retry; typed Retry-After is capped at 60 seconds and total fleet wait at 240 seconds. Agent text, ordinary failure, and timeout never authorize retry. Exhausted review throttling publishes `failed` plus `fleet-throttle-exhausted` under review-run v1.
- **Use a work-conserving ready queue.** Projected waves are an operator view, not barriers. Whenever a lease opens, admit the next ordinal task whose full dependency set completed; persist admission ordinals so timing cannot change order.
- **Continue independent work.** A terminal task failure cancels only transitive dependents; later tasks with satisfied dependencies still run and attendance records the degraded result.
- **Make timeouts host-owned.** The scheduler records a host timeout outcome but declares no timer it cannot enforce against the VS Code subagent host.
- **Use typed request/plan/result/status JSON.** Closed v1 schemas bind identity, models, dependencies, capabilities, omissions, projected waves, lease admissions, attempts, outcomes, host capabilities, and exits. A verified plan-only reader owns the pre-view.
- **Use one confined recoverable lifecycle.** Locked atomic states run `new -> planned -> running -> completing -> captured -> cleanup-pending -> closed`, with terminal cancellation. Fixed leaves, reparse checks, idempotent capture, tombstones, and incomplete-run discovery make interruption convergent.
- **Keep prompts and outputs out of fleet data.** The machine artifacts carry metadata and bounded diagnostics only. Untrusted plan/repository/agent content remains in the owning workflow and can never become executable scheduler input.
- **Use canonical path capabilities and receipts.** Reject path aliases, ancestors, reparse escapes, and overlapping writers before planning; reserve workflow-state paths; audit actual changed paths before Judge/CR. Caller labels alone are not authority.
- **Adopt a fixed CIP cadence.** Designer and Requirements Validator run in parallel after interview confirmation; Judge depends on both. The orchestrator writes the plan, and `/dr` remains the final design-review authority.
- **Adopt a fixed CI cadence.** Designer and Requirements Validator advise each step in parallel; one Implementor writes implementation scope; Judge evaluates the result; the existing `/cr` loop follows.
- **Hard-bound mandatory role cost.** CIP refuses above 4 logical/8 attempts per draft. CI refuses above 4/8 per step or 128/256 per plan (32 four-role steps); CIP requires larger plans to split. Rejected: a human overage gate that would stop whole-plan autopilot mid-run.
- **Use workflow-specific role agents.** `cip-*` and `ci-*` agents stay owned and installed by their workflows. Rejected: a new shared plugin or DR-owned generic agents that create cross-plugin runtime ownership.
- **Use an explicit cross-model pair.** Designer/Judge use `Claude Opus 5 (copilot)`; Requirements Validator/Implementor use `GPT-5.6 Sol (copilot)`; the existing explicit `Claude Sonnet 4.6 (copilot)` Pro fallback applies. Agent frontmatter remains model-agnostic.
- **Keep review Freeze authoritative.** Review callers validate candidates, review-run alone Freezes them, and fleet planning derives exact digest-bound frozen slots. The scheduler never authors frozen review records or a second post-run review view.
- **Leave epic review activation to `25aa23`.** This plan ships a generic conformance fixture plus typed ownership handoff, not a permanent CEP-absence guard that later work must delete.
- **Render chat and retain bounded capture summaries.** Generic plan/result views are operator-visible; plan-associated CIP/CI summaries use script-owned capture. Rejected: durable generic JSON artifacts or chat-only attendance with no plan provenance.
- **Own the cap, reuse the parity protocol.** This plan owns the four-in-flight scheduler value and its admission semantics, but depends on `34088e` for the `skalary/workflow-limits@1` descriptor/discovery contract; rejected: another prose or code literal with no registered owner.
- **Use an installable canonical module with generated bundles.** Canonical scripts, descriptor, and self-contained schemas are bundled into every consumer by an extended closed sidecar grammar. Installed tests poison repo-root fallbacks. Rejected: instructions-only scheduling or a separately installed scheduler plugin.
- **Keep existing model and generation owners.** `tools/model-allowlist.psd1` gains role-model keys; fleet registry references them and owns capabilities/output/activation only. Workflow agents are hand-authored and parity-tested, so no new generator or `79cfe1` dependency is introduced.
- **Isolate Implementor writes.** CI Implementor commits in a disposable worktree; a fixed promotion script audits parent, paths, capabilities, receipts, and reserved state before cherry-pick. Rejected: post-hoc audit of shared-worktree mutations and a new write-proxy subsystem.
- **Do not claim executable host enforcement.** Lease/correlation metadata accompanies calls, but the plan proves persisted admission and attempt conservation only. Rejected: refusing all execution on hosts without telemetry.
- **Bound every artifact and maximum operation.** Inputs are 2 MiB, views 256 KiB, terminal status 8 KiB, capture 4 KiB, diagnostics 2 KiB, labels 128 characters, reasons 512, edges 8,128; maximum dense-DAG operations use the existing 10s Linux/30s Windows and 256 MiB private-byte ceiling.
- **Add `ARCH-Fleet-Dispatch-V1` as provisional.** The contract states frozen declaration, four-in-flight wave admission, exact attendance, and authority boundaries without claiming the planner controls host-global concurrency.
- **Run container-autopilot for the whole plan.** All work is repository-local, all steps are `@ai-agent`, rollback is git revert, and no third-party package or external side effect is introduced.
