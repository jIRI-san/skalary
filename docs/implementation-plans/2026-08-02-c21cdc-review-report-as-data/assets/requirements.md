# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | Define closed draft-2020-12 schemas for frozen task plans, final `skalary/review-run@1` envelopes, and publication manifests. Native PowerShell 7.6+ `Test-Json -SchemaFile` owns structural validation; semantic code owns cross-record and UTF-8 byte invariants. | A Windows/Linux CI preflight requires PowerShell 7.6+ and demonstrates every committed schema feature; positive minimum/maximum fixtures pass; capability-absent, one-above, always-rejecting, unknown-version/property, duplicate, slot-mismatch, dangling, manifest-role/path, and aggregate-spoof fixtures fail at the named layer. `file:schemas/review/review-run.schema.json#exists` · `file:schemas/review/review-plan.schema.json#exists` · `file:schemas/review/review-manifest.schema.json#exists` · `test:ReviewReport.SchemaCapabilityAndSemantics` | 1.1, 1.2 |
| REQ-2 | Add a safe caller-authoring boundary and fixed installed CLI. CR/DR agents gain `edit` only to create computed `.review-plan.input.tmp` and `.review-result.input.tmp`; reviewer data never enters terminal text. `Freeze`/`Publish` atomically rename those files and accept only UUID `-RunId` plus optional confined `-PlanDir`; production derives repo/schema/artifact roots itself. | Agent/tool contracts forbid other edits; hostile quotes, here-strings, command substitutions, Markdown controls, traversal, alternate policies/roots, and legacy object calls never become executable or caller-selected. `Set-ScriptApproval` adds/removes the two exact object-valued `matchCommandLine` rules as one closed, tested exception. `test:ReviewReport.SafeInputAndApprovalBoundary` | 2.2 |
| REQ-3 | Freeze the complete planned task set before any reviewer dispatch, then publish results only against that immutable plan. Every slot carries concern and declared dispatch model; final outcomes are `completed`, `failed`, `timed-out`, `omitted`, `cancelled`, or `pending`. | Caller atomically moves `review-plan.input.json` into the computed run root before `Freeze` and `review-result.input.json` before `Publish`. Freeze requires 1-128 unique IDs/slots; Publish requires exact immutable fields/digest, bounded diagnostics, and completed-only findings. Mutation between modes fails; all-completed is clean and every other valid mix is degraded. `test:ReviewReport.FrozenPlanAndAttendanceMatrix` | 1.1, 1.2, 2.2 |
| REQ-4 | Preserve exact-key merge, strongest-severity selection, current full-declared-roster elevation, ordinal ordering, and recommendation behavior while deriving concern/model attribution from frozen tasks. Canonical semantic input, not raw JSON bytes, determines output. | A pre-change golden semantic projection pins grouping key, selected title/body/action, rank/elevation, model/concern/reference sets, and order; the new engine must match exactly. New attendance/encoding layouts have separate closed summary/full goldens. Shuffled JSON properties, task/finding order, culture, newline, and platform do not change canonical/rendered bytes. `test:ReviewReport.GoldenSemanticParityAndCanonicalization` | 1.1, 1.2 |
| REQ-5 | Publish canonical JSON as authority plus a summary of at most 32 KiB and full Markdown of at most 1 MiB. Structural maxima remain 128 tasks, 256 raw findings, and 128 merged groups, but exact UTF-8 byte-budget admission must prove both complete views fit. | Canonical JSON preserves accepted tasks/findings. Summary names every merged severity/title and attendance totals; full view lists every task/finding. Scope, diagnostics, titles, bodies, actions, and references are NFC/LF canonicalized, Markdown/HTML encoded, and fenced as untrusted data. High-confidence credential shapes are redacted before acceptance; plan publication blocks if a secret remains. A committed 44-finding corpus pins the pre-change byte count and proves at most 32 KiB without truncation. `test:ReviewReport.OutputAdmissionCompletenessReductionAndSecretGuard` | 1.1, 1.2, 3.1 |
| REQ-6 | Use immutable generation files plus `review-run.manifest.json` as sole publication commit point and provide bundled `Get-ReviewRun.ps1` as the only verifying reader. `Freeze` publishes the immutable plan; `Publish` stages canonical JSON/views and replaces the manifest last under a process-held lock. | Reader schema-validates manifest, confines single-segment names, verifies digests, and emits the summary separately from the 8 KiB terminal status. Closed transitions: identical replay is idempotent; changed reuse, Publish-before-Freeze, frozen mutation, and changed post-publication input exit `2`; exit `3` is terminal for that UUID; retry after `4` succeeds. Lock timeout is 5 seconds. Faults preserve prior authority and clean staging. `test:ReviewReport.ManifestReaderPublicationAndExitMatrix` | 1.2, 2.2 |
| REQ-7 | Both `/cr` and `/dr` allocate UUID, write/freeze one plan before any dispatch, dispatch every frozen task independently without prior-result input/suppression, collect results in memory, write one final result, publish once, read/print the verified summary, preserve path, and handle every exit. At next start they find any frozen unpublished run, publish all tasks `cancelled` with diagnostic `orchestrator-interrupted`, then start a new UUID; no resume/checkpoint subsystem. | Exit `0` prints clean summary; `5` prints degraded summary then propagates non-success; `2`/`3`/`4` abort as applicable, show bounded diagnostics, preserve authority, and propagate failure. Structural cases prove installed contract; the final live `review:cr` artifact proves observed frozen tasks/outcomes without claiming model compliance. `test:ReviewReport.SharedCallerExitIndependenceAndAbandonment` · `test:ReviewReport.ConsumerInstallInvocation` · `review:cr` | 2.2, 2.3, 4.1 |
| REQ-8 | Keep schemas, module/scripts/reader, skills/guides/agents, manifests, dogfood, settings approvals, design notes, marketplace, and registry synchronized with no new package or vendored validator. | Extend `Sync-PluginScripts.ps1` closure scanning to literal `$PSScriptRoot` `.schema.json` references resolved only from canonical `schemas/review/`; it copies/prunes sidecars without a new manifest field. Assert root/plugin/dogfood hashes, one automatic patch bump per changed plugin per synchronization step, exact expected CR/DR eval IDs, and no package/lockfile changes. `test:ReviewReport.PayloadOwnershipAndDrift` · `test:ReviewReport.StructuralEvalDiscovery` · `test:ReviewReport.NoNewRuntimeDependency` | 2.1, 2.2, 3.1, 3.2 |
| REQ-9 | `c21cdc` owns the v1 validation/persistence/rendering contract; `8a0644` owns future fleet task planning and emits this contract, while `ca8ba8` owns later similarity/corroboration policy. Both depend on `c21cdc`; neither may redefine v1. | Both markers/mirrors carry `c21cdc`; a real graph test proves edge resolution and state equivalence (`blocked` iff the dependency is incomplete), using a synthetic incomplete/complete fixture rather than requiring live blocked state after archival. `ca8ba8` consumes v1 or introduces v2/migration. `file:docs/implementation-plans/2026-08-08-ca8ba8-review-corroboration-truth/plan.md#contains:depends-on:[^>]*c21cdc` · `file:docs/implementation-plans/2026-08-08-8a0644-dispatch-plan-up-front/plan.md#contains:depends-on:[^>]*c21cdc` · `test:Epic.ReviewRunConsumerEdgesAndState` | 1.1, 3.1 |
| REQ-10 | Give every run a canonical identity/lifecycle. Plan runs publish under the `ReviewRuns` logical asset kind; generic runs publish under gitignored `.github/.skalary/review-runs/<run-id>/`; callers cannot provide another root. | Add `ReviewRuns` to `Resolve-PlanAssetPath` for current/legacy layouts and validate PlanDir through inventory. Run IDs are lowercase UUIDs. Input is removed after success and irreversibly deleted/redacted immediately on secret rejection; staging is cleaned. Plan artifacts are committed; generic published runs are removed by bundled `Remove-ReviewRun.ps1` only after verified chat delivery. `test:ReviewReport.ArtifactHandshakeLocationCleanupAndSecretRejection` | 1.2, 2.2, 2.3 |
| REQ-11 | Make encoding, canonicalization, exits, and diagnostics exact. Canonical JSON and Markdown are UTF-8 without BOM, LF, NFC, ordered by contract-defined ordinal keys, and hashed after canonicalization. | Exit `0` clean, `5` valid-degraded, `2` invalid, `3` admission, `4` lock/publication/unexpected. Every exit writes exactly one terminal-status JSON object on stdout, closed by schema and at most 8 KiB; stderr is encoded and at most 16 KiB; each task diagnostic is at most 2 KiB UTF-8. Error precedence is parse/schema -> semantic -> admission -> publication. `test:ReviewReport.EncodingExitDiagnosticAndLockContract` | 1.1, 1.2, 2.2 |
| REQ-12 | Bound cost and keep evidence discoverable. | On every supported CI leg, a child-process maximum-envelope fixture records OS/PowerShell identity, wall clock via `Stopwatch`, and peak private bytes by process sampling; execution is required, never skipped, and must publish within 5 seconds/256 MiB growth. Consumer installs reuse one fixture per plugin; removing steps update coverage baseline reasons; exact eval IDs are discovered; indexed docs own the contract; ordinary suite remains inside platform ceilings. `file:docs/design-notes/architecture/review-reporting.design.md#exists` · `test:ReviewReport.MaximumEnvelopeBudget` · `test:ReviewReport.TestAndEvalDiscovery` | 1.1, 1.2, 2.2, 2.3, 3.1 |
| REQ-13 | Retire the legacy object API only in the atomic caller migration after bundled sidecars/readers exist and both CR/DR installed fixtures pass. | Phase 1 keeps all existing formatter tests green; Phase 2 removes every `-Finding`, generated `[pscustomobject]`, old guide/help example, broad approval, and obsolete test ID in one step, with each suite-baseline removal naming its owner/reason. `test:ReviewReport.AtomicLegacyRetirement` | 2.2 |
