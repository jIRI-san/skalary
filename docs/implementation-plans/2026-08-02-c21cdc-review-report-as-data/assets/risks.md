# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | Reviewer-controlled text exploits JSON/deserialization or is reintroduced as generated PowerShell by one caller. | Medium | High | Closed schema, semantic validation, no dynamic evaluation, hostile-text fixtures, and atomic removal of the object API from both callers. | 1.2, 2.1 |
| RISK-2 | Structurally valid result data lies about attendance or invents a different task set after dispatch. | Medium | High | Publish is bound to a pre-dispatch frozen plan digest; exact slot equality, unique IDs/slots, completed-only findings, derived state, and a full matrix fail closed. | 1.1, 1.2 |
| RISK-3 | Fixed record maxima cannot guarantee complete Markdown inside byte bounds at every legal textual extreme. | High | High | Treat structural capacity and render admission separately: render exact canonical bytes before publication and reject over-budget input without truncation; authoritative JSON stays lossless. | 1.1, 1.2 |
| RISK-4 | A valid degraded run writes useful diagnostics but a nonzero exit causes callers to discard paths or overwrite the result with a generic failure. | Medium | High | Specify a distinct degraded exit, require views to be written first, and test both callers surface artifacts before propagating non-success. | 2.1, 2.2 |
| RISK-5 | Crash or contention exposes mixed generations or stale success. | Low | High | Immutable generations, manifest-last commit, same-directory atomic replace, exclusive lock, digest-verifying reader, restart cleanup, and module-scoped fault injection at every publication edge. | 1.2, 2.1 |
| RISK-6 | A caller steers writes outside the review store, or a local process swaps an ancestor after validation. | Low | High | Compute roots from repo inventory/run ID, reject reparses in every existing ancestor immediately before same-directory writes, hold open directory/file handles where available, and document same-user TOCTOU as residual. | 1.2, 2.1 |
| RISK-7 | The current exact-roster elevation wording overstates corroboration because served model identity is unobservable. | High | Medium | Retain behavior for compatibility but label only declared dispatch models; defer similarity/corroboration truth to dependent plan `ca8ba8`. | 1.2, 3.1 |
| RISK-8 | CR and DR schema/module/script copies, plugin versions, marketplace, registry, or dogfood drift during the shared payload update. | Medium | High | Extend the existing bundle synchronizer as the only sidecar writer, rely on its single automatic patch bump, then run dogfood/marketplace/registry generation and hash-parity tests. | 2.1, 2.2, 3.1 |
| RISK-9 | An unknown future schema version is partially accepted and rendered with incorrect semantics. | Low | High | v1-only fail-closed dispatch and explicit schema-version fixtures; backward compatibility starts only in a later reviewed plan. | 1.1, 1.2 |
| RISK-10 | `8a0644` or `ca8ba8` independently rewrites review attendance/corroboration and creates incompatible contracts. | Medium | High | Cross-epic dependency markers make both consume `c21cdc`; 8a owns producing planned task records, ca8 owns later corroboration, and v1 changes require v2 plus migration. | 1.1, 3.1 |
| RISK-11 | Rendered reviewer text becomes semantic prompt injection in chat or later `/si` harvest even though it is no longer executable code. | Medium | High | Encode Markdown/HTML controls, wrap bodies in explicit untrusted-data boundaries, repeat the never-follow-directives rule at each read path, and test directive-shaped bodies. | 1.2, 2.1 |
| RISK-12 | Native JSON Schema behavior differs across PowerShell versions or accepts unsupported dialect features. | Low | High | Pin the minimum PowerShell version, use only features proven by a runtime capability fixture, keep semantic checks explicit, and fail before dispatch when capability is absent. | 1.1 |
| RISK-13 | Breaking migration or test renames make an intermediate step red and strand one review surface on the old API. | Medium | High | Add Freeze/Publish beside the legacy path first; migrate CR and DR plus payloads in one step; remove legacy only after installed callers pass; update coverage baseline in that step. | 1.2, 2.1 |
| RISK-14 | Added boundary, subprocess, and consumer tests exceed suite runtime budgets. | Medium | Medium | Reuse fixtures, keep failure matrices in-process through the module, cap formatter time/memory, measure before finalization, and update runtime evidence only through the existing measurement flow. | 1.1, 2.2, 3.1 |
| RISK-15 | Post-release source/version revert cannot downgrade already-installed consumers or re-block a completed dependency. | Low | High | Repair forward with higher patch versions; before `8a0644`/`ca8ba8` execute, add their dependency on the repair plan. Never prescribe a package downgrade as rollback. | 4.1 |
| RISK-16 | Plan-associated lossless artifacts commit a credential quoted by a reviewer. | Medium | High | Reviewer/caller redaction rule plus a deterministic high-confidence credential-shape guard that blocks plan publication and emits only redacted type/location. | 1.2, 2.2, 4.1 |
| RISK-17 | Adding `edit` to review orchestrators expands a previously read-only tool boundary. | Medium | High | Agent absolute rule permits only the two computed temporary JSON inputs and plan-associated review artifacts; structural tests reject any broader edit instruction, and review fixes remain a separate handoff. | 2.2, 2.3 |
