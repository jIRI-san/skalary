# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- **D1 — Narrowly supersede `b0c0d3` REQ-18's object-only/pure-formatter boundary.** Deterministic script-owned collation remains; JSON file ingestion and script-owned output writes replace generated PowerShell because the old invocation made reviewer data executable and unapprovable. See [decisions/review-run-contract.md](decisions/review-run-contract.md).
- **D2 — Versioned authority:** schema `$id` is a repository URL and envelope discriminator is `skalary/review-run@1`; preserved canonical JSON is the source of truth and both Markdown views are digest-bound derivatives. v1 is immutable after release; follow-ups consume it or introduce v2 plus migration.
- **D3 — Closed capacity:** 2 MiB input, 128 tasks, 256 raw findings, 128 merged groups, 160-character titles, 4 KiB bodies, and 8 references per finding. Unknown versions and excess fail closed.
- **D4 — Frozen task truth:** `Freeze` commits at least one unique concern/model task slot before dispatch. `Publish` accepts the exact frozen set with outcomes `completed`, `failed`, `timed-out`, `omitted`, `cancelled`, or `pending`; only all-completed is clean and every other valid mix is degraded.
- **D5 — Bounded dual rendering:** summary is at most 32 KiB and names every merged finding; full Markdown is at most 1 MiB and carries every task/merged finding; raw records remain lossless in JSON.
- **D6 — Byte-budget admission, never truncation:** structural maxima do not promise renderability. `Publish` renders exact UTF-8 bytes first and rejects any envelope that cannot produce both complete views before the manifest changes.
- **D7 — Fixed CLI and exits:** one installed CLI exposes only `Freeze` and `Publish`, accepts only run ID plus optional plan directory, derives repo/schema/paths from its installed location, and returns `0` clean, `5` valid-degraded after publication, `2` invalid, `3` admission/bound, or `4` lock/publication/unexpected.
- **D8 — Independent discovery is invariant:** deduplicate only at render time, never prime or suppress reviewer dispatch based on another reviewer's output.
- **D9 — Model claims stay precise:** v1 records the declared dispatch model, not an unverifiable served identity; current exact-roster elevation behavior stays compatible until `ca8ba8` reviews corroboration semantics.
- **D10 — Ownership order:** `c21cdc` owns v1 validation, persistence, derived attendance, and rendering; `8a0644` depends on it and later owns fleet task-plan production; `ca8ba8` depends on it and owns later similarity/corroboration policy.
- **D11 — Execution:** container autopilot runs the whole plan with no new third-party packages; one final `@human` review gate approves the trust boundary and rendered artifacts.
- **D12 — Native schema validation:** the wrapper stays `#requires -Version 7.0`, explicitly checks for PowerShell 7.6+ before schema use, emits exit `2` terminal JSON when absent, and documents 7.6+ as a consumer prerequisite. Windows/Linux CI prove the required `Test-Json` features; semantic/byte rules remain explicit.
- **D13 — Manifest publication:** immutable content-addressed canonical JSON/summary/full files become visible only through an atomically replaced `review-run.manifest.json`; readers ignore unreferenced files.
- **D14 — Computed artifact homes:** live plan runs use gitignored `<plan>/assets/reviews/<uuid>/`; generic runs use gitignored `.github/.skalary/review-runs/<uuid>/`. Finalized plan evidence is the compact `<uuid>.review.md` + `<uuid>.receipt.json` sibling pair. The CLI accepts no schema or output-root parameter.
- **D15 — Canonical bytes:** canonical data is NFC, LF, UTF-8 without BOM, integer-only, ordinal-keyed, and deterministically sorted where arrays are semantically sets; its digest, not raw input ordering, binds every view.
- **D16 — Fixed input handshake:** caller atomically renames `.tmp` files to `review-plan.input.json` and `review-result.input.json` in the computed run root. Freeze/Publish consume only those names; identical replay is idempotent and changed run-ID reuse is invalid.
- **D17 — Exact terminal bounds:** task diagnostics are 2 KiB, stdout terminal JSON 8 KiB, and encoded stderr 16 KiB maximum. A closed terminal-status schema covers every mode/exit.
- **D18 — Secrets before lossless acceptance:** reviewers redact suspected values; plan-associated Publish blocks high-confidence credential shapes and reports only redacted type/location. Lossless authority applies after this acceptance guard.
- **D19 — One-shot caller lifecycle:** Freeze once, dispatch all tasks independently, collect results in memory, and Publish once. A later invocation converts frozen unpublished runs to degraded cancelled reports and starts a new UUID; it never resumes missing model outputs.
- **D20 — Verified view channel:** `Build-ReviewReport.ps1` stdout stays bounded terminal JSON; bundled read-only `Get-ReviewRun.ps1 -View Summary|Full` verifies the complete manifest, digests, encoding, and role bound before emitting either view. Summary and full detail are delivered before `Remove-ReviewRun.ps1` may clean up a generic run.
- **D21 — Admission is terminal:** exit `3` never mutates the accepted finding set. The caller abandons that UUID and starts a narrower-scope review; no lossy correction or same-ID retry is legal.
- **D22 — Structural trust, no artifact directives:** plan, run, manifest, and rendered views carry `contentTrust: reviewer-authored-data`; the renderer emits a structural marker/value and no AI-directed imperative warning.
- **D23 — Frozen scope authority:** code scope binds mode, base/head identities, canonical ordered path/status records including deletions, and an engine-computed digest. Design scope binds a canonical plan/design source path and digest. Dispatch and Publish use that frozen authority exactly.
- **D24 — Observable model state:** each roster label has requested/declared labels, preflight, optional fallback, degradation, and `servedIdentity: unverified`. Rendering never claims served identity.
- **D25 — Prepare before write:** the read-only engine resolver checks every reparse ancestor/leaf before plan inventory/layout reads and returns the sole run root. Callers create/write only after Prepare; Freeze never creates a missing root.
- **D26 — One bounded admission partition generation:** render admission preserves canonical source bytes, permits at most 16 ordered children at restart ordinal 1, and completes only when the reader proves exact parent scope coverage and exact raw-finding multiset preservation.
- **D27 — Structural evals are a separate deterministic CI gate:** `npm run eval` executes Tier-1 Pester on both platform legs and fails unless every id in `tools/structural-eval-required.json` executes exactly once and passes. It never invokes waza; Tier-2 remains opt-in.
- **D28 — Compact durable review evidence:** manifest-bound JSON/full views remain transient execution authority. Human finalization writes an explicit approved/blocked result capped at 8 KiB plus a digest/count receipt, then removes the live run. Approval requires clean attendance and zero Critical/High findings.
- **D29 — One verified read, one serialized finalization:** the manifest reader retains verified bytes and parsed authority for downstream views/finalization. Historical live bundles were migrated once; production now accepts only the current manifest shape, while already-written compact legacy receipts remain durable evidence. Plan finalization takes a stable ignored store lock plus the run publication lock, supports `ShouldProcess`, writes both compact siblings before recursive cleanup, reports cleanup-pending truthfully, and converges cleanup on same-verdict retry without relabeling durable evidence as failed.
