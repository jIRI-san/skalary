# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | One factory-loop plugin supports repository and global CLI use with explicit consumer selection. | `test:FactoryLoop.Install` and `test:FactoryLoop.GlobalLayout` prove foreign-consumer execution, plugin-relative assets, dependency bootstrap and no writes to global payload during project work. | 1.1, 4.2 |
| REQ-2 | Guided setup creates project-owned commands/configuration and validates readiness. | `test:FactoryLoop.Setup` proves preview/approval, rerun preservation, actionable missing auth and no credentials in config; no installer writes outside `.github`. | 1.1 |
| REQ-3 | Small command adapters cover work items, PR/checks, deployment, running version, acceptance and telemetry. | `test:FactoryLoop.AdapterContract` rejects malformed output, propagates errors and reconciles writes using stable operation identity; bundled loopback never calls live providers. | 1.2 |
| REQ-4 | Demo acceptance runs against actual immutable artifacts of a small application. | `test:FactoryLoop.DemoArtifact` rejects a planted defect, passes its code fix, rejects artifact mismatch and proves snapshots cannot change with working-tree edits. | 1.2 |
| REQ-5 | Finite ticks support personal scheduled polling with one active chain per project. | `test:FactoryLoop.Tick` proves locking, explicit root binding, configurable 60-second default and zero agent calls for unchanged waiting state. | 2.1 |
| REQ-6 | Restart recovers mutation boundaries without duplicate side effects. | `test:FactoryLoop.Restart` proves keys exist before dispatch, then interrupts after PR/bug/promotion/evidence/closure mutation but before result checkpoint; reconciliation retains the same provider ID or pauses visibly if unknown. | 2.1, 3.2, 4.1 |
| REQ-7 | PR polling handles failures and human merge against the current head. | `test:FactoryLoop.PrChecks` covers failing/pending/cancelled checks, changed head, closed-unmerged PR and human merge; no automatic merge. | 2.1 |
| REQ-8 | Idea or existing-plan intake preserves initial confirmation and deployment acceptance criteria. | `test:FactoryLoop.PlanAdmission` refuses unconfirmed/drifted plans, routes ideas through /cip and proves unrelated plans retain existing behavior. | 2.2 |
| REQ-9 | Initial work uses /ci; factory repair mode preserves baseline without completed-phase admission. | `test:FactoryLoop.AgentHandoff` proves original baseline validation, no criterion/marker writes and real Git effects using the existing launcher; `test:FactoryLoop.RepairBounds` proves at most two incident repair PRs and two corrective calls per stable build incident across successor PRs/heads, with scope changes paused. | 2.2 |
| REQ-10 | Chain-level credit admission accounts for planning, implementation and repairs without AI polling. | `test:FactoryLoop.Credits` proves idempotent execution imports, zero replay credits, no further invocation after known usage reaches allowance, explicit missing-usage stop and no claim of mid-call hard enforcement. | 2.2 |
| REQ-11 | Validation correlates merged work, deployment and running artifact. | `test:FactoryLoop.DeploymentIdentity` covers merge/source mapping, delayed version, failed/cancelled/approval-pending/superseded deployments and unexpected artifact. | 3.1 |
| REQ-12 | Test/pre-prod/prod share profiles and project-owned scenario commands. | `test:FactoryLoop.Acceptance` proves test/prod use artifact-specific scenarios, criteria cannot be weakened, cleanup is explicit and prod defaults read-only; pre-prod profile parsing is covered. | 3.1 |
| REQ-13 | Bounded telemetry observation is separate from feature acceptance. | `test:FactoryLoop.Telemetry` uses an injected clock for configurable five-minute default, cursor recovery, empty valid results, confirmed failures and auth/query outages; unavailable data cannot pass. | 3.1 |
| REQ-14 | Production triggering needs explicit approval for the artifact accepted in test. | `test:FactoryLoop.ProductionApproval` proves unanswered decisions wait with zero AI, decline blocks, replaced artifacts invalidate approval, HEAD edits cannot rebuild the promoted snapshot, native approvals remain and resume cannot duplicate promotion. | 3.2 |
| REQ-15 | Confirmed defects create deduplicated linked bugs and follow the original validation through repair. | `test:FactoryLoop.BugCycle` proves repeated polls yield one bug, occurrences attach, a fix PR follows test/prod again and bug resolution requires the original reproducer to pass. | 3.2 |
| REQ-16 | Missing access or uncertain attribution pauses instead of inventing success/repair. | `test:FactoryLoop.InaccessibleProduction` proves inaccessible prod stays blocked and original item open; prerequisite failures and suspected causes do not trigger automatic app fixes. | 3.2 |
| REQ-17 | Sanitized evidence commits live on a separate non-deploying branch/worktree. | `test:FactoryLoop.Evidence` verifies provenance/window/verdict labels, secret/customer-data refusal, source-tree preservation, no merge to main and setup acknowledgement/verification of trigger exclusion. | 4.1 |
| REQ-18 | Original item closes after all configured required environment acceptance and published evidence. | `test:FactoryLoop.Completion` proves evidence failure prevents closure, closure replay is idempotent and terminal ticks stop monitoring. | 4.1 |
| REQ-19 | Deterministic installed replay proves the complete local chain. | `test:FactoryLoop.EndToEnd` covers feature implementation stand-in, PR/build, human merge, test, approval, prod, evidence and closure with actual Git/artifact assertions and no AI/network. | 4.2 |
| REQ-20 | Fault matrix proves resilience and denial paths. | `test:FactoryLoop.FaultMatrix` covers build repair, deployed defect repair, stale version, missing auth/telemetry, approval denial, exhausted repairs, malformed adapter results and restart boundaries without real waits. | 4.2 |
| REQ-21 | Ship focused structural evals and explicit opt-in observable agent evals. | `test:FactoryLoop.EvalContract` validates grader placement/execution, isolated write-enabled cases, preserved criteria and no premium callers in deterministic routes; premium live results remain optional/report-only. | 4.3 |
| REQ-22 | Documentation and generated distribution expose the usable MVP and limits. | `test:FactoryLoop.Documentation` and `review:cr` cover demo controls, scheduler recipe, global bootstrap, live command examples, cleanup, auth/approval stops and loopback limitations; existing generator drift checks pass. | 4.3 |
