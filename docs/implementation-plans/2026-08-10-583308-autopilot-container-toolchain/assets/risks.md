# Risks

| ID | Risk | Likelihood | Impact | Mitigation | Steps |
|----|------|------------|--------|------------|-------|
| RISK-1 | A broad utility list bloats image pulls and slows clean builds. | Medium | Medium | Keep a closed baseline, clean apt metadata, validate candidate first, share within-run BuildKit cache, enforce 25/10/35/45-minute budgets, and report sizes against an advisory threshold. | 1.1, 1.3, 2.1, 2.2, 3.1, 4.1 |
| RISK-2 | Extra binaries or acquisition sources increase supply-chain and executable surface. | Medium | High | Enforce the pre-third-party Debian host allowlist, add no daemon/editor/browser/cloud CLI/curl-pipe source, and run candidate code without secrets, socket, privilege, devices, capabilities, or host network. | 1.1, 1.2, 1.3, 2.2, 4.1 |
| RISK-3 | Debian's `fdfind`/`batcat` names make agents believe tools are absent or permit writable shims. | High | Medium | Install exact root-owned conventional aliases in a non-writable directory and prove invocation in structure and image smoke. | 1.2, 1.3, 2.2, 3.1 |
| RISK-4 | Static tests pass while tools fail under the non-root runtime user or installed payload. | Medium | High | Use ordinary runner contracts plus bounded local/CI candidate builds, manifest-driven parity, closed smoke JSON, durable failure receipts, and fail-closed result propagation. | 1.2, 1.3, 2.1, 2.2, 3.1, 4.1 |
| RISK-5 | `pip`, SSH, netcat, and DNS clients make code retrieval and outbound diagnostics easier in a PAT-bearing production autopilot container. | Medium | High | Accept capability explicitly; add no daemon or privilege; preserve non-root production execution and existing secret/command boundaries; keep CI candidate execution secretless/socketless. | 1.1, 1.2, 1.3, 4.1 |
| RISK-6 | Conditional image execution can omit or false-green the stable check. | Medium | High | Trigger every PR/main push, force relevance when detection base is unusable, and test the full detector/image truth table; only irrelevant/skipped or relevant/success passes. | 2.1, 2.2, 3.1, 4.1 |
| RISK-7 | Floating base tags, historical payload drift, and unavailable event bases make byte comparison unavailable or misleading. | High | Medium | Always validate candidate first; use closed candidate-only reasons for unusable or failed base work; otherwise bind and report exact event SHAs, image identity, architecture, daemon, and Copilot version. | 1.1, 2.1, 2.2, 3.1, 4.1 |
