# Decisions

<!-- Key decisions made during planning — one bullet per decision. Extended rationale goes in assets/decisions/<topic>.md. -->

- Create a dedicated epic child instead of adding container image work to consumer-install or review-report plans; those plans do not own `plugins/autopilot/devcontainer/**`.
- Treat `ripgrep`, `fd`, and `bat` as the primary agent ergonomics gap, then include a closed supporting baseline for archives, native dependencies, Python helpers, shell lint, process/network inspection, SSH, and SQLite.
- Install only from configured Debian repositories with `--no-install-recommends`; do not add runtime package installation or another third-party download channel.
- Normalize Debian package aliases with image-owned links so agent instructions stay portable across Linux environments.
- Report measured image growth against an advisory 250 MiB threshold. Exceeding it does not fail CI, but the job summary and final human gate must keep the cost visible and explain material growth.
- Keep the ordinary `npm test` suite Docker-free. Run functional non-root execution in a post-merge Linux workflow with conditional image work; structural Pester coverage proves workflow, package, alias, runner, and payload wiring without Docker on unrelated changes.
- Keep Windows Sandbox parity out of scope because its versioned host cache has a separate cost and update model.
- Reuse plan `001`'s non-root container and safety boundaries and plan `003`'s plugin-canonical/dogfood distribution; extend plan `aaf29b`'s image-owned versus runtime-package distinction and plan `768d7b`'s affordable-gate separation. No indexed decision is superseded or in conflict.
- Raise the advisory phase budget from six to nine points: the manifest/image/smoke contract and the runner/workflow/result contract each require three `L` steps, and splitting them further would leave red or false-green intermediate commits.
- Keep the existing floating `.NET 10` base, Debian packages, and launch-time Copilot version policy. Comparisons are run-reproducible through shared resolved inputs, not byte-reproducible across dates.
- Accept `pip`, SSH, netcat, and DNS-client availability. The container already carries `curl`, npm, GitHub credentials, unrestricted outbound networking, and host Docker authority; these tools improve diagnostics without adding a daemon, privilege, or new trust boundary.
- Use an unfiltered `push`-to-`main` trigger with a conditionally expensive image job and an always-reported final result, not workflow-level path filters. The result is reported for every merged commit without rebuilding on unrelated changes.
- Treat ordinary Pester as the sole `test:` evidence host. Docker-only smoke execution is required workflow/review evidence but is not named as a typed `test:` marker.
- Use `toolchain.tsv` as the sole executable package/case inventory and `Invoke-ContainerToolchainGate.ps1` as the sole path, event, build, result, receipt, and size-reporting implementation shared by local and CI execution.
- Always block on candidate parity/build/smoke. When the event base is unavailable, predates the installed context, or has historical payload drift, emit a closed candidate-only result instead of failing or substituting an unrelated base; size delta is then not comparable.
- Keep the existing first-layer bootstrap packages outside `toolchain.tsv`; the Dockerfile installs their named literal plus the manifest-derived additional baseline, so no second baseline package list exists.
- Make the image gate post-merge (`push` to `main`) rather than a pull-request check. This supersedes the earlier decision to run PR detection and validation from a credential-free base-SHA checkout: on `pull_request`, GitHub reads the workflow definition from the candidate's own head, so the candidate authors the steps that are supposed to contain it — including the base-SHA checkout — and deleting the job leaves a green check. GitHub's organization *required workflows* would supply a definition the candidate cannot edit, but this repository has none configured, so it cannot be relied on. A `push` to `main` runs the definition at a commit a reviewer already accepted, which is a boundary that actually holds. The accepted cost is that a regression is detected after merge, not before it. Candidate scripts still run only inside the built secretless/socketless image.
- Validate candidate first under 25 minutes, then spend at most 10 residual minutes on advisory base comparison. Every internal terminal path writes a bounded receipt from `finally`; artifact upload runs under `if: always()` before the 45-minute job ceiling.
- Use the floating `debian:trixie-slim` base and install the maintained .NET 10 SDK from Microsoft's Debian 13 repository after the Debian-only baseline layer. The previously approved `mcr.microsoft.com/dotnet/sdk:10.0` floating tag changed to Ubuntu and made the Debian source boundary fail closed during phase 3 measurement.
