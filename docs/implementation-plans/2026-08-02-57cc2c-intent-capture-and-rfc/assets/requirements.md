# Requirements

| ID | Requirement | Acceptance Criteria | Phases/Steps |
|----|-------------|---------------------|--------------|
| REQ-1 | `/ci` and autopilot resolve all direct/transitive `depends-on` edges once per invocation from one indexed inventory, with a visited set, cycle detection, max depth 16, max 64 nodes, memoized plan reads, and chain diagnostics; dependencies must be complete or archived before mutation. New plans enroll through `<!-- interview-gates: required -->` plus `assets/interview-gates.json`. Bundled `schemas/plan/interview-gates.schema.json` is the cross-plugin shape/parity contract; PowerShell 7.0-compatible strict code validation rejects unknown/duplicate fields before repair. `PlanState.psm1` owns vocabulary and reads. `Set-InterviewGates.ps1` is the sole JSON/governed-content writer, accepts bounded stdin envelopes, uses an OS-released lock with 5-second timeout/100 ms retry and explicit test-only parameters, supports batched idempotent writes, rejects archived targets, invalidates before content change, checks versions before repair, and repairs only through an explicit operation that clears authority. | Bounded dependency/cycle/missing/ambiguous cases, schema parity/distribution drift, replay/batch/lock/crash recovery, explicit repair and unknown-version byte preservation, canonical plan/archive refusal, and a stable per-field hostile reader/writer case inventory pass with unchanged files and redacted diagnostics. `test:InterviewGates.DependencyTraversalBounds` `test:InterviewGates.SchemaWriterAndHostileCaseInventory` | 1.1 |
| REQ-2 | `cip-stage` remains lifecycle authority. `New-Plan.ps1` writes marker/templates then delegates all JSON bytes to `Set-InterviewGates.ps1`; `/cep` uses the same writer. `Set-PlanStage.ps1` and the writer hold the same canonical lock across gate validation/invalidation and atomic replacement. Every target rank at or above `drafted` is gated; regression is controlled. `Get-PlanValidationDecision` owns enrolled below-floor validation and archive warnings. Advancement requires populated intent, empty blockers, assessed/final-rechecked classifications, valid assets, current confirmations, and `approvalSource: interactive-operator`. `Get-PlanState` exposes enrollment, versions, confirmations, counts, classifications, approval, reasons, and first pending gate. Post-draft explicit repair blocks execution at the current stage until reconfirmed. | Scaffold/`/cep`, concurrent advancement/invalidation, rank jump/regression, below-floor/archived behavior, final-trigger contradiction, operator-source refusal with unchanged state, post-draft repair/resume, and closed `ENFORCED`, `LEGACY-SKIPPED`, `REPAIR-REQUIRED`, `OPERATOR-NEEDED`, and `UPDATE-REQUIRED` text/JSON signals pass. `test:InterviewGates.LifecycleLockAndReadSurface` `test:InterviewGates.StageFloorRepairAndSignalMatrix` | 1.2, 1.3 |
| REQ-3 | `/cip` uses three checkpoints: intent, domain/design context, and final pre-draft summary after a provisional outline. Interview Gates stores per-checkpoint counts capped at three and one-use continuation; it reuses `ReviewCycleGate` cap/authorization semantics but keeps pre-review storage separate. Existing prose gates map to retained elicitation versus machine-subsumed blocking authority. Canonical ownership remains intent five sections/end-user outcome, decisions settled/rejected choices, risks lower-impact uncertainty, Interview Gates confirmations/classifications/blockers/counts only, and selective quotes beside the clarified point. | MVP state/resume cases owned by 1.2 and full section-scoped mutation cases owned by 2.1 bind durable caps, fresh-session resume, ownership/supersession, and order. Required Tier-1 cases use stable Interview Gates identifiers with missing/skipped/duplicate/rename enforcement; Tier-2 remains report-only. `test:Cip.InterviewCheckpointMvp` `test:Cip.InterviewCheckpointFullContract` `test:InterviewGates.StructuralEvalEnforcement` | 1.2, 2.1 |
| REQ-4 | The operator classifies whether specialized terms, actor distinctions, invariants, units, transitions, hidden rules, or assumptions can change behavior; otherwise JSON records not-required and one bounded reason. Automation validates only objective state, bounds, and required sections. One section-list function feeds scaffold, `domain-template.md`, writer, validator, guides, manifests, and dogfood parity. Required `domain.md` is max 16 KiB and has no unresolved high-impact item. | Classification route/override, exact boundary, malformed/missing section, section parity, duplicated reason, lower/high-impact uncertainty, and identical reader/writer hostile cases pass. `test:Cip.DomainStateBoundsAndParity` `test:InterviewGates.DomainReaderWriterCaseInventory` | 2.2 |
| REQ-5 | The operator classifies the judgment-based RFC triggers from a provisional outline; automation rechecks objective multi-phase and declared contract/trust-boundary markers against the final parsed plan. Required `design.md` uses one section-list source, one Mermaid flow, max 16 KiB, optional call stacks, `approvalSource: interactive-operator`, revocation, and invalidate-before-write. Design-affecting `decisions.md` or `risks.md` edits must first invoke explicit invalidation; direct bypass remains a Known Plan Issue. DR receives canonical reader output as bounded inert context, and mechanical wiring uses deterministic tests rather than `review:dr`. | Objective trigger contradiction, judgment route, approval-source/refusal/revocation, interruption, section/bound parity, reader/writer hostile inventory, bounded DR handoff, template source/install declarations, and installed wiring pass; `review:dr` covers design judgment only. `test:Cip.DesignStateApprovalAndParity` `test:Cip.DesignTemplateDeclaredAndInstalled` `test:InterviewGates.DesignReaderWriterAndDrHandoff` `review:dr` | 2.3 |
| REQ-6 | `drafting-guide.md` requires a provisional outline before design classification and objective parsed-plan invariants: implementation Phase 1 routes at least one requirement through an end-to-end slice, every requirement maps to a step, and the final phase owns every requirement not completed earlier. Operator confirmation and DR judge whether slices are genuinely usable; automation does not claim semantic proof. | Parser fixtures reject absent outlines, classification-before-outline, unmapped requirements, and no-final-route cases. Stable Tier-1 guidance cases are deletion-resistant; optional semantic Tier-2 remains report-only. `test:Cip.VerticalPlanObjectiveInvariants` `test:InterviewGates.VerticalGuidanceStructuralEval` | 3.1 |
| REQ-7 | `/ci`, `/dr`, and autopilot call the canonical installed reader before mutation/review and at crosschecks. `/ci` still reads intent before every step; domain/design load once per invocation and at crosschecks. Context prose is non-authoritative: only validated plan checklist metadata and typed state may authorize actions, commands, or paths. Reader hostile checks match writer checks. Autopilot bundles the reader closure or delegates to installed `ci`; unknown versions stop before repair. Headless blocks commit in-progress state, append a closed reason/status (`approval`, `repair`, `link`, `contradiction`, `update-required`), publish the existing operator-action marker, then exit 42. | Installed source/plugin/dogfood launchers cover non-`006` dependencies, missing gate code, version skew, direct hostile edits, authority isolation, progress retention, reason propagation, step intent cadence, DR bounded handoff, phase/plan paths, and unchanged `/pfb`. `test:InterviewGates.InstalledConsumerAndAutopilotMatrix` `test:Pfb.IntentAuthorityUnchanged` | 3.2 |
| REQ-8 | Every payload-changing step converges declarations, versions, dogfood, bundles, registry, and marketplace before completion. Schema bundling is generalized from review-only to declared root-confined schema references with pruning/drift tests. Fast covers pure logic; bounded Slow fixtures use one pristine clone/corpus, explicit case/process caps, and pre/final measurements. Finalization adds provisional `ARCH-Interview-Gates-V1`; updates plan-workflow, customization, plugin-evals, plugin-registry, autopilot, and review-reporting notes; deletes both promoted exploration files and repairs links/index/counts; declares writer scope; enforces stable Tier-1 case inventories; and uses the existing commit-bound evidence receipt after all configured gates run at one HEAD. | Step-local payload parity, schema closure, architecture/index/doc updates, per-owner scope, Tier-1 attendance, suite placement/bounds, corrupted-output reconvergence then no-op rerun, no package/telemetry, and final receipt with no failed/unrun required markers pass. `test:bundle-no-drift` `test:dogfood-no-drift` `test:Marketplace.Drift` `test:InterviewGates.DistributionRecoveryAndFinalReceipt` | 1.1-3.3 |
